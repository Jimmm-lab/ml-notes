K-Means 的限制

投影片 17

投影片 17 整理了 K-Means 的缺點。前兩個在前面看過了：要跑好幾次才不會卡在差的解（第 2 篇），要事先指定群數（第 3 篇）。第三個更根本：群的大小不同、密度不同，或者不是圓形時，K-Means 的效果不好。投影片 17（課本圖 9-11）用三個大小、密度、方向都不同的橢圓形群示範：

import numpy as np
from sklearn.datasets import make_blobs
from sklearn.cluster import KMeans

X1, y1 = make_blobs(n_samples=1000, centers=((4, -4), (0, 0)), random_state=42)
X1 = X1.dot(np.array([[0.374, 0.95], [0.732, 0.598]]))   # 拉長、轉斜，變成兩個橢圓
X2, y2 = make_blobs(n_samples=250, centers=1, random_state=42)
X2 = X2 + [6, -8]
X = np.r_[X1, X2]

kmeans_good = KMeans(n_clusters=3, init=np.array([[-1.5, 2.5], [0.5, 0], [4, 0]]),
                     n_init=1, random_state=42).fit(X)
kmeans_bad = KMeans(n_clusters=3, n_init=10, random_state=42).fit(X)
print(round(kmeans_good.inertia_, 1), round(kmeans_bad.inertia_, 1))
# 2242.6 2179.6

實驗：三個橢圓形的群

inertia–
和真正的群不一致–

兩個結果都不好。「好的起點」比較接近，但中間那個橢圓還是有一截被切給右邊那群；預設的 K-Means 更糟，把兩個斜的橢圓攔腰切成兩半，再兩兩拼在一起。奇怪的是，差的那個 inertia 反而比較小（2179.6 比 2242.6）。原因是 inertia 只看每一點到中心的距離：細長的橢圓橫著切開，每一塊都比較「圓」、比較緊，距離平方和就變小了。K-Means 的目標本身就偏好圓形、大小差不多的群，遇到細長的群，inertia 最小的分法就不是我們想要的分法。

投影片 17 的結論：遇到這種橢圓形的群，高斯混合模型的效果很好（第 7 篇）。形狀更不規則的群，可以用 DBSCAN（第 5 篇）。

補充筆記為什麼跑 K-Means 前要先縮放特徵？
  • K-Means 用距離決定每筆資料屬於哪一群。如果一個特徵的範圍是 0～1000（例如收入，單位千元），另一個是 0～1（例如比例），距離幾乎只由第一個特徵決定，第二個特徵等於沒用。
  • 先用 StandardScaler 把每個特徵變成平均 0、標準差 1，每個特徵對距離的影響才差不多。
  • 課本提醒：縮放不保證群會變成漂亮的圓形，但通常會讓 K-Means 的效果好一些。
  • 第 5 章的 SVM 也是這樣：凡是用距離來判斷的演算法，都要先注意特徵的尺度。

一句話K-Means 靠距離分群，範圍大的特徵會主導距離，所以要先縮放。

影像分割：把顏色分群

課本補充（Géron 第 9 章）

影像分割（image segmentation）是把一張圖切成好幾個區塊。最先進的做法（例如分出每一個人、每一輛車）要用深度學習，但最簡單的顏色分割，用 K-Means 就做得到：

  • 每一個像素是一筆資料，特徵是它的紅、綠、藍（R、G、B）三個數值。
  • 用 K-Means 把所有像素的顏色分成 群。
  • 每個像素換成它所屬那一群的中心顏色。整張圖就只剩 種顏色，顏色相近的像素會變成同一個區塊。
from sklearn.datasets import load_sample_image

image = load_sample_image("flower.jpg")       # scikit-learn 內建的照片
X_img = image.reshape(-1, 3)                  # 每一列是一個像素的 R、G、B
print(image.shape, X_img.shape, len(np.unique(X_img, axis=0)))
kmeans = KMeans(n_clusters=8, n_init=10, random_state=42).fit(X_img)
segmented_img = kmeans.cluster_centers_[kmeans.labels_].reshape(image.shape)
print(segmented_img.shape, len(np.unique(segmented_img.reshape(-1, 3), axis=0)))
# (427, 640, 3) (273280, 3) 62941
# (427, 640, 3) 8

原本 273,280 個像素有 62,941 種不同的顏色，分群後只剩 8 種。kmeans.cluster_centers_[kmeans.labels_] 是把每個像素換成它那一群的中心顏色。用下面這張畫出來的風景圖試試看不同的 ：

實驗：把像素的顏色分成 群

各群的中心顏色（下面的數字是佔多少像素）

很小的時候，面積大的天空、山、湖會先各自佔一種顏色；面積小但顏色很不一樣的東西，例如花和太陽，要到 比較大才會出現。這是因為 K-Means 在降低 inertia：讓佔了大部分像素的大區塊顏色準一點，比照顧一小撮像素划算。課本的瓢蟲照片也是這樣， 小於 8 時，紅色的瓢蟲就被併進周圍的顏色裡了。

分群當作前處理

課本補充（Géron 第 9 章）

第 1 篇說過，transform() 會把每筆資料換成「到每個中心的距離」。這些距離可以當成新的特徵，交給後面的監督式模型。用 scikit-learn 內建的手寫數字（1,797 張 8 × 8 的灰階圖，64 個特徵）試試看。先用邏輯迴歸當作比較的基準：

from sklearn.datasets import load_digits
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

X_digits, y_digits = load_digits(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X_digits, y_digits, random_state=42)
log_reg = LogisticRegression(max_iter=10_000, random_state=42).fit(X_train, y_train)
print(round(log_reg.score(X_test, y_test), 4))
# 0.9733

再用 pipeline 先把資料分成 50 群，換成到 50 個中心的距離，再交給邏輯迴歸：

from sklearn.pipeline import make_pipeline

pipeline = make_pipeline(KMeans(n_clusters=50, n_init=10, random_state=42),
                         LogisticRegression(max_iter=10_000, random_state=42))
pipeline.fit(X_train, y_train)
print(round(pipeline.score(X_test, y_test), 4))
# 0.9756

群數是前處理的超參數，可以用第 2 章的格點搜尋找。因為 K-Means 在 pipeline 裡，參數名稱要加上它的名字 kmeans__（這段要跑大約 20 秒）：

from sklearn.model_selection import GridSearchCV

param_grid = dict(kmeans__n_clusters=range(2, 100, 10))
grid_clf = GridSearchCV(pipeline, param_grid, cv=3).fit(X_train, y_train)
print(grid_clf.best_params_, round(grid_clf.score(X_test, y_test), 4))
# {'kmeans__n_clusters': 72} 0.98

準確率從 97.33% 提高到 98.00%，錯誤率從 2.67% 降到 2.00%，錯的少了四分之一。這裡的群數不是「資料有幾團」，而是「哪個群數讓後面的分類器表現最好」，所以不用手肘法或輪廓分數，直接看驗證的成績。

半監督式學習：只標記每群的代表

課本補充（Géron 第 9 章）

半監督式學習（semi-supervised learning）的情況是：資料很多，但只有少數有標籤（標記要花人力）。假設 1,400 張手寫數字只能請人標記 50 張。最直接的做法是隨便挑 50 張來標：

X_train, y_train = X_digits[:1400], y_digits[:1400]
X_test, y_test = X_digits[1400:], y_digits[1400:]
n_labeled = 50
log_reg = LogisticRegression(max_iter=10_000).fit(X_train[:n_labeled], y_train[:n_labeled])
print(round(log_reg.score(X_test, y_test), 4))
# 0.7582

準確率只有 75.82%。改用分群挑：先把 1,400 張圖分成 50 群，每一群挑離中心最近的那一張當作代表圖，只標記這 50 張代表圖：

k = 50
kmeans = KMeans(n_clusters=k, n_init=10, random_state=42)
X_digits_dist = kmeans.fit_transform(X_train)          # 每張圖到 50 個中心的距離
representative_idx = X_digits_dist.argmin(axis=0)     # 每一群離中心最近的那一張
X_representative = X_train[representative_idx]
y_representative = y_train[representative_idx]        # 實務上是請人看圖標記
log_reg = LogisticRegression(max_iter=10_000).fit(X_representative, y_representative)
print(round(log_reg.score(X_test, y_test), 4))
# 0.8388

一樣只標 50 張，準確率提高到 83.88%。比較看看兩組 50 張圖：

實驗：隨便挑的 50 張，和 50 群的代表圖

每個數字有幾張

代表圖是每一群「最典型」的那一張，彼此不太重複，就像從每一種寫法各挑一張來標記，所以學到的東西比較多。還可以更進一步，把代表圖的標籤傳給同一群的所有圖（標籤傳播，label propagation）：

y_train_propagated = np.empty(len(X_train), dtype=np.int64)
for i in range(k):
    y_train_propagated[kmeans.labels_ == i] = y_representative[i]
log_reg = LogisticRegression(max_iter=10_000).fit(X_train, y_train_propagated)
print(round(log_reg.score(X_test, y_test), 4), round((y_train_propagated == y_train).mean(), 3))
# 0.8589 0.95

現在 1,400 張都有標籤了（其中 95% 是對的），準確率 85.89%。錯的標籤主要來自離中心很遠、靠近群邊界的圖，它們很可能其實屬於別的數字。所以只把標籤傳給每一群裡離中心最近的 20%：

percentile_closest = 20
X_cluster_dist = X_digits_dist[np.arange(len(X_train)), kmeans.labels_]
for i in range(k):
    in_cluster = kmeans.labels_ == i
    cutoff = np.percentile(X_cluster_dist[in_cluster], percentile_closest)
    X_cluster_dist[in_cluster & (X_cluster_dist > cutoff)] = -1
partially = X_cluster_dist != -1
log_reg = LogisticRegression(max_iter=10_000).fit(X_train[partially], y_train_propagated[partially])
print(partially.sum(), round(log_reg.score(X_test, y_test), 4),
      round((y_train_propagated[partially] == y_train[partially]).mean(), 3))
# 300 0.8766 0.987

只用 300 張，但標籤有 98.7% 是對的，準確率反而升到 87.66%。整理一下，從頭到尾都只請人標記了 50 張：

做法訓練用的圖測試準確率
隨便挑 50 張標記5075.82%
標記 50 群的代表圖5083.88%
代表圖的標籤傳給整群1,40085.89%
只傳給離中心最近的 20%30087.66%
補充筆記接下來還能怎麼做？主動學習是什麼？
  • 課本提到下一步可以用主動學習（active learning）：讓模型自己挑出它最沒把握的資料，再請人標記這些資料。
  • 最常見的是「不確定性抽樣」：模型對某張圖預測各數字的機率都差不多（例如 4 是 35%、9 是 33%），就優先請人標記它。
  • 標記完重新訓練，再挑下一批，直到準確率夠好或預算用完。
  • 和隨機挑資料來標記相比，同樣的人力通常能得到更好的模型，因為每一張標記都用在模型最需要的地方。

一句話主動學習讓模型挑它最沒把握的資料請人標記，把標記的人力花在刀口上。

常見陷阱與自我檢查

以為 inertia 越小，分群就越好三個橢圓的例子裡，差的那個分法 inertia 反而比較小。K-Means 的目標偏好圓形、大小差不多的群，不一定符合資料真正的結構。
沒有縮放特徵就跑 K-Means範圍大的特徵會主導距離。通常先用 StandardScaler⁠。
用 K-Means 分不是圓形的群細長、彎曲或大小差很多的群，換成高斯混合模型（第 7 篇）或 DBSCAN（第 5 篇）。
前處理的群數也用輪廓分數選分群當作前處理時，群數是為了讓後面的模型表現好，要用格點搜尋看驗證成績，不是看資料有幾團。
投影片 17 說 K-Means 有哪些限制？

① 要跑好幾次才能避免停在差的解；② 要事先指定群數；③ 群的大小不同、密度不同，或不是圓形時，效果不好。遇到橢圓形的群可以改用高斯混合模型。

用 K-Means 做顏色分割時，「一筆資料」和「特徵」各是什麼？分群後怎麼畫出新的圖？

一筆資料是一個像素，特徵是它的 R、G、B 三個值（所以一張 427 × 640 的圖有 273,280 筆資料、3 個特徵）。分群後把每個像素換成它那一群的中心顏色，再排回原本的形狀，整張圖就只剩 種顏色。

只能標記 50 張圖，為什麼標記「50 群的代表圖」比隨便挑 50 張好？

隨便挑可能挑到很多寫法很像的圖，有些寫法卻一張都沒挑到。代表圖是每一群離中心最近、最典型的那一張，50 群就涵蓋了 50 種不同的寫法，同樣的標記數量能學到比較多樣的例子。這份資料上準確率從 75.82% 提高到 83.88%。

標籤傳播時，為什麼只傳給離中心最近的 20% 反而比傳給整群好？

離中心很遠的圖靠近群的邊界，很可能其實是別的數字，傳過去的標籤容易錯（整群傳播只有 95% 的標籤是對的）。只傳給最近的 20%，雖然訓練資料從 1,400 張變成 300 張，但標籤 98.7% 是對的，錯誤的標籤少了，模型反而比較準。
