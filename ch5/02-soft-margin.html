5. Support Vector Machines，第 2 篇／共 7 篇（投影片 5–6、12、47）

軟間隔與超參數 C：
街道寬一點，還是違規少一點？

上一篇的 SVM 要求街道裡不能有任何資料，這叫硬間隔。但真實資料常有雜訊，兩類會有一點重疊，硬間隔就失靈了。這篇介紹軟間隔：允許少數資料跑進街道，再用超參數 C 決定「街道要多寬」和「違規要多少」之間怎麼取捨。這也是期末考連續兩年都考的題目。

這篇讀完你會知道
  • 硬間隔分類的兩個問題：只能用在線性可分的資料、對離群值很敏感。
  • 什麼是間隔違規（margin violation），以及軟間隔怎麼在街道寬度和違規之間取捨。
  • 超參數 C 怎麼影響街道寬度、違規數量和支援向量，以及模型過擬合時為什麼要調小 C。
  • 軟間隔 SVM 的成本函數：兩項怎麼互相拉扯，C 在裡面扮演什麼角色。
  • 用 scikit-learn 1.9 的 LinearSVC、SVC、SGDClassifier 訓練線性 SVM，以及它們的差別。

硬間隔的兩個問題

投影片 5

上一篇的 SVM 有一個嚴格的要求：每一筆資料都必須在街道外面，而且在正確的那一邊。這叫做硬間隔分類（hard margin classification）。投影片 5 指出它有兩個問題：

  • 只能用在線性可分的資料：只要有一筆資料混進對方的地盤，就找不到任何一條「裡面沒有資料」的街道。投影片左圖直接寫著 Impossible!
  • 對離群值很敏感：就算還分得開，一筆位置很奇怪的資料（離群值，outlier）也可能逼得街道變得非常窄、方向也歪掉，對新資料的表現多半會變差（投影片右圖）。
補充筆記離群值不一定是錯誤的資料

離群值只是「和同類的資料差很多」的資料，原因可能有好幾種：

  • 量錯或抄錯：例如把 0.8 公分記成 8 公分。
  • 標錯類別：這朵花其實是 versicolor，卻被標成 setosa。
  • 真的很少見：資料本身沒錯，只是這種情況很少出現。

從資料本身通常分不出是哪一種。軟間隔的好處是不用先判斷：它把離群值當成一筆「違規」，付一點代價就好，不會讓它左右整個模型。

軟間隔：允許一點點違規

投影片 6

解決辦法是放寬要求：允許少數資料跑進街道，甚至跑到錯的那一邊，只是要付出代價。這叫做軟間隔分類（soft margin classification）。

落在街道裡、或在錯的那一邊的資料，叫做間隔違規（margin violation）。依照資料的位置，可以分成三種：

街道外、分對沒有違規。
街道裡、分對違規，但還在正確的一邊。
錯的那一邊違規，而且分類錯誤。
補充筆記分對但在街道裡，也算違規
  • 違規看的是「有沒有乖乖待在街道外」，不只是「有沒有分對」。
  • 這筆資料雖然在正確的那一邊，但離決策邊界太近，模型對它不夠有把握：再偏一點點就會分錯。
  • 所以違規有輕重之分：
    • 在街道裡、但在正確的一邊：輕微違規。
    • 剛好在決策邊界上：違規。
    • 跑到錯的那一邊：嚴重違規，而且分類錯誤。
  • 後面的成本函數會把「違規得多嚴重」算成一個數字。

一句話分對還不夠，要分得夠有把握：離邊界至少一個街道半寬。

軟間隔的目標，是在兩件事之間找平衡：

  • 街道盡量寬：上一篇說過，邊界離兩類越遠，對新資料越有利。
  • 違規盡量少：跑進街道或分錯的資料越少越好。

這兩件事互相衝突：街道開得越寬，就有越多資料落進街道；要違規少，街道就得變窄。

超參數 C：街道寬度和違規之間的取捨

投影片 6、47

scikit-learn 的 SVM 用超參數 C 決定這個平衡：

  • C 小：違規的代價低。模型寧可讓很多資料進街道，也要把街道開寬。
  • C 大：違規的代價高。模型盡量讓每筆資料都在街道外，街道只好變窄。

投影片 6 的例子是 versicolor 和 virginica 兩種鳶尾花，各 50 朵，先用 StandardScaler 標準化。這兩種花有一部分重疊，一條直線怎樣都分不完美。拖動 C 的滑桿看看：

  • 支援向量的數量跟著變：軟間隔的支援向量，是所有在街道邊緣上或街道裡的資料，所以街道越寬，支援向量越多。C = 0.01 時 100 朵裡有 76 朵是支援向量，邊界由大量的花一起決定。

補充筆記C 大到一定程度，答案就不再改變
  • 把 C 想成每單位違規的罰款。C 變大，模型就會「花錢」把違規的資料推到街道外：把街道變窄、轉一下方向。
  • 但推得動的只有能推出去的資料。versicolor 和 virginica 有幾朵花混在對方的地盤裡，用直線怎麼畫都會有花分錯，這些違規永遠消不掉。
  • C = 100 時，在街道裡但分對的花都已經推出去了，只剩 6 朵分錯邊的花。不管街道怎麼移，總有花會分錯：模型已經找到總違規量最小的位置，罰款再高也找不到更好的答案，結果就停住了。
  • 資料分得開時更明顯：C 大到沒有任何違規之後，罰款再高也罰不到錢，答案就和硬間隔一模一樣（實驗裡的 setosa 與 versicolor，C 超過大約 1.15 就是如此）。

一句話C 只決定違規有多貴；當能消除的違規都消除了，再貴也沒有差別。

換成另外兩組資料：

  • setosa 與 versicolor（分得開）：C 很小時，模型還是寧可讓一些花進街道，換取更寬的街道；C 超過大約 1.15 之後，已經沒有任何違規，結果和硬間隔一模一樣。投影片 47 用另一份資料示範了同一件事，並把 C = ∞ 標成硬間隔。這裡先標準化了，所以最寬的街道是 1.01 cm，和上一篇沒標準化的 1.30 cm 不同：正是上一篇說的「單位會改變答案」。
  • 再加一朵離群值：C = 1 時，模型乾脆把離群值當成違規（它被分到 versicolor 那一邊），街道還有 0.92 cm；C 很大時，違規太貴，又變回硬間隔，被它逼到只剩 0.21 cm。試著拖動離群值。

現在可以完整解釋 C 的作用了：

C 小：違規很便宜

第二項就算很大，乘上小小的 C 也沒多少。模型專心把第一項壓低： 小、街道寬、違規多。

C 大：違規很貴

這個式子就是 SGDClassifier 訓練線性 SVM 時用的成本函數，2024 和 2023 期末考的第 1 題都直接給了它。第 7 篇會再從數學推導一次，並說明怎麼用梯度下降來最小化它。

C 是正則化的旋鈕

投影片 6

投影片 6 的最後一句：「SVM 過擬合時，可以調小 C 來正則化。」第一項限制 不能太大，作用和第 4 章的正則化一樣；C 越小，這個限制相對越重要，所以C 越小，正則化越強。

補充筆記C 和第 4 章 Ridge 的 ：方向相反

1把成本函數除以 C

  • 成本函數整個除以一個正數，最低點的位置不變。把 SVM 的成本函數除以 ：
  • 變成「違規量」加上「 倍的正則化項」。這和 Ridge 迴歸「MSE 加上 倍的正則化項」是同一種形式。
  • 所以 的角色就像 ：C 越大，正則化越弱；C 越小，正則化越強。方向和 相反。

2和邏輯迴歸的 C 方向相同

  • 第 4 章的 LogisticRegression 也用 C 控制正則化，同樣是「C 越小，正則化越強」。
  • scikit-learn 的分類器大多用這種寫法。SGDClassifier 是例外，它用 alpha，換算關係在第 7 篇。

一句話C 像是 ：看到 C 就想成「違規有多貴」，看到 就想成「權重有多貴」。

C 小（正則化強）

街道寬、違規多。很多資料都是支援向量，邊界由大量資料一起決定，比較平滑，不容易被個別資料拉走。太小會欠擬合。

C 大（正則化弱）

街道窄、違規少。邊界只由少數靠近邊界的資料決定，訓練資料擬合得很緊，也容易被離群值帶偏。太大容易過擬合。

C 該設多少，沒有固定答案。和其他超參數一樣，用交叉驗證在幾個數量級裡試試看（例如 0.01、0.1、1、10、100），挑驗證分數最好的那個（第 2 章第 6 篇的 Grid Search）。

在 scikit-learn 訓練線性 SVM

投影片 2、6、12

投影片 6 的寫法：先用 StandardScaler 標準化，再用 LinearSVC：

import numpy as np
from sklearn.datasets import load_iris
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import LinearSVC

iris = load_iris(as_frame=True)
X = iris.data[["petal length (cm)", "petal width (cm)"]].values
y = iris.target.values
versicolor_or_virginica = (y == 1) | (y == 2)
X = X[versicolor_or_virginica]
y = (y[versicolor_or_virginica] == 2)          # True：virginica，False：versicolor

svm_clf = make_pipeline(StandardScaler(),
                        LinearSVC(C=1, loss="hinge", random_state=42))
svm_clf.fit(X, y)

X_new = [[5.5, 1.7], [5.0, 1.5]]
svm_clf.predict(X_new)                         # array([ True, False])
svm_clf.decision_function(X_new).round(2)      # array([ 1.36, -0.27])
  • 花瓣 5.5 × 1.7 cm：，在 virginica 那一側的街道外，很有把握是 virginica。
  • 花瓣 5.0 × 1.5 cm：，預測 versicolor，但它在街道裡，比較沒把握。
  • loss="hinge" 就是上面成本函數的第二項。LinearSVC 預設的是 "squared_hinge"（違規量再平方），結果會有點不同。

補充筆記LinearSVC 和 SVC(kernel="linear") 的三個差別
  • 演算法不同：兩個函式庫用不同的方法逼近最佳解，各自在「夠接近」時就停下來，停的位置會差一點點。
  • 截距的處理不同：LinearSVC 把截距 當成一個額外的權重，也一起正則化；SVC 不會。資料先標準化時，這個差別通常很小。
  • 預設的 loss 不同：LinearSVC 預設是 "squared_hinge"，要設 loss="hinge" 才和 SVC 解同一個問題。
  • 上面的鳶尾花用 loss="hinge"、C=1：兩者的 coef_ 是 (1.4933, 1.5370) 和 (1.4934, 1.5367)，幾乎一樣（見下面的 Python 實作）。

一句話同一個模型、不同的解法；資料大時用 LinearSVC，要用核技巧時用 SVC。

投影片 12 之後，scikit-learn 改了兩個地方

  • LinearSVC 的 dual 預設從 True 改成 "auto"，會依資料自動選擇解法。
  • SVC 的 probability 在 1.9 版被標為淘汰（1.11 版移除）。想要機率，改用 CalibratedClassifierCV(SVC(), ensemble=False)。

Python 實作

接著上面的程式，用 SVC 試三種 C，算出街道寬度、違規數量和支援向量數量（就是 C 那一節的表格）：

from sklearn.svm import SVC

t = np.where(y, 1, -1)                         # 類別改成 +1 / −1
for C in [0.01, 1, 100]:
    clf = make_pipeline(StandardScaler(), SVC(kernel="linear", C=C)).fit(X, y)
    w = clf[-1].coef_[0] / clf[0].scale_       # 換回 cm 單位的 w
    margin = t * clf.decision_function(X)      # 每筆資料的 y·h
    print(f"C={C:<5} 街道寬 {2 / np.linalg.norm(w):.2f} cm，"
          f"違規 {(margin < 0.99).sum()} 朵（分錯 {(margin < 0).sum()} 朵），"
          f"支援向量 {len(clf[-1].support_)} 個")
# C=0.01  街道寬 1.70 cm，違規 74 朵（分錯 6 朵），支援向量 76 個
# C=1     街道寬 0.49 cm，違規 16 朵（分錯 6 朵），支援向量 19 個
# C=100   街道寬 0.22 cm，違規 6 朵（分錯 6 朵），支援向量 12 個
  • 標準化之後，SVM 的 coef_ 是標準化單位的權重。除以 scale_（每個特徵的標準差）就換回公分，才能算出圖上看到的街道寬度。
  • 違規的條件是 。這裡用 0.99，因為剛好在街道邊緣的資料，算出來可能是 0.9999，不該算成違規。

最後重現投影片 5：setosa 和 versicolor 加上一朵離群的 setosa，比較硬間隔和軟間隔：

# load_iris() 的前 100 朵是 setosa 和 versicolor
X2 = iris.data[["petal length (cm)", "petal width (cm)"]].values[:100]
y2 = iris.target.values[:100]
X_out = np.r_[X2, [[3.2, 0.8]]]                # 加一朵離群的 setosa
y_out = np.r_[y2, [0]]

hard = SVC(kernel="linear", C=1e100).fit(X_out, y_out)     # 硬間隔
2 / np.linalg.norm(hard.coef_[0])              # np.float64(0.22145290508336574)
hard.support_vectors_
# array([[3.2, 0.8],
#        [3.3, 1. ],
#        [3. , 1.1]])

soft = make_pipeline(StandardScaler(), SVC(kernel="linear", C=1)).fit(X_out, y_out)
soft.predict([[3.2, 0.8]])                     # array([1])：把離群值當成違規，判成 versicolor
2 / np.linalg.norm(soft[-1].coef_[0] / soft[0].scale_)   # np.float64(0.9165102994319401)

硬間隔被離群值逼到只剩 0.22 cm，三個支援向量裡就有離群值本身；軟間隔（C=1）接受這一筆違規，保住了 0.92 cm 的街道。

常見陷阱與自我檢查

把 C 當成正則化強度剛好相反：C 越大，正則化越弱。模型過擬合時要調小 C。
以為違規只包括分錯的資料在街道裡、但分對的資料也算違規，只是違規量比較小（0 到 1 之間）。
以為 C 夠大，訓練準確率就能到 100%兩類重疊時，直線怎樣都會分錯幾筆。versicolor 和 virginica 不管 C 多大，都會分錯 5 到 6 朵。
沒標準化就比較不同的 C街道寬度和違規都和特徵的單位有關。先標準化，C 的效果才有意義。
以為 LinearSVC 和 SVC 一定一樣LinearSVC 預設是 squared hinge，也會正則化截距；要比較時記得設 loss="hinge"。
（期末考題）兩張圖用不同的 C 訓練：左圖街道很寬、很多點在街道裡；右圖街道很窄、只有少數點在街道裡。哪一張的 C 比較大？為什麼？
  • 右圖的 C 比較大。成本函數 的兩項互相拉扯。
  • C 大時違規很貴，模型盡量讓資料都在街道外，只好把街道縮窄（ 變大）：街道窄、違規少。邊界由少數靠近邊界的點決定，比較容易過擬合。
  • C 小時違規很便宜，模型專心讓 變小（街道寬度 變大）：街道寬、違規多。邊界由很多點一起決定，比較平滑，太小會欠擬合。
SVM 在訓練集上表現很好，在驗證集上卻差很多。C 要調大還是調小？

這是過擬合，要加強正則化，所以調小 C：讓街道變寬、允許更多違規，邊界由更多資料一起決定，比較不會只顧著擬合訓練資料。

一筆資料 、。它違規了嗎？違規量是多少？如果 呢？

，在街道裡，違規但分對：違規量 。 時 ，跑到錯的一邊：違規量 。

資料線性可分。C 設成 1000 和設成無限大（硬間隔），結果有差嗎？

通常沒有差。C 大到沒有任何違規之後，第二項是 0，C 再大也沒有影響，答案就是硬間隔的答案。實驗裡的 setosa 與 versicolor，C 超過大約 1.15 就和硬間隔一模一樣。

為什麼 C 很小時，支援向量特別多？

軟間隔的支援向量是所有在街道邊緣上或街道裡的資料。C 小，街道寬，落進街道的資料就多：versicolor 與 virginica 在 C = 0.01 時，100 朵裡有 76 朵是支援向量。
