8. Dimensionality Reduction，第 5 篇／共 9 篇（投影片 12–14）

要降到幾維？
PCA 壓縮與重建

降維時要決定 ：留太少會丟掉太多資訊，留太多又省不了多少。這篇用 MNIST 看最常見的做法「保留 95% 的變異」，再把 PCA 當成壓縮：784 個像素壓成 154 個數字，再解壓縮回來，看看損失了什麼。

這篇讀完你會知道
  • 怎麼選維度 ：保留足夠比例（例如 95%）的變異，或看曲線的手肘。
  • MNIST 保留 95% 的變異只要 154 維，資料剩不到原本的 20%（期末考的例子）。
  • 用 inverse_transform() 解壓縮，以及為什麼重建誤差就是丟掉的變異。
  • 降維之後，模型一定訓練得比較快嗎？實測 SVM 和隨機森林。

選 d：保留足夠的變異

投影片 12

與其隨便挑一個 ，不如選一個能保留足夠變異的 ，例如 95%（投影片 12）。做法是：先保留全部的主成分訓練 PCA⁠，把解釋變異比一個一個累加起來，找出累計第一次達到 95% 的位置。scikit-learn 有更簡單的寫法：n_components 直接給 0 到 1 之間的小數，代表要保留的變異比例：

pca = PCA(n_components=0.95)                    # 保留 95% 的變異，自動決定 d
X_reduced = pca.fit_transform(X_train)

MNIST 的訓練資料有 784 個特徵，下面是累計解釋變異比的曲線（投影片 12 的圖）。拉動滑桿，看要保留多少變異需要幾維：

保留 95% 只要 154 維；但要保留 99%，就要 331 維，多出一倍以上。越往後，每多保留一點變異，要付出的維度就越多。

看曲線的手肘

投影片 12

另一個做法是直接看這條曲線（投影片 12）：它一開始升得很快，之後越來越平，轉折的地方像手肘（elbow）。手肘之後，多加維度換來的變異很少。MNIST 的手肘大約在 100 維附近：前 100 維就有 91.5% 的變異，之後的 684 維加起來只有 8.5%。

如果降維只是分類或迴歸之前的前處理，還有第三種做法：把 當成一個超參數，用交叉驗證（第 2 章的格狀搜尋）挑出讓最後的模型表現最好的 。這是課本第 3 版的建議，因為「保留多少變異」和「模型準不準」不一定一致。

PCA 當作壓縮：784 → 154

投影片 13

把 MNIST 降到 154 維、保留 95% 的變異：每張圖從 784 個數字變成 154 個，資料只剩 154 ÷ 784 ≈ 19.6%，不到原本的 20%（投影片 13）。很多分類器的訓練時間和特徵數量有關，例如 SVM，資料變小可以快很多（後面會實測）。

這就是期末考「用一個例子說明降維」最好用的例子：784 個特徵，用 PCA 壓到 154 個，保留 95% 的變異，資料剩不到 20%。

解壓縮：重建與重建誤差

投影片 13–14

壓縮過的資料也可以解壓縮：把投影的過程反過來做，乘上 的轉置，就回到原本的 784 維（投影片 13）：

（scikit-learn 的 inverse_transform() 最後還會加回訓練資料的平均。）丟掉的那 5% 變異回不來了，所以重建出來的圖和原圖不完全一樣，有點模糊。原圖和重建之間的平均平方距離，叫做重建誤差（reconstruction error）。

154 維（投影片 14 的 95%）重建的數字已經和原圖很像，只是筆畫邊緣有點模糊。重建誤差還有一個漂亮的性質：它剛好等於丟掉的變異。保留 95.02% 的變異時，重建誤差是 170,750，正好是總變異 3,428,445 的 4.98%。

補充筆記為什麼重建誤差剛好等於丟掉的變異？
  • 重建，就是把每一點投影到前 個主成分張出來的超平面上，再用原本的 784 維座標寫出來。所以重建的點，就是原圖在這個超平面上的投影。
  • 原圖到重建的距離，就是原圖到超平面的距離。第 3 篇的畢氏定理說：總變異 = 投影後的變異 + 平均平方距離。
  • 投影後的變異就是保留的 95.02%，所以平均平方距離（重建誤差）就是剩下的 4.98%。
  • 所以 PCA 讓投影後的變異最大，也等於讓重建誤差最小：在所有 維的超平面裡，PCA 找到的那一個，壓縮之後還原得最好。

一句話重建的點就是投影，重建誤差就是投影時丟掉的距離，也就是丟掉的變異。

降維之後，訓練一定比較快嗎？

投影片 13 說，資料變小可以讓 SVM 這類分類器快很多。實際試試看：用前 1 萬張訓練圖訓練兩種分類器，一次用原本的 784 個像素，一次先用 PCA 保留 95% 的變異（在這 1 萬張圖上要 150 維），都用同樣的 1 萬張測試圖評估：

分類器784 個像素PCA 降到 150 維
SVM（⁠SVC()⁠，RBF 核）訓練 6.9 秒
準確率 95.9%		訓練 2.2 秒
準確率 96.6%
隨機森林訓練 4.0 秒
準確率 95.0%		訓練 9.3 秒
準確率 91.5%

訓練時間是在我們的電腦上量 3 次取中間值（只算訓練分類器，不含 PCA），換一台電腦會不一樣，但快慢的關係差不多；準確率每次都相同。

  • SVM：訓練快了大約 3 倍，準確率還稍微變高。SVM 要計算很多筆資料之間的相似度，每次計算的成本和特徵數成正比，特徵變少，速度就快。
  • 隨機森林：反而慢了一倍多，準確率也下降。第 6 章最後一篇說過，決策樹只會做和座標軸垂直的切割，對旋轉很敏感；PCA 把資料轉了方向，原本「某個像素有沒有筆畫」這種好切的特徵不見了，每個新特徵都是很多像素的混合，樹要切更多刀才分得開。

所以和第 2 篇投影片 23 的結論一樣：降維不一定讓訓練變快或變準，要看模型和資料，最好實際試試。

Python 實作

先載入 MNIST，用全部的主成分訓練 PCA⁠，找出累計解釋變異比第一次達到 95% 的維度（投影片 12 的做法）：

import numpy as np
from sklearn.datasets import fetch_openml
from sklearn.decomposition import PCA

mnist = fetch_openml("mnist_784", as_frame=False)
X_train, y_train = mnist.data[:60_000], mnist.target[:60_000]
X_test, y_test = mnist.data[60_000:], mnist.target[60_000:]

pca = PCA()                                     # 保留全部 784 個主成分
pca.fit(X_train)
cumsum = np.cumsum(pca.explained_variance_ratio_)
d = np.argmax(cumsum >= 0.95) + 1               # 第一個達到 95% 的位置（從 0 數，所以 + 1）
print(d, cumsum[99].round(3))                   # 154 維；前 100 維的累計比例
# 154 0.915

直接用 n_components=0.95⁠：

pca = PCA(n_components=0.95)
X_reduced = pca.fit_transform(X_train)
print(pca.n_components_, X_reduced.shape)
print(pca.explained_variance_ratio_.sum().round(4), round(154 / 784, 3))
# 154 (60000, 154)
# 0.9502 0.196

解壓縮，算重建誤差（每張圖到它的重建的距離平方，再取平均），並和總變異比較：

X_recovered = pca.inverse_transform(X_reduced)
sq_dist = ((X_train - X_recovered) ** 2).sum(axis=1)
print(X_recovered.shape, sq_dist.mean().round(1))
print((sq_dist.mean() / X_train.var(axis=0).sum()).round(4))   # 占總變異的比例
# (60000, 784) 170750.2
# 0.0498

inverse_transform() 做的就是投影片 13 的式子，最後加回平均：

W_d = pca.components_.T                         # 784 × 154
X_manual = X_reduced @ W_d.T + pca.mean_
print(np.allclose(X_recovered, X_manual))
# True

最後比較兩種分類器，用 1 萬張訓練圖，有沒有先用 PCA 降維（只印準確率，訓練時間見上面的表格）。把 PCA 放進 pipeline，測試資料就會自動用訓練資料的主成分轉換：

from sklearn.base import clone
from sklearn.ensemble import RandomForestClassifier
from sklearn.pipeline import make_pipeline
from sklearn.svm import SVC

X_small, y_small = X_train[:10_000], y_train[:10_000]
for model in [SVC(), RandomForestClassifier(random_state=42)]:
    raw = clone(model).fit(X_small, y_small).score(X_test, y_test)
    pipe = make_pipeline(PCA(n_components=0.95), clone(model))
    reduced = pipe.fit(X_small, y_small).score(X_test, y_test)
    print(type(model).__name__, raw, reduced)
# SVC 0.9594 0.9655
# RandomForestClassifier 0.9504 0.9153

常見陷阱與自我檢查

以為 n_components 只能給整數給整數是維度 ；給 0 到 1 之間的小數，是要保留的變異比例，PCA 會自己決定 ，存在 n_components_⁠。
以為 inverse_transform() 能完全還原只有保留全部 個主成分時才能完全還原。丟掉的變異回不來，重建誤差就是它。
以為降維一定讓訓練變快SVM 快了 3 倍，隨機森林卻慢了一倍多、還變得不準。要看模型和資料。
argmax 忘了加 1np.argmax(cumsum >= 0.95) 傳回的是索引（從 0 開始），維度要再加 1。
（2024、2023 期末考）用 MNIST 當例子，說明降維的好處和代價。

MNIST 每張圖有 784 個像素（特徵）。用 PCA 保留 95% 的變異，只需要 154 個特徵，資料大小剩不到原本的 20%。好處是訓練變快（例如 SVM 快了大約 3 倍，準確率幾乎不變）、省記憶體；降到 2 維或 3 維時還能畫圖觀察。代價是丟掉了 5% 的變異：解壓縮回 784 維時，數字會有點模糊（重建誤差），而且不是每種模型都會變快或變準，例如隨機森林反而變慢。

累計解釋變異比是 [0.50, 0.75, 0.88, 0.95, 0.98, …]。要保留 90% 的變異， 是多少？

4。前 3 個累計 0.88，還不到 0.90；前 4 個累計 0.95，第一次達到 90%。用程式寫就是 np.argmax(cumsum >= 0.90) + 1⁠。

用 PCA 保留 92% 的變異，重建誤差大約占總變異的多少？

8%。重建的點就是投影，重建誤差等於丟掉的變異：1 − 0.92 = 0.08。
