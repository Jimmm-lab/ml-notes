資料太大時：
隨機 PCA 與增量 PCA

完整的 SVD 要一次處理整份資料，資料很大時又慢又佔記憶體。這篇看 PCA 的兩種變形：只求前幾個主成分、速度快很多的隨機 PCA，以及一次只看一小批資料的增量 PCA，並實際量一量它們在 MNIST 上的表現。

這篇讀完你會知道
  • 完整 SVD 的計算量，以及隨機 PCA 為什麼在 遠小於 時快很多。
  • scikit-learn 怎麼自動選算法：MNIST 用的其實不是隨機 PCA。
  • 增量 PCA：把資料切成小批次一批一批訓練，適合放不進記憶體的資料和線上學習。
  • 補充：隨機投影，不看資料就投影，距離為什麼還能大致保留。

完整的 SVD 有多慢

投影片 15

到目前為止，我們都用完整的 SVD 算主成分。投影片 15 給出它的計算量：

是資料筆數， 是特徵數。計算量和 的平方、甚至三次方成正比：特徵變成 10 倍，計算量就變成 100 到 1000 倍。MNIST（6 萬筆、784 個特徵）還算小，幾秒就算完；但如果每筆資料有上萬個特徵（例如高解析度的圖片），或資料多到放不進記憶體，完整的 SVD 就吃不消了。這篇的兩個方法，分別解決這兩個問題：

  • 特徵太多、只要前幾個主成分：隨機 PCA。
  • 資料太多、放不進記憶體，或資料不斷進來：增量 PCA。

隨機 PCA：只求前 d 個主成分

投影片 15

完整的 SVD 會算出全部 個主成分，但降維時通常只要前 個。隨機 PCA（randomized PCA）是一種用到隨機數的演算法，它很快地找出前 個主成分的近似值。投影片 15 說它的計算量是：

和完整 SVD 比，裡面的 換成了 ，所以當 遠小於 時，會快非常多。用法只要設定 svd_solver="randomized"⁠：

rnd_pca = PCA(n_components=154, svd_solver="randomized", random_state=42)
X_reduced = rnd_pca.fit_transform(X_train)

實際量一量：一份 4,000 筆、4,000 個特徵的資料，完整 SVD 要 11 秒左右；隨機 PCA 只求前 10 個主成分要 1.4 秒，求前 100 個要 2.5 秒，保留的變異和完整 SVD 幾乎一樣（98.181% 對 98.185%）。

補充筆記隨機 PCA 是怎麼做的？為什麼計算量只和 d 有關？
  1. 產生一個 的隨機矩陣（ 是多抓的幾個方向，scikit-learn 預設 10），把資料乘上它，得到 的矩陣。隨機方向乘上資料之後，會偏向資料變異最大的那些方向，所以這個小矩陣大致涵蓋了前 個主成分。
  2. 為了更準，會再來回乘幾次資料（power iteration），讓變異大的方向更突出。
  3. 把這 個方向整理成互相垂直的一組（QR 分解，約 ），把資料投影上去，變成一個只有 列的小矩陣，對它做完整的 SVD 就很便宜了。

投影片的式子只算了後面這些步驟。嚴格來說，把資料乘上隨機矩陣那幾次，每次還要 。不過結論不變： 遠小於 時，這都比完整 SVD 的 小得多。

一句話先用隨機方向「撈」出資料最散開的那幾個方向，再在這個小空間裡做精確的 SVD。

scikit-learn 怎麼選算法？

PCA 的 svd_solver 預設是 "auto"⁠，會依資料的形狀自動選（scikit-learn 1.5 之後的規則）：

  1. 特徵不超過 1,000 個，而且資料筆數至少是特徵數的 10 倍（又高又瘦的資料）：用 "covariance_eigh"⁠，先算出 的共變異數矩陣，再求它的特徵向量（第 3 篇補充筆記說過，主成分就是它的特徵向量）。
  2. 資料很小（兩個維度都不超過 500）：用完整的 "full"⁠。
  3. 要的主成分個數少於 、 中較小者的 80%：用隨機的 "randomized"⁠。
  4. 其他情況（包括 n_components 給 0.95 這種比例）：用 "full"⁠。

MNIST 有 784 個特徵、6 萬筆資料，符合第 1 條，所以預設用的是 covariance_eigh⁠。在我們的電腦上，求 MNIST 的前 154 個主成分：covariance_eigh 只要 0.4 秒，而且結果和完整 SVD 完全一樣；完整 SVD 要 3.7 秒；隨機 PCA 要 3.3 秒，並沒有比較快，因為 784 個特徵不算多。（課本寫的是舊版的規則：資料大於 500 × 500、要的主成分少於 80% 時就用隨機 PCA。）

相似度是兩個方向的夾角餘弦取絕對值：1 表示同一條軸，0 表示互相垂直。前 100 個主成分，三種算法幾乎完全一樣；第 154 個就差很多了。不過，前 154 個主成分合起來保留的變異幾乎一樣：完整 SVD 95.02%、隨機 PCA 94.98%、增量 PCA 94.95%。後面的主成分變異都很小、而且彼此很接近，哪一個排第 154 本來就不太穩定；降維在乎的是它們合起來保留了多少，所以近似的結果一樣好用。

增量 PCA：一批一批來

投影片 15

前面的方法都要把整份訓練資料放進記憶體。增量 PCA（Incremental PCA，IPCA）把訓練資料切成小批次（mini-batch），一次只餵一批（投影片 15）。每餵一批，它就更新目前的平均和主成分，然後就可以把這一批丟掉。它適合兩種情況：

  • 資料太大，放不進記憶體：一次只讀一小批。
  • 線上學習（online）：新的資料不斷進來，邊收邊更新，不必每次都從頭算。

這是第 3 篇那 200 筆 2 維資料，每批 20 筆、分 10 批餵給 IncrementalPCA(n_components=1)⁠。第一批只有 20 筆，估計出來的 差了 3.6°；餵完 10 批，只差 0.02°。在 MNIST 上分 100 批，前 154 個主成分保留了 94.95% 的變異，和完整 SVD 的 95.02% 幾乎一樣。代價是比較慢：在我們的電腦上要 15 秒，是完整 SVD 的 4 倍，但它任何時候都只需要放 600 張圖在記憶體裡。

課本還示範了另一種寫法：用 NumPy 的 memmap 把存在硬碟上的大檔案當成陣列，需要哪一部分才讀進記憶體，再交給 IncrementalPCA 的 fit()⁠，並用 batch_size 指定每批的大小（見下面的 Python 實作）。

補充：隨機投影

課本第 3 版還介紹了一種更快的方法：隨機投影（random projection）。它完全不看資料，直接把資料乘上一個隨機的矩陣，投影到一個維度比較低的空間。聽起來很隨便，但 Johnson–Lindenstrauss 引理保證：只要維度夠，任兩點之間的距離大致都會保留下來。

  • 需要的維度由資料筆數 和容許的誤差 決定，和原本的特徵數 無關。例如 5,000 筆資料、容許距離誤差 10%，要 7,300 維（⁠johnson_lindenstrauss_min_dim(5000, eps=0.1)⁠）。
  • scikit-learn 有 GaussianRandomProjection 和 SparseRandomProjection（隨機矩陣大部分是 0，更快、更省記憶體）。
  • 適合特徵非常多（例如上萬個）、連隨機 PCA 都嫌慢的情況，例如文字資料。但它不像 PCA 會把變異集中在前面幾個維度，所以需要的維度通常多很多。

Python 實作

先載入 MNIST，用隨機 PCA 求前 154 個主成分（要設 random_state⁠，結果才固定）：

import numpy as np
from sklearn.datasets import fetch_openml
from sklearn.decomposition import PCA, IncrementalPCA

mnist = fetch_openml("mnist_784", as_frame=False)
X_train = mnist.data[:60_000]

rnd_pca = PCA(n_components=154, svd_solver="randomized", random_state=42)
X_reduced = rnd_pca.fit_transform(X_train)
print(X_reduced.shape, rnd_pca.explained_variance_ratio_.sum().round(4))
# (60000, 154) 0.9498

增量 PCA：用 np.array_split() 把訓練資料切成 100 批（每批 600 張），一批一批用 partial_fit() 餵進去：

n_batches = 100
inc_pca = IncrementalPCA(n_components=154)
for X_batch in np.array_split(X_train, n_batches):
    inc_pca.partial_fit(X_batch)                # 每次只看一批
X_reduced = inc_pca.transform(X_train)
print(X_reduced.shape, inc_pca.explained_variance_ratio_.sum().round(4))
# (60000, 154) 0.9495

資料大到放不進記憶體時，可以先把它存成硬碟上的 memmap 檔案；之後讀回來時，NumPy 只在需要時才把那一部分載入記憶體。fit() 會依 batch_size 一批一批讀：

filename = "my_mnist.mmap"
X_mmap = np.memmap(filename, dtype="float32", mode="write", shape=X_train.shape)
X_mmap[:] = X_train                             # 存到硬碟（實務上可以一塊一塊寫）
X_mmap.flush()

X_mmap = np.memmap(filename, dtype="float32", mode="readonly").reshape(-1, 784)
batch_size = X_mmap.shape[0] // n_batches       # 每批 600 張
inc_pca = IncrementalPCA(n_components=154, batch_size=batch_size)
inc_pca.fit(X_mmap)
print(inc_pca.explained_variance_ratio_.sum().round(4))
# 0.9495

隨機投影（課本第 3 版）：先看需要的維度，再用一份 1,000 筆、10,000 個特徵的隨機資料，比較投影前後的距離：

from sklearn.random_projection import GaussianRandomProjection, johnson_lindenstrauss_min_dim

print(johnson_lindenstrauss_min_dim(5_000, eps=0.1))   # 5,000 筆、距離誤差 10% 要幾維

rng = np.random.default_rng(42)
X = rng.standard_normal((1_000, 10_000))
grp = GaussianRandomProjection(eps=0.3, random_state=42)   # 容許 30% 的誤差
X_proj = grp.fit_transform(X)
i, j = rng.integers(0, 1_000, size=(2, 2_000))           # 隨機挑 2,000 對資料
i, j = i[i != j], j[i != j]                              # 去掉自己和自己配對的
ratio = (np.linalg.norm(X_proj[i] - X_proj[j], axis=1)
         / np.linalg.norm(X[i] - X[j], axis=1))          # 投影後 ÷ 投影前的距離
print(X_proj.shape, ratio.min().round(3), ratio.max().round(3))
# 7300
# (1000, 767) 0.918 1.087

10,000 維降到 767 維，隨機挑的 2,000 對資料，投影後的距離都在原本的 92% 到 109% 之間，沒有超過容許的 30%。

常見陷阱與自我檢查

以為隨機 PCA 一定比較快它在特徵很多、 遠小於 時才快很多。MNIST 只有 784 個特徵，隨機 PCA 並沒有比完整 SVD 快；scikit-learn 預設用的 covariance_eigh 才是最快的。
以為增量 PCA 比 PCA 快它通常更慢。它的好處是省記憶體、能接著新資料繼續更新，不是速度。
隨機 PCA 忘了設 random_state它用到隨機數，不設的話每次結果可能有一點不同，實驗就無法重現。
以為近似的主成分就不能用後面幾個主成分的方向可能差很多，但它們合起來保留的變異和完整 SVD 幾乎一樣，降維的效果差不多。
資料有 2,000 筆、20,000 個特徵，只需要前 50 個主成分。用哪一種方法比較好？

隨機 PCA。特徵很多（），而 遠小於 ，完整 SVD 很慢，隨機 PCA 快很多，結果也幾乎一樣。這種形狀用 svd_solver="auto" 也會自動選隨機 PCA。

網站每天都有新的使用者資料進來，想讓 PCA 跟著更新，不想每天從頭算。用哪一種？

增量 PCA：每天把新資料當成一批，用 partial_fit() 餵進去，平均和主成分就會更新，不需要舊資料。

為什麼 MNIST 用 svd_solver="auto" 時，選的不是隨機 PCA？

MNIST 有 784 個特徵（不超過 1,000），資料筆數 6 萬筆也超過特徵數的 10 倍，是「又高又瘦」的資料，所以 scikit-learn 選 covariance_eigh⁠：先算 784 × 784 的共變異數矩陣再求特徵向量，又快又精確。
