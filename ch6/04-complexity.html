預測：

投影片 12–13

第 1 篇看過，預測一筆新資料就是從根節點走到葉節點。投影片 12 的推理分成三步：

  1. 每個節點只比一次：節點只問一個特徵的一個問題（ 嗎？），比一次就知道往左還是往右，花的時間是固定的 。
  2. 要經過幾個節點，等於樹的深度：從根走到葉，每一層經過一個節點。
  3. 樹大致平衡時，深度約是 ：每往下一層，資料大約被切成一半。 筆資料一直對半切，切 次就只剩 1 筆。

  • 對半切 次之後，每一份大約剩 筆。

一句話 就是「 要除以 2 幾次才會變成 1」。

三步合起來：預測要比 次，每次 ，總共 。注意式子裡沒有特徵數 ：就算每筆資料有一萬個特徵，每個節點還是只看其中一個。所以投影片說，決策樹的預測非常快，即使訓練資料很多也一樣。

訓練：

投影片 12–13

訓練就辛苦多了。上一篇看過，CART 在每個節點要找最好的切法：這個節點裡的資料，每個特徵、每個可能的門檻都要試一遍，而可能的門檻差不多和資料筆數一樣多。投影片 13 右邊的圖說明怎麼算總量：

  1. 根節點： 筆資料、 個特徵都要看，大約 次計算。
  2. 第二層：兩個節點各有一部分資料，但加起來還是 筆，所以這一層還是大約 次。

  4. 一共約 層（和預測一樣，假設樹大致平衡）。

  • 特徵數 加倍：時間大約加倍。

更精確一點：排序的成本

要在一個特徵上試所有門檻，得先把資料依照這個特徵排序，排序本身要 。如果每個節點都重新排序，更精確的總量會多出一個 。課本和投影片的 是常用的近似說法，考試寫這個就對了。

真實的樹有多深？

課本補充

上面兩個式子都假設樹大致平衡，每一層把資料差不多對半分。真實的樹不一定這樣：如果每次都只切掉一兩筆，樹會很深，最壞的情況深度接近 ，預測就變成 。

實際量一下：用 make_classification 產生 10 個特徵的資料，其中 5% 的標籤是隨機亂給的（雜訊），不限制深度訓練到底，看看樹有多深，以及訓練資料平均要比幾次才走到葉節點：

  • 不限制深度時，樹會為了雜訊一直切下去，最深的葉節點遠超過 。
  • 但平均要比的次數還是很少：100 萬筆資料，平均也只比 33 次，和 100 萬比起來微不足道。
  • 限制 max_depth（第 5 篇）時，預測最多比 max_depth 次，更快。

訓練時間也實際量一下。資料量從 12,500 筆一路加倍到 200,000 筆（10 個特徵），訓練時間從約 0.16 秒變成 4.7 秒；特徵數從 5 個一路加倍到 40 個（50,000 筆），從約 0.4 秒變成 5.0 秒。每次加倍，時間變幾倍：

特徵數 2.1～2.4 倍2 倍

大方向和式子一致： 或 加倍，時間大約加倍多一點。實測的倍數比式子稍大，而且有高有低：式子只估計大致的量級，沒有算進排序（上面的方框）和記憶體存取這些成本，樹的形狀也會跟著資料改變；每次執行的時間本身也會有些起伏。

預測則快得驚人：一次預測 20 萬筆，平均每筆只要 0.1～0.2 微秒（1 微秒是百萬分之一秒）；用 10,000 筆或 100,000 筆訓練的樹都差不多。

Python 實作

量樹的深度，以及每筆訓練資料從根走到葉要比幾次（decision_path() 會標出每筆資料經過的節點）：

import math
from sklearn.datasets import make_classification
from sklearn.tree import DecisionTreeClassifier

for m in [1_000, 10_000, 100_000]:
    X, y = make_classification(n_samples=m, n_features=10, n_informative=5,
                               flip_y=0.05, random_state=42)
    tree = DecisionTreeClassifier(random_state=42).fit(X, y)
    path = tree.decision_path(X).sum(axis=1).A1 - 1    # 經過的節點數 − 1 = 比了幾次
    print(m, round(math.log2(m), 1), tree.get_depth(), round(path.mean(), 1))
# 1000 10.0 14 7.8
# 10000 13.3 26 14.6
# 100000 16.6 54 24.9

量訓練時間怎麼隨 成長（時間因電腦而異，看倍數就好）：

import time

prev = None
for m in [12_500, 25_000, 50_000, 100_000, 200_000]:
    X, y = make_classification(n_samples=m, n_features=10, n_informative=5,
                               flip_y=0.05, random_state=42)
    start = time.perf_counter()
    DecisionTreeClassifier(random_state=42).fit(X, y)
    t = time.perf_counter() - start
    print(m, round(t, 3), "" if prev is None else f"×{t / prev:.2f}")
    prev = t

忘了「樹大致平衡」這個前提 是平衡的樹的深度。很不平衡的樹，深度可能接近 。
以為每一層的計算量越來越少下面的節點資料變少，但節點變多，同一層加起來還是 筆，每一層都是 。
（2024 期末考、2023 期末考）說明為什麼決策樹做一次預測的計算複雜度是 。

預測是從根節點走到一片葉節點，每個節點只檢查一個特徵、比較一次，是 ，所以時間等於經過的節點數，也就是樹的深度。決策樹大致平衡時，每往下一層資料大約減半， 筆資料減半約 次就剩 1 筆，深度約 。所以預測是 ，而且和特徵數 無關。

（2024 期末考、2023 期末考）說明為什麼訓練一棵決策樹的計算複雜度是 。

CART 在每個節點要比較所有 個特徵、這個節點裡所有的資料，找出最好的切法。同一層的節點雖然各自只有一部分資料，但加起來還是 筆，所以每一層大約要 次計算。樹大致平衡時約有 層，總共 ，也就是 。

訓練資料從 100 萬筆變成 200 萬筆，預測一筆資料的時間大約變多少？訓練時間呢？

預測： 從約 20 變成約 21，只多比一次，幾乎不變。訓練： 從 變成 ，大約是原本的 2.1 倍。

特徵從 10 個增加到 1,000 個（資料筆數不變），預測和訓練時間大約怎麼變？

預測幾乎不變（每個節點還是只看一個特徵；樹的形狀可能稍微不同）。訓練大約變成 100 倍，因為每個節點要試的特徵多了 100 倍。
