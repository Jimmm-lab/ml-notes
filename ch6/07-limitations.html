6. Decision Trees，第 7 篇／共 7 篇（投影片 22–25）

決策樹的弱點：
怕旋轉、變異大

決策樹容易理解、容易使用、分類和迴歸都能做，表現也很好。但它有兩個明顯的弱點：只會切出和座標軸平行的邊界，而且變異很大。這篇用實驗看這兩個弱點從哪裡來，以及常用的解法。

這篇讀完你會知道
  • 為什麼決策樹「喜歡直角」：資料一旋轉，就要切很多刀，新資料也變得比較不準。
  • 先標準化、再用 PCA 把資料轉正，常常能讓樹變簡單。
  • 什麼叫「變異很大」：同樣的資料，換一個 random_state 就可能長出另一棵樹。
  • 為什麼把很多棵樹的預測合起來可以降低變異：這就是第 7 章的隨機森林。

只會切直角：怕旋轉

投影片 22

決策樹的每一刀都只看一個特徵（ 嗎？），所以切出來的邊界一定和某個座標軸平行（第 1 篇）。投影片說決策樹「愛」直角的邊界：真正的邊界剛好和座標軸平行時，一刀就解決；但只要把資料轉個角度，同樣的邊界就得用很多刀拼出一道階梯。

投影片 22 的例子：在正方形裡隨機撒 100 個點，右半邊（）是一類、左半邊是另一類，真正的邊界是一條直線。把整份資料轉一個角度，邊界就變成斜線。另外用同樣的方式產生 1,000 筆新資料，看看樹在沒看過的資料上表現如何：

不管轉幾度，訓練資料都是 100% 正確：不加限制的樹總能用夠多的刀把訓練資料分開。但投影片提醒，轉 45° 的那棵樹很可能泛化得不好。實驗也是這樣：沒有旋轉時新資料對 99%，邊界一斜就往下掉，轉 5° 是 97.1%，轉 30° 只剩 91.6%。階梯的每一階，都是照著這 100 個點的位置切出來的，換一批資料就對不上了。

解法一：先把資料轉正

投影片 23

既然問題出在角度，一個辦法是先把資料轉到比較好的方向：先標準化，再做主成分分析（PCA）。PCA 會旋轉資料，讓第一個新座標 沿著資料散開最多的方向，第二個新座標 和它垂直。轉完之後特徵之間的相關性降低，常常（不是每次）能讓樹的工作變簡單。PCA 第 8 章會詳細介紹（期末考連續兩年都考了，例如 2024 期末考第 7 題）。

補充筆記PCA 一定有幫助嗎？
  • PCA 只看資料「散開的形狀」，不看類別標籤。它保證 沿著資料散開最多的方向，但不保證類別的分界剛好和 或 平行。
  • 如果類別的分界和資料散開的方向沒有關係，轉完一樣是斜的，樹還是得切出階梯。
  • 所以投影片說「常常（不是每次）」有幫助。實務上可以把「先做 PCA」當成一個選項，用交叉驗證比較做和不做哪個好。

一句話PCA 幫資料換個方向，換得好不好要看資料。

投影片 23 拿鳶尾花的花瓣長度和寬度來試。這兩個特徵高度相關：花瓣越長，通常也越寬，所以點沿著一條斜線分布。PCA 把這條斜線轉成 軸：

轉正之後，深度 2 的樹兩刀都切在 上（ 和 ），只用一個特徵就把三類分開，訓練準確率從 96% 提高到 98%。 幾乎包含了全部的資訊：它解釋了 98.1% 的變異量。

變異很大：差一點，整棵樹就不同

投影片 24

決策樹更根本的問題是變異很大（high variance）：超參數或訓練資料稍微改變，就可能訓練出很不一樣的模型。

甚至什麼都不改也可能發生。scikit-learn 的 CART 在每個節點會用隨機的順序檢查特徵，兩個切法一樣好時，先檢查到的勝出。鳶尾花的根節點剛好有兩個一樣好的切法：花瓣長度 ≤ 2.45 和花瓣寬度 ≤ 0.8，加權 Gini 都是 0.333（第 3 篇的實驗）。所以只要換一個 random_state，同樣的資料、同樣的超參數，就會長出另一棵樹（投影片 24）：

兩棵樹在訓練資料上的預測完全一樣（準確率都是 96%），但在沒有訓練資料的地方就不一樣了。例如花瓣長 1.5 cm、寬 1.5 cm 的花，左邊的樹預測 setosa，右邊預測 versicolor。把 random_state 從 0 試到 99，有 51 個先切花瓣寬度、49 個先切花瓣長度，幾乎是丟銅板。

補充筆記為什麼決策樹的變異特別大？
  • 貪婪：每一刀都只挑「目前最好」的切法（第 3 篇）。上面的一刀改變了，下面整棵子樹都跟著改，小差異會一路放大。
  • 硬切：門檻直接取在兩筆資料之間，多一筆或少一筆資料，門檻就可能移動，甚至換成另一個特徵。
  • 長得很深：不加限制的樹會一直切到很細，連雜訊都學進去（第 5 篇）。換一批資料，雜訊不同，樹也就不同。

一句話貪婪、硬切、長得深，讓決策樹對資料的小變動很敏感。

解法二：很多棵樹一起投票

投影片 25

好消息是，把很多棵樹的預測合起來（分類就是投票，迴歸就是平均），可以大幅降低變異。每棵樹用不同的抽樣資料訓練，各自犯的錯不太一樣，投票時就互相抵消。這樣的一群樹叫做隨機森林（random forest），是現在最強大的模型之一，第 7 章會詳細介紹。

下面用 moons 資料試試看：500 筆，其中 375 筆訓練、125 筆測試。每棵樹都從 375 筆訓練資料裡取後放回地隨機抽 375 筆來訓練，有的資料會被抽到好幾次，有的一次也沒抽到。左邊是其中一棵樹，右邊是很多棵這樣的樹一起投票：

實驗：一棵樹 vs. 一群樹

一棵樹的測試準確率
一起投票的測試準確率

多按幾次「重新抽樣」：左邊那棵樹的邊界每次都長得很不一樣，右邊投票的邊界只有小小的變化，而且平滑得多。這就是「降低變異」。用 scikit-learn 的 BaggingClassifier 訓練 500 棵樹（照課本的設定，每棵抽 100 筆），測試準確率從一棵樹的 85.6% 提高到 90.4%（投影片 25）。

決策樹的優點與缺點

第 6 章整理

優點

容易理解、能解釋每個預測（白箱模型，第 1 篇）；不需要特徵縮放（第 3 篇）；預測很快，只要 （第 4 篇）；分類、迴歸都能做（第 6 篇）。

缺點

只會切直角，怕旋轉（本篇）；變異很大，資料或 random_state 一變，樹就可能不同（本篇）；不加限制很容易過擬合（第 5 篇）；迴歸樹不能往外延伸（第 6 篇）。

這些缺點裡，變異大和過擬合，正是第 7 章的隨機森林要解決的問題。

Python 實作

投影片 22：同一份資料，不轉和轉 45°，訓練兩棵樹，再用新資料打分數：

import numpy as np
from sklearn.tree import DecisionTreeClassifier

np.random.seed(6)
X_square = np.random.rand(100, 2) - 0.5              # 正方形裡的 100 個點
y_square = (X_square[:, 0] > 0).astype(int)          # 右半邊是類別 1
X_new = np.random.rand(1000, 2) - 0.5                # 接著產生 1,000 筆新資料
y_new = (X_new[:, 0] > 0).astype(int)

def rotate(X, degrees):
    a = np.deg2rad(degrees)
    return np.c_[X[:, 0] * np.cos(a) + X[:, 1] * np.sin(a),
                 -X[:, 0] * np.sin(a) + X[:, 1] * np.cos(a)]

for deg in [0, 45]:
    tree = DecisionTreeClassifier(random_state=42).fit(rotate(X_square, deg), y_square)
    print(deg, tree.get_n_leaves(), tree.score(rotate(X_square, deg), y_square),
          tree.score(rotate(X_new, deg), y_new))
# 0 2 1.0 0.99
# 45 6 1.0 0.942

投影片 23：先標準化、再做 PCA，然後訓練深度 2 的樹：

from sklearn.datasets import load_iris
from sklearn.decomposition import PCA
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.tree import export_text

iris = load_iris()
X_iris = iris.data[:, 2:]                            # 花瓣長度、花瓣寬度
y_iris = iris.target

pca_pipeline = make_pipeline(StandardScaler(), PCA())
X_iris_rotated = pca_pipeline.fit_transform(X_iris)
tree_pca = DecisionTreeClassifier(max_depth=2, random_state=42).fit(X_iris_rotated, y_iris)
print(export_text(tree_pca, feature_names=["z1", "z2"], decimals=3))
# |--- z1 <= -0.911
# |   |--- class: 0
# |--- z1 >  -0.911
# |   |--- z1 <= 0.758
# |   |   |--- class: 1
# |   |--- z1 >  0.758
# |   |   |--- class: 2
print(tree_pca.score(X_iris_rotated, y_iris))
# 0.98

投影片 25：一棵樹和 500 棵樹投票（第 7 章的 bagging）比一比：

from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.ensemble import BaggingClassifier

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

tree = DecisionTreeClassifier(random_state=42).fit(X_train, y_train)
bag = BaggingClassifier(DecisionTreeClassifier(), n_estimators=500, max_samples=100,
                        random_state=42).fit(X_train, y_train)
print(tree.score(X_test, y_test), bag.score(X_test, y_test))
# 0.856 0.904

常見陷阱與自我檢查

以為決策樹可以切斜線每一刀只看一個特徵，邊界一定和座標軸平行；斜的邊界只能用階梯去逼近。
以為訓練準確率 100% 就代表學對了轉 45° 的樹訓練資料全對，新資料卻比沒轉的差。
以為 PCA 一定有幫助PCA 不看類別標籤，只是把資料轉到散開最多的方向。常常有幫助，但不保證。
以為同樣的資料一定訓練出同一棵樹scikit-learn 會隨機排列檢查特徵的順序，兩個切法打平時誰勝出，要看 random_state。
為什麼決策樹對資料的旋轉很敏感？

決策樹每一刀只看一個特徵，切出來的邊界一定和座標軸平行。真正的邊界如果和座標軸平行，一刀就夠；資料旋轉之後邊界變成斜的，就只能用很多刀拼成階梯，樹變大，也比較難泛化到新資料。

投影片 22 的兩棵樹在訓練資料上都是 100% 正確，為什麼轉 45° 的那棵「很可能泛化得不好」？

它的階梯是照著這 100 個訓練點的位置切出來的，和真正的斜線只是剛好在訓練點上一致。在訓練點之間的空隙，階梯和斜線會有落差，新資料落在這些地方就會分錯（實驗中新資料的準確率從 99% 降到 94.2%）。

同樣的資料、同樣的超參數，換一個 random_state 就得到不同的樹。這是 bug 嗎？

不是。scikit-learn 在每個節點會隨機排列檢查特徵的順序（設了 max_features 時，還會隨機挑一部分特徵）。鳶尾花的根節點有兩個一樣好的切法，先檢查到的勝出，所以 random_state 決定了選哪一個。這也說明了決策樹的變異很大。

（2024 期末考第 6 題的一部分）為什麼把很多棵決策樹的預測合起來，通常比一棵樹準？

一棵樹的變異很大，資料稍微不同，預測就差很多。讓很多棵樹各自用不同的抽樣資料訓練，它們犯的錯不太一樣，投票（或平均）時互相抵消，結果就穩定得多，也更準。前提是每棵樹都比亂猜好，而且彼此的錯誤不要太相關。這就是隨機森林等集成學習方法的想法。
