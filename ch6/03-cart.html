CART 演算法：
怎麼找出最好的切法

第 1 篇的樹，第一個問題是「花瓣長度 ≤ 2.45 嗎？」。為什麼是花瓣長度，又為什麼是 2.45？scikit-learn 用 CART 演算法決定：把每個特徵、每個可能的門檻都試一遍，挑出讓兩邊最純的那一個，再對兩邊重複同樣的事。

這篇讀完你會知道
  • CART 的成本函數 ：左右兩邊 Gini 不純度的加權平均，以及為什麼要加權。
  • CART 怎麼在一個節點找出最好的特徵 和門檻 ：排序、試遍每個中點。
  • 它怎麼一層一層往下切，以及什麼時候停下來。
  • 為什麼 CART 是「貪婪」演算法，不保證長出最好的樹。
  • 為什麼決策樹完全不需要特徵縮放（期末考題）。

CART 的成本函數

投影片 9

scikit-learn 用 CART（Classification and Regression Tree，分類與迴歸樹）演算法訓練決策樹（訓練決策樹也常說成「讓樹長出來」，growing trees）。它的做法是：

  • 用一個特徵 和一個門檻 ，把訓練資料切成兩份： 的放左邊，其他放右邊。
  • 在所有可能的 裡，找出讓兩份資料最純的那一組。

「最純」用下面的成本函數衡量，越小越好：

  • 、：左右兩邊的 Gini 不純度（上一篇）。
  • 、：左右兩邊各有幾筆資料， 是這個節點的總筆數。

也就是兩邊 Gini 不純度的加權平均，資料越多的那一邊權重越大。投影片 9 的小例子：12 筆資料、三類各 4 筆，；某個切法把它分成兩邊各 6 筆，兩邊都是一類 4 筆、一類 2 筆，：

從 0.667 降到 0.444，這一刀讓資料變純了。第 1 篇的根節點也一樣：「花瓣長度 ≤ 2.45」把 150 朵分成左邊 50 朵（全部 setosa，）和右邊 100 朵（）：

為什麼要加權？如果只把兩邊的 Gini 直接平均，只切掉一兩筆資料的切法會被高估。

補充筆記為什麼不直接把兩邊的 Gini 不純度平均？
  • 假設 100 筆資料，有一個切法只切掉 1 筆：左邊 1 筆，當然是純的（）；右邊 99 筆，幾乎和原本一樣混雜（ 約 0.5）。
  • 直接平均：，看起來很棒，好像不純度降了一半。
  • 加權平均：，幾乎沒有改善，這才符合事實：99% 的資料還是一樣混雜。

一句話加權讓每一筆資料都算一票，切掉一兩筆的「假純」不會被高估。

在一個節點裡，怎麼找最好的切法

投影片 10

特徵只有 個，但門檻 可以是任何數字，要怎麼試完？投影片 10 的做法：

  1. 對每一個特徵 ，把這個節點的 筆資料依照 排序。
  2. 門檻只要放在兩筆相鄰資料的中間：同一個空隙裡放哪裡，分到左右兩邊的資料都一樣，所以每個空隙只要試一個，scikit-learn 用兩個值的中點。
  3. 每個候選門檻都算一次 ，記下最小的。
  4. 所有特徵都做完， 最小的那一組 就是這個節點的切法。

筆資料最多只有 個空隙，所以一個節點最多試 次。鳶尾花的根節點：花瓣長度有 43 種不同的值，候選門檻 42 個；花瓣寬度 22 種值，21 個。自己移動門檻，看看 怎麼變：

一層一層往下切

投影片 11

根節點切完，CART 對左右兩邊用同樣的方法再切，然後再切它們的子節點……一直遞迴下去（投影片 11）。它會在下面這些情況停下來：

  • 到了 max_depth 規定的最大深度。
  • 找不到能降低不純度的切法，例如節點已經是純的（），或裡面的資料長得一模一樣、切不開。
  • 其他超參數規定的條件：min_samples_split、min_samples_leaf、min_weight_fraction_leaf、max_leaf_nodes（第 5 篇）。

CART 是貪婪演算法

投影片 11

CART 每一步只挑「現在看起來最好」的切法，不考慮這一刀會不會讓後面變難切。這種一步一步只看眼前的做法叫做貪婪演算法（greedy algorithm）。

  • 好處：快。每個節點只要試 個切法。
  • 壞處：不保證長出最好的樹。它找到的通常是「還不錯」的答案。

那為什麼不直接找最好的樹？因為可能的樹多到算不完。找出最佳的決策樹是一個 NP 完全問題，需要的時間大約是 ，資料稍微多一點就算不完。

補充筆記NP 完全是什麼意思？
  • NP 完全（NP-complete）是一群公認很難的問題：到目前為止，沒有人找到「計算時間只隨資料量多項式增加」（例如 、）的解法。
  • 已知的解法基本上都要把各種可能試過一遍，時間大約是 ：資料每多一筆，時間就乘上一個倍數。Géron 的課本說，這讓問題就算訓練資料不多也幾乎解不完。
  • 這不是「還沒有人想到」那麼簡單：如果能替其中任何一個問題找到快速的解法，整群問題都能快速解決，這是電腦科學最有名的未解問題之一（P vs NP）。

一句話找最佳的樹，需要的時間會隨資料量爆炸性成長，所以實務上只能用貪婪的方法求一個夠好的解。

下面這 6 個點就是一個貪婪會吃虧的例子：

  • CART 的第一刀，在 的幾個切法中挑了 ，只切下左邊 1 個點；之後又切了 4 刀，總共 6 片葉子。
  • 最好的樹第一刀切在 ：這一刀的 ，和不切一模一樣，完全沒有改善，貪婪的 CART 絕對不會選它。但切完之後，左右兩邊各再切一刀就全部分開了，只要 4 片葉子。

這就像爬山時每一步都往最陡的方向走，不一定會走到最高的山頂。實務上，貪婪找到的樹通常已經夠好，再加上第 5 篇的正則化，效果就很不錯。

為什麼決策樹完全不需要特徵縮放

投影片 10、2023 期末考第 3 題 (1)

投影片 10 下方特別註明：決策樹完全不需要特徵縮放。這和前幾章很不一樣：梯度下降、SVM 都很怕特徵的單位不一致。原因在於 CART 找切法的方式：

  • 每個節點只問一個特徵：「 嗎？」，從來不把不同特徵加在一起，也不算距離。
  • 一個特徵只看資料的大小順序：排序後，在相鄰兩筆中間放門檻。
  • 標準化、min-max 縮放、換單位，都是「乘一個正數、再加一個數」，不會改變大小順序。排序結果一樣，每個空隙分出來的左右兩群也一樣， 也就一樣。

所以每一步選到的切法、整棵樹的形狀、每個預測都一模一樣，只是門檻的數字換了單位。

實驗：換一種單位，重新訓練

根節點的問題
葉節點
訓練準確率

對照：線性迴歸、SVM、K-近鄰會把不同特徵加起來或算距離，數值大的特徵會主宰結果，所以需要縮放；決策樹從不把不同特徵混在一起比較，所以不需要。

補充筆記取對數這種轉換也不影響嗎？
  • 取對數、開根號也不會改變大小順序，所以切出來的訓練資料分組完全一樣，樹的形狀也一樣。
  • 差別只在門檻的位置：門檻放在兩筆資料的「中點」，而取對數後的中點，換回原本的單位不是正中間。例如 setosa 最長 1.9 cm、versicolor 最短 3.0 cm，原本的門檻是 2.45；取對數後訓練，門檻換回來是 。
  • 所以落在 2.39 到 2.45 之間的新資料，兩棵樹的預測會不一樣；乘一個正數再平移的縮放就沒有這個差別，中點換單位後還是中點。

一句話不改變順序的轉換都不影響「怎麼分組」，只有線性縮放連門檻的位置也完全一樣。

Python 實作

先寫出成本函數 ，算根節點那一刀：

import numpy as np
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier

iris = load_iris(as_frame=True)
X_iris = iris.data[["petal length (cm)", "petal width (cm)"]].values
y_iris = iris.target.values

def gini(y):
    p = np.bincount(y, minlength=3) / len(y)
    return 1 - np.sum(p ** 2)

def cost(X, y, k, t):                                  # J(k, t_k)
    left, right = y[X[:, k] <= t], y[X[:, k] > t]
    m = len(y)
    return len(left) / m * gini(left) + len(right) / m * gini(right)

print(round(cost(X_iris, y_iris, 0, 2.45), 3))        # 0.333

照投影片 10 的方法，試遍每個特徵、每個中點：

def best_split(X, y):
    best = (None, None, np.inf)
    for k in range(X.shape[1]):                        # 每個特徵
        values = np.unique(X[:, k])                    # 排序好、不重複的值
        for t in (values[:-1] + values[1:]) / 2:       # 相鄰兩個值的中點
            J = cost(X, y, k, t)
            if J < best[2]:
                best = (k, t, J)
    return best

k, t, J = best_split(X_iris, y_iris)
print(k, t, round(J, 3))                               # 0 2.45 0.333
right = X_iris[:, 0] > 2.45                            # 右邊的子節點
k, t, J = best_split(X_iris[right], y_iris[right])
print(k, t, round(J, 3))                               # 1 1.75 0.11

和 scikit-learn 的結果一樣（feature 的 0 是花瓣長度、1 是花瓣寬度，−2 代表葉節點）：

tree_clf = DecisionTreeClassifier(max_depth=2, random_state=42).fit(X_iris, y_iris)
print(tree_clf.tree_.feature)              # [ 0 -2  1 -2 -2]
print(tree_clf.tree_.threshold.round(2))   # [ 2.45 -2.    1.75 -2.   -2.  ]

特徵縮放不影響決策樹：標準化前後各訓練一棵，對 1,000 個隨機的新點預測，結果完全一樣：

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_iris)
tree_raw = DecisionTreeClassifier(random_state=42).fit(X_iris, y_iris)
tree_scaled = DecisionTreeClassifier(random_state=42).fit(X_scaled, y_iris)

X_new = np.random.default_rng(0).uniform([1, 0], [7, 2.5], size=(1000, 2))
(tree_raw.predict(X_new) == tree_scaled.predict(scaler.transform(X_new))).all()   # np.True_
print(round(tree_scaled.tree_.threshold[0], 4))                                   # -0.7434
print(round((2.45 - scaler.mean_[0]) / scaler.scale_[0], 4))                       # -0.7434：就是 2.45 換成標準化的單位

常見陷阱與自我檢查

J 用簡單平均 是依照筆數加權的平均；只切掉一兩筆資料的切法，簡單平均會嚴重高估它的效果。
以為門檻可以是任何數字，所以要試無限多次只有「相鄰兩筆資料之間」的位置會改變分組，每個空隙試一次就夠：每個特徵最多 次。
以為 CART 會找到最好的樹它是貪婪的：每一步只挑眼前最好的切法，不保證整棵樹最好。找最佳的樹是 NP 完全問題。
訓練決策樹前先做標準化不會出錯，但完全沒有必要：切法、樹的形狀、預測都一樣，只是門檻換了單位。
（2023 期末考）說明為什麼決策樹完全不需要特徵縮放。

每個節點只用一個特徵和門檻比大小，CART 找門檻時只看資料在這個特徵上的排序。縮放是「乘一個正數再平移」，不改變排序，所以每個候選切法分出的兩群、算出的 都一樣，選到的切法和整棵樹都一樣，門檻只是換了單位。決策樹也從不把不同特徵加起來或算距離，所以單位不一致不會有影響。

一個節點有 10 筆資料：6 筆 A、4 筆 B。某個切法把它分成左邊 4 筆（全是 B），右邊 6 筆（全是 A）。 是多少？

兩邊都是純的，，。這是最好的切法。

同一個節點，另一個切法分成左邊 5 筆（4 A、1 B）、右邊 5 筆（2 A、3 B）。 是多少？

，。。原本的 ，有改善，但不如上一題。

一個節點有 1,000 筆資料、5 個特徵，每個特徵的值都不重複。CART 在這個節點最多要試幾個切法？

每個特徵 999 個空隙，共 個。
