學習率、樹的數量
與提前停止

Gradient Boosting 有兩個最重要的超參數：學習率和樹的數量。學習率決定每棵樹修正多少，樹的數量決定修正幾次，兩個要一起調。這篇用驗證集找出最好的樹數、介紹提前停止，最後看看 XGBoost、LightGBM 這些常用的實作。

這篇讀完你會知道
  • 學習率怎麼縮小每棵樹的貢獻（shrinkage），以及它和樹數的取捨。
  • 怎麼用 staged_predict() 找出驗證誤差最小的樹數。
  • 兩種提前停止的寫法：warm_start 自己寫迴圈，或設 n_iter_no_change。
  • subsample、HistGradientBoosting、XGBoost、LightGBM、CatBoost 各是什麼。

學習率：每棵樹只修正一部分

投影片 40–41

上一篇手寫的三棵樹，用 scikit-learn 一行就能做出來：

gbrt = GradientBoostingRegressor(max_depth=2, n_estimators=3, learning_rate=1.0)
gbrt.fit(X, y)

max_depth 控制每棵樹的大小（預設 3），n_estimators 是樹的數量（預設 100），learning_rate 就是上一篇演算法裡的 ：每棵樹的預測先乘上 ，再加進集成裡（投影片 41）：

學習率越小，每棵樹只修正殘差的一小部分，就需要越多棵樹才能擬合訓練資料；但這樣通常泛化得比較好。這種正則化的方法叫做 shrinkage（縮減）。學習率的預設值是 0.1，常用的範圍大約是 0.1 到 0.3（投影片 40）。

學習率和樹的數量要一起看。投影片 40 的圖 7-10：左邊學習率 1.0、只有 3 棵樹，曲線太粗糙，欠擬合；右邊學習率 0.1、200 棵樹，曲線跟著每個點彎來彎去，過擬合。下面用 75 筆訓練資料、25 筆驗證資料自己試試：

學習率 1.0 每棵樹修正全部的殘差，很快就開始擬合雜訊，最好的驗證誤差也比較差。學習率 0.1 要 56 棵樹才到最低點，但驗證誤差最低。學習率 0.3 只用 15 棵就差不多一樣好：學習率小一點通常比較準，代價是要更多棵樹、訓練更久。

找出最好的樹數：staged_predict()

投影片 45–46

樹太少欠擬合，太多過擬合。最好的樹數要用驗證集找。最簡單的方法是 staged_predict()（投影片 45）：它會依序傳回「1 棵樹、2 棵樹、3 棵樹……」時的預測，所以只要訓練一次，就能算出每一種樹數的驗證誤差：

  1. 先訓練一個樹很多的模型（課本用 120 棵，學習率是預設的 0.1）。
  2. 用 staged_predict(X_val) 算出每一個階段的驗證 MSE。
  3. 驗證 MSE 最小的階段就是最好的樹數：np.argmin(errors) + 1（加 1 是因為編號從 0 開始）。
  4. 用這個樹數重新訓練一個模型。

課本的結果是 56 棵，最低的驗證 MSE 約 0.0027（投影片 46 的圖 7-11）。在上面的實驗選 、按「跳到驗證誤差最小的樹數」就會看到同一個模型。

提前停止

投影片 46

上面的方法要先把 120 棵樹全部訓練完，再回頭找最好的。也可以真的提早停下來（投影片 46 的 Note）：每加一棵樹就看一次驗證誤差，連續好幾棵都沒有進步就停止。這叫做提前停止（early stopping），第 4 章第 5 篇訓練線性模型時也用過一樣的想法。scikit-learn 有兩種寫法：

自己寫迴圈：warm_start=True

設 warm_start=True 後，再呼叫 fit() 會保留已經訓練好的樹，只補上新增的。每次把 n_estimators 加 1、算一次驗證誤差，連續 5 次沒進步就停。課本的例子停在 61 棵（最好的是第 56 棵）。

交給 scikit-learn：n_iter_no_change

設 n_iter_no_change=10，它會自動從訓練資料切出 10% 當驗證集（validation_fraction），連續 10 棵樹都沒進步（幅度小於 tol）就停。訓練完的樹數放在 n_estimators_。

補充筆記Gradient Boosting 的提前停止，和第 4 章梯度下降的提前停止一樣嗎？
  • 想法一樣：一邊訓練、一邊看驗證誤差，驗證誤差不再下降就停，避免過擬合。
  • 差別在每次檢查之間做了什麼：梯度下降是多訓練一輪（一個 epoch，參數會更新一次或好幾次）；Gradient Boosting 是多加一棵樹。所以停下來的位置，就是決定要用幾棵樹。
  • 驗證誤差常常會上下抖動，所以通常不會一變差就停，而是等連續好幾步都沒有進步（例如 5 棵或 10 棵）才停，這個數字叫做 patience（耐心）。

一句話Gradient Boosting 的提前停止，就是用驗證集決定「樹加到第幾棵就好」。

另一個常用的超參數是 subsample：每棵樹只用隨機抽出的一部分訓練資料，例如 subsample=0.25 表示每棵樹只用 25%。這叫做隨機梯度提升（stochastic gradient boosting），一樣是用偏差高一點換變異低一點，而且訓練快很多。

各種 Gradient Boosting 的實作

投影片 47

Gradient Boosting 在表格資料上非常強，所以有很多針對速度和準確率最佳化的實作（投影片 47）：

GradientBoostingscikit-learn

本篇用的傳統版本（GBRT）。每個節點逐一嘗試門檻，資料量大時很慢。

HistGradientBoostingscikit-learn

先把每個特徵分成最多 255 個區間（histogram），只在區間的邊界上找切法，資料很多時快非常多。能直接處理缺失值和類別特徵；資料超過 10,000 筆時預設會自動提前停止。

XGBoosteXtreme Gradient Boosting

獨立的套件，在損失函數裡加上樹的正則化，同時用一次和二次微分決定每片葉子的值，速度快、可以平行運算，在資料科學競賽裡非常常見。

LightGBMLight Gradient Boosting Machine

微軟開發。也用 histogram，而且優先切「最能降低損失的葉子」（leaf-wise），所以在大資料上又快又省記憶體。

CatBoostCategorical Boosting

Yandex 開發。特別擅長處理類別特徵，並用特別的訓練順序減少過擬合，預設值通常就很好用。

它們的核心都是上一篇的演算法：一棵接一棵、每棵樹學前面留下的負梯度。差別在找切法的速度、正則化的方式，以及對類別特徵和缺失值的處理。

Python 實作

資料和切分（75 筆訓練、25 筆驗證），以及投影片 40 的兩種設定：

import numpy as np
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.metrics import mean_squared_error
from sklearn.model_selection import train_test_split

np.random.seed(42)
X = np.random.rand(100, 1) - 0.5
y = 3 * X[:, 0] ** 2 + 0.05 * np.random.randn(100)
X_train, X_val, y_train, y_val = train_test_split(X, y, random_state=49)

for lr, n in [(1.0, 3), (0.1, 200)]:
    gbrt = GradientBoostingRegressor(max_depth=2, n_estimators=n,
                                     learning_rate=lr, random_state=42)
    gbrt.fit(X_train, y_train)
    train_mse = mean_squared_error(y_train, gbrt.predict(X_train))
    val_mse = mean_squared_error(y_val, gbrt.predict(X_val))
    print(lr, n, round(train_mse, 5), round(val_mse, 5))
# 1.0 3 0.00509 0.00693
# 0.1 200 0.00027 0.00317

第一種的訓練和驗證誤差都偏高（欠擬合）；第二種的訓練誤差很小，驗證誤差卻是它的 10 倍以上，也比最好的情況（下面會找到 0.00271）差，這是過擬合。用 staged_predict() 找最好的樹數（投影片 45）：

gbrt = GradientBoostingRegressor(max_depth=2, n_estimators=120, random_state=42)
gbrt.fit(X_train, y_train)
errors = [mean_squared_error(y_val, y_pred) for y_pred in gbrt.staged_predict(X_val)]
bst_n_estimators = np.argmin(errors) + 1
print(bst_n_estimators, round(min(errors), 5))

gbrt_best = GradientBoostingRegressor(max_depth=2, n_estimators=bst_n_estimators,
                                      random_state=42)
gbrt_best.fit(X_train, y_train)
# 56 0.00271

用 warm_start=True 真的提早停下來：連續 5 棵樹驗證誤差都沒有變好就停止：

gbrt = GradientBoostingRegressor(max_depth=2, warm_start=True, random_state=42)
min_val_error = float("inf")
error_going_up = 0
for n_estimators in range(1, 120):
    gbrt.n_estimators = n_estimators
    gbrt.fit(X_train, y_train)                  # 只會補訓練新增的那一棵
    val_error = mean_squared_error(y_val, gbrt.predict(X_val))
    if val_error < min_val_error:
        min_val_error = val_error
        error_going_up = 0
    else:
        error_going_up += 1
        if error_going_up == 5:
            break                               # 提前停止
print(gbrt.n_estimators, round(min_val_error, 5))
# 61 0.00271

停在 61 棵：第 56 棵之後連續 5 棵都沒有進步。最低的驗證誤差和上一個方法一樣。最後是交給 scikit-learn 的寫法（課本第 3 版）：最多 500 棵、學習率 0.05，連續 10 棵沒進步就停：

gbrt_es = GradientBoostingRegressor(max_depth=2, learning_rate=0.05, n_estimators=500,
                                    n_iter_no_change=10, random_state=42)
gbrt_es.fit(X, y)
print(gbrt_es.n_estimators_)                    # 實際訓練了幾棵樹
# 92

這次直接用全部 100 筆資料，驗證集由它自己切（預設 10%）。最多可以到 500 棵，實際只訓練了 92 棵。

常見陷阱與自我檢查

把學習率和樹數分開調學習率變小，需要的樹就變多。調整學習率之後，要重新找最好的樹數。
用測試資料挑樹數挑樹數也是在調超參數，要用驗證集（或交叉驗證、n_iter_no_change 自動切出的驗證集），測試資料留到最後才用。
以為 Gradient Boosting 的樹越多越好和隨機森林不同，Boosting 的樹一直加下去會過擬合，所以才需要提前停止。
學習率從 0.1 調成 0.01，樹的數量通常要怎麼調？為什麼？

要增加，大約多很多倍。每棵樹的貢獻變成原來的十分之一，要更多棵樹加起來才能擬合訓練資料。好處是通常泛化得比較好，代價是訓練和預測都比較慢。

staged_predict() 和提前停止，都能找到最好的樹數，差別在哪裡？

staged_predict() 要先把很多棵樹全部訓練完，再回頭看每個階段的驗證誤差、挑最好的，最後通常再訓練一次。提前停止則是一邊加樹一邊看驗證誤差，連續幾棵沒進步就停下來，不用訓練多餘的樹。

為什麼隨機森林不太需要提前停止，Gradient Boosting 卻需要？

隨機森林的樹是各自獨立訓練再平均，樹越多結果越穩定，只會越來越接近某個極限，不會過擬合得更嚴重。Gradient Boosting 的每棵樹都在修正前面的殘差，樹一多就會開始擬合訓練資料的雜訊，驗證誤差先降後升，所以要找出停下來的時機。
