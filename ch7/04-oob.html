Out-of-Bag 評估：
沒抽到的資料剛好拿來考

用 bagging 訓練時，每棵樹大約有 37% 的訓練資料沒被抽到。這些「袋子外」的資料，那棵樹從來沒看過，剛好可以拿來考它。這篇推導 37% 從哪裡來，一步步看 OOB 評估怎麼算，以及它和驗證集有什麼不同。

這篇讀完你會知道
  • 為什麼取後放回抽 次，大約有 37%（）的資料一次都沒被抽到。
  • OOB 誤差怎麼算：每筆資料只讓「沒看過它」的樹來預測（期末考連續兩年考這題）。
  • 怎麼用 scikit-learn 的 oob_score=True 和 oob_decision_function_。
  • OOB 分數和驗證集分數有什麼不同、該怎麼選。

OOB 評估怎麼算

投影片 18–20

一棵樹在訓練時從來沒看過自己的 OOB 資料，所以可以拿這些資料來考它，效果就像一份驗證集，不用另外切資料（投影片 18）。

實際計算時是反過來看（投影片 19）：每棵樹有一組沒抽到的資料；反過來，每筆資料 也有一組「沒抽到它」的樹，記為 。用 這一小群樹來預測 ，再和真實答案比對。投影片 20 的例子：9 筆資料、5 棵樹，每棵樹的 OOB 資料各有 3 筆（只列出 到 ）。把它整理成表格，● 表示「這棵樹沒抽到這筆資料」：

資料D₁D₂D₃D₄D₅沒抽到它的樹
s₁●●D₁、D₄
s₂●●D₁、D₅
s₃●●●D₁、D₂、D₄
s₄●●●D₂、D₃、D₅
s₅●●●D₂、D₃、D₄
s₆●●D₃、D₅

直著看是每棵樹的 OOB 資料（例如 D₁ 沒抽到 s₁、s₂、s₃），橫著看就是每筆資料的 。OOB 誤差的算法：

  1. 每棵樹用自己的 bootstrap 樣本訓練。
  2. 對每一筆資料，找出沒抽到它的樹。例如 s₄ 的 是 D₂、D₃、D₅。
  3. 只用這幾棵樹預測它：分類就投票（或平均機率），迴歸就平均。這個預測記為 。
  4. 把每一筆的 和真實答案比對，錯誤率就是 OOB 誤差（迴歸就是 的平均）。
補充筆記迴歸的 OOB 分數，scikit-learn 給的是什麼？
  • BaggingRegressor、RandomForestRegressor 設 oob_score=True 時，每筆資料的 OOB 預測（沒看過它的那些樹的平均）放在 oob_prediction_。
  • oob_score_ 不是均方誤差，而是 （決定係數）：1 代表完全預測正確，0 代表和「永遠猜平均值」一樣。
  • 要投影片上的平方誤差，就用 oob_prediction_ 自己算，例如 mean_squared_error(y_train, model.oob_prediction_)。

一句話迴歸的 oob_score_ 是 ；要均方誤差，用 oob_prediction_ 自己算。

注意這和平常的預測不一樣：每筆資料是由一小群樹 預測的，不是整座森林（投影片 19）。另外，如果某筆資料剛好被每一棵樹都抽到，它就沒有 ，沒辦法評估。樹很少時會發生，樹一多就幾乎不可能。

下面是真實的例子：moons 的 375 筆訓練資料、500 棵樹（每棵取後放回抽 375 次）。點一下圖上的資料，看看哪些樹沒看過它、它們怎麼投票：

實驗：每筆資料，只讓沒看過它的樹投票

類別 0類別 1OOB 預測錯沒有樹可以評估選到的資料

OOB 準確率
測試準確率
沒有樹可以評估的資料

500 棵樹時，每筆資料平均有 184 棵樹沒看過它（500 的 37%），由它們投票。OOB 準確率 89.6%，和測試準確率 92% 很接近：測試資料只有 125 筆，差 2.4% 大約就是 3 筆。把樹減少到 5 棵以下，就會出現沒有樹可以評估的資料。

在 scikit-learn 裡：oob_score=True

投影片 18

建立 BaggingClassifier 時設 oob_score=True，訓練完就會自動做 OOB 評估，結果放在 oob_score_：

bag_clf = BaggingClassifier(DecisionTreeClassifier(), n_estimators=500,
                            oob_score=True, n_jobs=-1, random_state=42)
bag_clf.fit(X_train, y_train)
bag_clf.oob_score_          # 0.896

OOB 估計這個模型在沒看過的資料上大約有 89.6% 的準確率；實際在測試資料上是 92%，相當接近。

每筆訓練資料的 OOB 預測機率放在 oob_decision_function_：第 1 筆是 [0.324, 0.676]，表示沒看過它的樹裡，有 67.6% 認為它是類別 1（就是上面實驗一開始選到的那筆：170 棵樹裡 115 棵投類別 1）。決策樹能輸出機率，所以這裡平均的是機率，也就是軟投票。

幾個要注意的地方：

  • OOB 只有在取後放回（bootstrap=True）時才能用；設成 pasting 再要求 oob_score=True，scikit-learn 會直接報錯。
  • 隨機森林 RandomForestClassifier 也有一樣的 oob_score=True（第 5 篇），期末考問的就是它。
  • 樹太少時，有些資料沒有樹可以評估。scikit-learn 會發出警告，而且把這些資料一律當成預測類別 0 來算分數，所以那時的 oob_score_ 不可靠。

OOB 分數 vs. 驗證集分數

投影片 21

OOB 分數驗證集分數
用哪些資料評估訓練資料本身，每筆只問沒看過它的樹另外留下來、完全沒參與訓練的資料
用哪些樹預測每筆只用約 37% 的樹整座森林
要另外切資料嗎不用，訓練資料全部都能拿來訓練要，訓練資料變少
額外的計算幾乎沒有，訓練時順便算要另外預測驗證集
  • OOB 通常略為保守：每筆資料只由一部分的樹預測，而整座森林一般比一部分的樹準。樹有幾百棵時，一部分（例如 184 棵）也已經很接近整座森林，差距不大。
  • 兩種分數不要混著比：調整超參數時選定一種，比較「這組設定的 OOB 分數」和「那組設定的 OOB 分數」，或者都用驗證集。拿一組的 OOB 分數和另一組的驗證集分數比較，就像拿蘋果比橘子。
  • 資料少的時候特別有用：留不起一份驗證集時，OOB 讓所有資料都能拿來訓練，同時還有一個評估的依據。和交叉驗證比，它也不用把模型多訓練好幾次。

Python 實作

訓練 500 棵樹，看 OOB 分數和測試準確率：

from sklearn.datasets import make_moons
from sklearn.ensemble import BaggingClassifier
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

bag_clf = BaggingClassifier(DecisionTreeClassifier(), n_estimators=500,
                            oob_score=True, n_jobs=-1, random_state=42)
bag_clf.fit(X_train, y_train)
print(bag_clf.oob_score_)
print(bag_clf.score(X_test, y_test))
# 0.896
# 0.92

前三筆訓練資料的 OOB 機率，和它們真正的類別：

print(bag_clf.oob_decision_function_[:3].round(3))
print(y_train[:3])
# [[0.324 0.676]
#  [0.338 0.662]
#  [1.    0.   ]]
# [1 0 0]

第 2 筆的 OOB 樹有 66.2% 投類別 1，但它其實是類別 0，所以這筆算 OOB 預測錯。接下來自己照四個步驟算一次，看結果是不是和 oob_score_ 一樣：

import numpy as np

m = len(X_train)
votes = np.zeros((m, 2))                        # 每筆資料：OOB 樹給類別 0、1 的票
for tree, idx in zip(bag_clf.estimators_, bag_clf.estimators_samples_):
    oob = np.ones(m, dtype=bool)
    oob[idx] = False                            # 這棵樹抽到的資料不算
    votes[oob] += tree.predict_proba(X_train[oob])
print(votes[:3])
print((votes.argmax(axis=1) == y_train).mean())
# [[ 55. 115.]
#  [ 54. 106.]
#  [190.   0.]]
# 0.896

第 1 筆有 55 + 115 = 170 棵 OOB 樹，115 ÷ 170 ≈ 0.676，和 oob_decision_function_ 一樣；全部算完的準確率也是 0.896。最後驗證 37%：

for n in [2, 5, 10, 100, 375, 10_000]:
    print(n, round((1 - 1 / n) ** n, 4))
print(round(np.exp(-1), 4))                     # 1/e
print(np.mean([1 - len(np.unique(i)) / m for i in bag_clf.estimators_samples_]).round(4))
# 2 0.25
# 5 0.3277
# 10 0.3487
# 100 0.366
# 375 0.3674
# 10000 0.3679
# 0.3679
# 0.3678

最後一行是實際的 500 棵樹：平均每棵樹有 36.78% 的訓練資料沒被抽到，和理論值 幾乎一樣。

常見陷阱與自我檢查

以為 OOB 預測是整座森林的預測每筆資料只由沒看過它的那一小群樹（約 37%）預測，所以 OOB 分數通常比整座森林的實際表現略低一點。
以為每棵樹的 OOB 資料是同一批每棵樹抽到的資料不一樣，OOB 資料也各不相同；37% 指的是每棵樹各自大約有這麼多。
用 pasting 時想看 OOB 分數OOB 只能搭配取後放回（bootstrap=True）。
（2024、2023 期末考）舉一個例子，說明 OOB 誤差怎麼算。

用投影片 20 的例子：5 棵樹 D₁～D₅ 各自用 bootstrap 樣本訓練，例如 D₁ 沒抽到 s₁、s₂、s₃。對每一筆資料，找出沒抽到它的樹，例如 s₄ 沒被 D₂、D₃、D₅ 抽到，就只用這三棵樹投票預測 s₄，再和 s₄ 的真實答案比對。每一筆都這樣做（沒有任何樹可以評估的資料略過），錯的比例就是 OOB 誤差。考古題詳解有一個列出每一步的完整例子（6 筆資料、3 棵樹，算出 OOB 誤差 40%）。

為什麼每棵樹大約有 37% 的資料沒被抽到？

筆資料取後放回抽 次，某一筆每次沒被抽到的機率是 ， 次都沒抽到是 。 很大時趨近 。

OOB 分數和驗證集分數，一般來說哪一個比較保守？為什麼？

OOB 分數比較保守（略低）。OOB 每筆資料只由約 37% 的樹預測，驗證集則用整座森林預測，而整座森林通常比一部分的樹準。樹很多時兩者差距不大。

只訓練 3 棵樹時做 OOB 評估，會有什麼問題？

一筆資料被 3 棵樹都抽到的機率約是 ，所以大約四分之一的資料沒有樹可以評估；其他資料也只有一兩棵樹投票，結果很不穩定。scikit-learn 這時會警告估計不可靠。
