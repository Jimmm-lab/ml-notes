投票分類器：
硬投票與軟投票

集成學習最直接的做法：用不同的演算法各訓練一個模型，再讓它們投票。這篇用 moons 資料訓練邏輯迴歸、隨機森林和 SVM，看投票怎麼把三個各有缺點的模型合成一個更準的模型，以及「硬投票」和「軟投票」差在哪裡。

這篇讀完你會知道
  • 硬投票分類器怎麼做預測：每個模型投一票，選票數最多的類別。
  • 為什麼三個各錯十幾筆的模型，投票之後錯得比任何一個都少。
  • 軟投票怎麼把機率平均起來，以及它為什麼常常比硬投票好（期末考題）。
  • 怎麼用 scikit-learn 的 VotingClassifier 做硬投票和軟投票。

不同的演算法，一起投票

投影片 7–8

假設你已經訓練好幾個分類器，每個的準確率都還不錯，例如邏輯迴歸、SVM、隨機森林（投影片 7）。它們用的演算法不同，犯錯的地方也不太一樣，這就是上一篇說的多樣性。

要合併它們最簡單的方法：遇到一筆新資料，每個分類器各自預測、各投一票，得票最多的類別就是最後的預測（投影片 8）。這叫做硬投票（hard voting）分類器。例如：

分類器預測
邏輯迴歸類別 1
SVM類別 1
隨機森林類別 2
其他分類器類別 1
投票結果類別 1（3 票對 1 票）

多數決的道理就是上一篇的擲硬幣：只要每個分類器都比亂猜好、犯的錯又不一樣，投票的結果常常比其中最好的分類器還準。

用 scikit-learn 做硬投票

投影片 9

投影片 9 用 moons 資料（兩個交錯的半月形，500 筆，帶有雜訊）示範：375 筆訓練、125 筆測試，訓練三個不同的分類器，再用 VotingClassifier 把它們合起來（完整程式在 Python 實作）。在測試資料上的準確率：

分類器測試準確率錯幾筆（共 125 筆）
邏輯迴歸86.4%17
隨機森林89.6%13
SVM89.6%13
硬投票91.2%11

投票分類器比三個成員都準。關鍵在於它們錯在不同的地方：三個模型各錯 17、13、13 筆，但同一筆資料有兩個以上模型一起錯的，只有 11 筆。只有一個模型錯的那 14 筆，另外兩個會把它投回來；投票只會在「至少兩個一起錯」時跟著錯。

邏輯迴歸只會畫直線，隨機森林的邊界一格一格，SVM 是一條平滑的曲線。三種完全不同的邊界，錯的地方也不同，投票就能互相截長補短。

軟投票：把機率平均

投影片 12

如果每個分類器都能估計每一類的機率（都有 predict_proba()），還有另一種合併方法：把每個分類器給的機率平均起來，選平均機率最高的類別。這叫做軟投票（soft voting）。

軟投票通常比硬投票好，因為它讓很有把握的模型有更大的影響力（投影片 12）。例如三個分類器對同一筆資料給出「是類別 1 的機率」：

分類器類別 1 的機率投的票
A0.45類別 0
B0.40類別 0
C0.95類別 1
  • 硬投票看右欄的票：類別 0 有 2 票、類別 1 只有 1 票，所以答類別 0。
  • 軟投票看中間的機率，平均是 ，超過 0.5，所以答類別 1。

同一筆資料，兩種投票給出相反的答案。A 和 B 其實很猶豫（0.45、0.40 都接近 0.5），C 卻非常有把握。硬投票只數票數，C 的把握完全沒有用；軟投票把把握程度算進去，結果就倒向 C。

在 scikit-learn 裡，只要把 voting="hard" 換成 voting="soft"，並確定每個分類器都能輸出機率。邏輯迴歸和隨機森林本來就可以；SVM 只會輸出「離邊界多遠」的分數，要先包一層 CalibratedClassifierCV，把分數換算成機率。

補充筆記為什麼 SVM 要包一層 CalibratedClassifierCV？投影片上的 probability=True 呢？
  • SVM 預測時算的是「離決策邊界多遠」的分數，不是機率。CalibratedClassifierCV 用交叉驗證另外學一個函數（預設是 S 形的 sigmoid），把分數換算成 0 到 1 之間的機率。
  • ensemble=False 表示最後只保留一個用全部訓練資料訓練的 SVM，再配上學好的換算函數。
  • 投影片和課本寫的 SVC(probability=True) 做的是同一件事。但 scikit-learn 1.9 起不建議再用這個參數（1.11 版會移除），官方建議改成 CalibratedClassifierCV(SVC(), ensemble=False)。
  • 因為多了交叉驗證，訓練會比較慢。換算後的機率和原本的分數偶爾會不一致：這裡的 SVM 換成機率後，單獨的準確率是 88.8%，原本是 89.6%。

一句話SVM 本身沒有機率，要另外學一個「分數換機率」的函數，軟投票才用得上它。

換成軟投票之後，測試準確率從 91.2% 提高到 92%（課本說「超過 91.2%」）。在上面的實驗切到「軟投票」，看邊界和錯誤怎麼變。

使用時要注意的地方

課本補充

  • 成員要多樣：投票的效果來自「錯在不同的地方」。三個幾乎一樣的模型，投票等於只問一個。
  • 成員不能太差：每個成員都要比亂猜好。加進一個很差的模型，反而可能把投票拖下水。
  • 硬投票最好用奇數個模型：兩類問題、偶數個模型可能平手。scikit-learn 平手時選編號比較小的類別，不一定是你要的結果；軟投票比較不會遇到平手。
  • 可以加權：VotingClassifier 的 weights 參數可以讓比較準的模型多算幾票（或在軟投票時佔比較大的比重）。
  • 迴歸也可以：VotingRegressor 把每個模型預測的數值平均。

Python 實作

投影片 9 的硬投票：三個不同的分類器，用 VotingClassifier 合起來，再分別看每個成員和投票的測試準確率：

from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier, VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.svm import SVC

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

voting_clf = VotingClassifier(
    estimators=[("lr", LogisticRegression(random_state=42)),
                ("rf", RandomForestClassifier(random_state=42)),
                ("svc", SVC(random_state=42))],
    voting="hard")
voting_clf.fit(X_train, y_train)

for name, clf in voting_clf.named_estimators_.items():   # 訓練好的三個成員
    print(name, clf.score(X_test, y_test))
print("voting", voting_clf.score(X_test, y_test))
# lr 0.864
# rf 0.896
# svc 0.896
# voting 0.912

換成軟投票：SVM 改成能輸出機率的版本，再重新訓練：

from sklearn.calibration import CalibratedClassifierCV

voting_clf.set_params(voting="soft",
                      svc=CalibratedClassifierCV(SVC(random_state=42), ensemble=False))
voting_clf.fit(X_train, y_train)
print(voting_clf.score(X_test, y_test))
# 0.92

軟投票的預測，就是三個成員機率的平均。看第一筆測試資料：

for name, clf in voting_clf.named_estimators_.items():
    print(name, clf.predict_proba(X_test[:1]).round(3))
print("soft", voting_clf.predict_proba(X_test[:1]).round(3), "答案", y_test[0])
# lr [[0.499 0.501]]
# rf [[0.48 0.52]]
# svc [[0.575 0.425]]
# soft [[0.518 0.482]] 答案 1

這一筆很有意思：邏輯迴歸和隨機森林都只是勉強偏向類別 1（0.501、0.52），SVM 比較有把握是類別 0（類別 1 只有 0.425）。平均 ，軟投票預測類別 0，答錯了；硬投票 2 比 1 預測類別 1，反而答對。軟投票整體比較準（92% 對 91.2%），但不是每一筆都比較好。

常見陷阱與自我檢查

以為軟投票就是把預測的類別平均軟投票平均的是每一類的機率，再選平均機率最高的類別；硬投票才是數票數。
軟投票時忘了讓每個成員都能輸出機率每個成員都要有 predict_proba()。SVM 要包一層 CalibratedClassifierCV（舊寫法是 probability=True）。
以為投票一定比最好的成員準成員要夠多樣、每個都比亂猜好才會成立；成員太像或太差，投票不一定有幫助。
（2024 期末考的一部分）硬投票和軟投票有什麼不同？為什麼軟投票通常比較好？

硬投票是每個模型投一票，選票數最多的類別；軟投票是把每個模型估計的每一類機率平均，選平均機率最高的類別。軟投票把「有多大把握」也算進去，很有把握的模型影響比較大，猶豫的模型影響比較小，所以通常比硬投票準。但軟投票要求每個模型都能估計機率。

三個模型對同一筆資料給出「是類別 1 的機率」0.6、0.6、0.1。硬投票和軟投票各預測哪一類？

硬投票：前兩個投類別 1、第三個投類別 0，2 比 1，預測類別 1。軟投票：平均 ，預測類別 0。第三個模型非常有把握是類別 0，軟投票讓它的意見佔了上風。

三個模型在 125 筆測試資料上各錯 17、13、13 筆，硬投票卻只錯 11 筆。這是怎麼發生的？

它們錯在不同的地方。只要一筆資料只有一個模型錯，另外兩個就會把它投回正確答案；只有「至少兩個模型一起錯」的資料，投票才會錯。這份資料裡，至少兩個一起錯的剛好是 11 筆。
