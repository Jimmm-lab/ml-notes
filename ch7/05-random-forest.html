隨機森林與 Extra-Trees：
再多一點隨機

隨機森林就是用 bagging 訓練的一群決策樹，但多了一個隨機：每個節點只從隨機挑出的幾個特徵裡找最好的切法。Extra-Trees 更進一步，連切的門檻都隨機決定。這篇看這兩種隨機怎麼讓樹更多樣，以及隨機森林附帶的好工具：特徵重要性。

這篇讀完你會知道
  • 隨機森林 = bagging + 決策樹 + 每個節點隨機挑特徵（max_features="sqrt"）。
  • 為什麼多一點隨機（偏差略高、變異更低），森林通常會更準。
  • 特徵重要性怎麼算：用到這個特徵的節點，平均讓不純度下降多少。
  • Extra-Trees 和隨機森林差在哪裡，以及該怎麼選。

隨機森林：每個節點隨機挑特徵

投影片 25–26

隨機森林（random forest）是一群決策樹，通常用 bagging（偶爾用 pasting）訓練，每棵樹抽的筆數通常和訓練資料一樣多（投影片 25）。你可以自己用 BaggingClassifier 包一個 DecisionTreeClassifier，但 scikit-learn 有專門的 RandomForestClassifier（迴歸用 RandomForestRegressor），用起來方便，也針對決策樹做了最佳化。

和普通的 bagging 比，隨機森林在長樹時多加了一個隨機（投影片 26）：

每個節點不是從所有特徵裡找最好的切法，而是先隨機挑一部分特徵，再從這幾個特徵裡找最好的切法。分類時預設挑 個（ 是特徵數，max_features="sqrt"）。

這讓每棵樹長得更不一樣。代價是偏差高一點（有時候最好的特徵沒被挑到），換來更低的變異，整體通常更好。所以隨機森林用了三種手法：隨機抽資料（bootstrap）、每個節點隨機抽特徵、把預測平均起來（投票）。

用鳶尾花資料（150 筆、4 個特徵）看看根節點怎麼切。每一列是一個特徵，三種花分成三排畫出來；線是切的位置，右邊的長條是這一刀讓 Gini 不純度下降多少（越長越好）。切換三種做法，按「再抽一次」：

決策樹每次都看全部特徵，第一刀永遠切在花瓣上（花瓣長度和花瓣寬度一樣好，都能把 setosa 完全分出來）。隨機森林每次只看 2 個特徵：抽到的 2 個裡只要有花瓣就切花瓣；只有抽到「花萼長度＋花萼寬度」（6 種組合中的 1 種）時，第一刀才會切在花萼長度上。用 scikit-learn 實際訓練 500 棵樹（每棵還用了 bootstrap 抽樣），根節點切在花瓣長度的有 220 棵、花瓣寬度 178 棵、花萼長度 102 棵：樹的長相確實變得更多樣。

這和第 3 篇的 Random Subspaces 不一樣：隨機森林是每個節點重新抽特徵，不是每棵樹抽一次。

補充筆記隨機森林隨機挑特徵，和第 3 篇的 Random Subspaces 有什麼不同？
  • Random Subspaces 是每棵樹抽一次特徵：這棵樹從頭到尾只能用這幾個特徵。
  • 隨機森林是每個節點重新抽一次：根節點可能看花萼長度和花瓣寬度，下一個節點換成花萼寬度和花瓣長度。整棵樹還是可能用到所有特徵。
  • 所以隨機森林的每棵樹不會因為「剛好沒抽到最重要的特徵」而整棵都很差，只是某些節點沒有切在最好的地方。

一句話Random Subspaces 每棵樹抽一次特徵；隨機森林每個節點都重抽。

也因此，下面這兩個模型大致相等：RandomForestClassifier(n_estimators=500, max_leaf_nodes=16)，以及 BaggingClassifier(DecisionTreeClassifier(max_features="sqrt", max_leaf_nodes=16), n_estimators=500)。在 moons 資料上，兩者對 125 筆測試資料的預測完全一樣（見 Python 實作）。

補充筆記RandomForestClassifier、RandomForestRegressor 的預設值有什麼要注意的？
  • max_features：分類器預設 "sqrt"（每個節點看 個特徵）；迴歸器預設 1.0，也就是每個節點看全部特徵，等於只有 bootstrap 的 bagging。要讓迴歸森林也隨機挑特徵，要自己設，例如 max_features="sqrt" 或 0.33。
  • bootstrap=True、max_samples=None：每棵樹取後放回抽和訓練資料一樣多筆。
  • 每棵樹預設不限制大小（max_depth=None、min_samples_leaf=1），靠很多棵平均來降低變異；第 6 章的正則化超參數都可以用在每棵樹上。
  • n_estimators 預設 100。樹越多越穩定、也越慢，但不會因此過度擬合。

一句話分類森林預設每個節點看 個特徵，迴歸森林預設看全部。

特徵重要性

投影片 25、27

隨機森林還有一個很好用的地方：很容易看出每個特徵有多重要（投影片 25）。scikit-learn 的算法是：看用到這個特徵的節點，平均讓不純度下降了多少（以經過節點的資料筆數加權，再對所有樹平均），最後把所有特徵的重要性調整成加起來等於 1（投影片 27）。

先看一棵樹怎麼算。第 6 章第 1 篇那棵深度 2 的鳶尾花樹：根節點用花瓣長度切，右邊的節點再用花瓣寬度切。

第 1 步：每個節點讓不純度下降多少

根節點（150 筆，Gini 0.667）用花瓣長度切成 50 筆（Gini 0）和 100 筆（Gini 0.5）。下降量乘上「經過這個節點的資料比例」：

右邊的節點（100 筆，Gini 0.5）用花瓣寬度切成 54 筆（Gini 0.168）和 46 筆（Gini 0.043）：

第 2 步：同一個特徵的節點加起來，再調整成總和 1

花瓣長度 0.333、花瓣寬度 0.260，總和 0.593。各除以 0.593：花瓣長度 、花瓣寬度 ，兩個花萼特徵沒被用到，都是 0。

隨機森林就是把每棵樹這樣算出來的重要性平均。投影片 27 用 500 棵樹的隨機森林，得到花萼長度 0.11、花萼寬度 0.02、花瓣長度 0.44、花瓣寬度 0.42：花瓣的兩個特徵最重要，和上面實驗看到的一致。因為隨機森林每個節點會隨機挑特徵，花萼長度也有機會被用到，所以它的重要性不是 0。

特徵很多時，重要性也很好用。下面是手寫數字資料（8×8 的灰階圖片，每個像素是一個特徵，共 64 個）：左邊是 1,797 張圖片的平均，右邊是隨機森林算出來每個像素的重要性：

所以要做特徵選擇時，隨機森林是很方便的第一步：先看哪些特徵幾乎沒用，再決定要不要拿掉。

補充筆記特徵重要性可以完全相信嗎？
  • 這種重要性是用訓練資料上的不純度下降算的。樹會過度擬合時，連沒用的特徵也可能分到一些重要性。
  • 它偏好可以切很多種門檻的特徵（例如連續數值、或類別很多的特徵），因為這種特徵比較容易找到「剛好」降低不純度的切法。
  • 兩個特徵很像時（例如花瓣長度和花瓣寬度），重要性會被它們分掉，各自看起來都沒那麼重要。
  • 想要更可靠的結果，可以用 scikit-learn 的 permutation_importance：在驗證資料上把某個特徵的值打亂，看準確率掉多少。

一句話不純度算出的重要性快又方便，適合當第一步；要下結論時，最好再用打亂特徵的方法確認。

Extra-Trees：連門檻也隨機

投影片 28

隨機森林的每個節點雖然只看隨機挑出的特徵，但對每個特徵還是會找最好的門檻。Extra-Trees 再多走一步：對每個候選特徵，隨機挑一個門檻（在這個節點的資料裡，這個特徵的最小值和最大值之間隨機挑），再從這幾個隨機的切法裡選最好的一個（投影片 28）。

這種樹叫做 Extremely Randomized Trees，簡稱 Extra-Trees，scikit-learn 用 ExtraTreesClassifier、ExtraTreesRegressor。在上面的實驗切到「Extra-Trees」看看：隨機的門檻常常沒有落在花瓣的空隙，花萼被選上的機會因此變多，每一刀也比較不準。

隨機森林

每個節點：隨機挑特徵，每個特徵找最好的門檻。預設每棵樹用 bootstrap 抽樣（bootstrap=True）。

Extra-Trees

每個節點：隨機挑特徵，每個特徵隨機挑一個門檻。預設每棵樹用全部的訓練資料（bootstrap=False），隨機性全部來自切法。

  • 偏差更高、變異更低：每一刀都比較隨便，單棵樹比較不準，但樹與樹之間更不一樣。
  • 訓練快很多：長樹時最花時間的工作，就是在每個節點替每個特徵找最好的門檻；Extra-Trees 直接跳過這一步。
  • 哪個比較好很難事先知道：唯一的辦法是兩個都試，用交叉驗證比較。在 moons 資料上隨機森林略好（0.904 對 0.899）；在手寫數字資料上 Extra-Trees 比較好（0.940 對 0.958）。

Python 實作

隨機森林，以及和它大致相等的 bagging 寫法（每棵樹最多 16 片葉子）：

from sklearn.datasets import make_moons
from sklearn.ensemble import BaggingClassifier, RandomForestClassifier
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

rnd_clf = RandomForestClassifier(n_estimators=500, max_leaf_nodes=16,
                                 n_jobs=-1, random_state=42)
rnd_clf.fit(X_train, y_train)
bag_clf = BaggingClassifier(
    DecisionTreeClassifier(max_features="sqrt", max_leaf_nodes=16),
    n_estimators=500, n_jobs=-1, random_state=42)
bag_clf.fit(X_train, y_train)

y_pred_rf = rnd_clf.predict(X_test)
y_pred_bag = bag_clf.predict(X_test)
print(rnd_clf.score(X_test, y_test), bag_clf.score(X_test, y_test))
print((y_pred_rf == y_pred_bag).mean())         # 兩個模型預測相同的比例
# 0.912 0.912
# 1.0

隨機森林和 Extra-Trees，在兩份資料上各做 5 折交叉驗證：

from sklearn.datasets import load_digits
from sklearn.ensemble import ExtraTreesClassifier
from sklearn.model_selection import cross_val_score

X_digits, y_digits = load_digits(return_X_y=True)
datasets = {"moons": (X_train, y_train), "digits": (X_digits, y_digits)}
for name, (X_, y_) in datasets.items():
    for clf in (RandomForestClassifier(n_estimators=500, n_jobs=-1, random_state=42),
                ExtraTreesClassifier(n_estimators=500, n_jobs=-1, random_state=42)):
        score = cross_val_score(clf, X_, y_, cv=5).mean()
        print(name, type(clf).__name__, score.round(3))
# moons RandomForestClassifier 0.904
# moons ExtraTreesClassifier 0.899
# digits RandomForestClassifier 0.94
# digits ExtraTreesClassifier 0.958

手寫數字的像素重要性（上面那張圖的右半邊）：

rnd_clf_d = RandomForestClassifier(n_estimators=500, n_jobs=-1, random_state=42)
rnd_clf_d.fit(X_digits, y_digits)
imp = rnd_clf_d.feature_importances_.reshape(8, 8)
print(imp[:, 0].round(4))                          # 最左邊一欄的 8 個像素
print(imp.max().round(3), imp.argmax() // 8, imp.argmax() % 8)   # 最重要的像素：第幾列、第幾欄
# [0.     0.     0.0001 0.0001 0.     0.     0.     0.    ]
# 0.052 2 5

最左邊一欄的像素幾乎永遠是空白，重要性都接近 0；最重要的是第 2 列、第 5 欄（從 0 開始數）的像素，重要性約 0.052。

常見陷阱與自我檢查

以為隨機森林只是「很多棵樹投票」它還在每個節點隨機挑特徵。只用 bootstrap、每個節點看全部特徵的，是 bagging 決策樹；迴歸森林的預設值就是這樣（max_features=1.0）。
以為重要性 0.02 的特徵一定沒用重要性會被相似的特徵分掉，而且是用訓練資料算的。拿掉特徵前，最好用驗證資料確認。
以為 Extra-Trees 一定比隨機森林好（或差）要看資料。兩個都試，用交叉驗證比較。
隨機森林比 bagging 決策樹多了什麼隨機？為什麼這樣通常比較好？

每個節點只從隨機挑出的一部分特徵（分類預設 個）裡找最好的切法。這讓樹與樹之間更不一樣、彼此比較不相關；每棵樹的偏差略高，但平均之後變異降低更多，整體通常比較準。

鳶尾花有 4 個特徵，隨機森林在每個節點看幾個？根節點切在花萼長度的機率大約是多少（不考慮 bootstrap）？

個。4 個特徵挑 2 個有 6 種組合，只有「花萼長度＋花萼寬度」這一種不含花瓣特徵，這時花萼長度比花萼寬度好，所以機率約 。實際的 500 棵樹還有 bootstrap 的影響，是 102 棵（約 20%）。

scikit-learn 的特徵重要性是怎麼算的？

對每棵樹，把用到這個特徵的每個節點的不純度下降量（乘上經過這個節點的資料比例）加起來；再對所有樹平均，最後調整成所有特徵的重要性加起來等於 1。

Extra-Trees 和隨機森林差在哪裡？它為什麼訓練比較快？

兩者每個節點都隨機挑特徵，但隨機森林會替每個特徵找最好的門檻，Extra-Trees 則隨機挑一個門檻，再從這些隨機的切法裡選最好的。找最好的門檻是長樹最花時間的步驟，Extra-Trees 跳過它，所以快很多。另外 Extra-Trees 預設不用 bootstrap，每棵樹都用全部的訓練資料。

  5. 隨機森林與 Extra-Trees：再多一點隨機（本篇）
  6. AdaBoost：把注意力放在做錯的資料上
  7. Gradient Boosting：一棵接一棵修正殘差
  8. 學習率、樹的數量與提前停止
  9. Stacking：讓模型學會怎麼合併預測
