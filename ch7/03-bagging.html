Bagging 與 Pasting：
同一種模型，抽不同的資料

上一篇用不同的演算法做出多樣的模型。這篇換個做法：所有模型都用同一種演算法（通常是決策樹），但每個模型拿到的訓練資料都是隨機抽出來的，彼此不一樣。取後放回的抽法叫 bagging，不放回叫 pasting。

這篇讀完你會知道
  • Bagging 和 Pasting 怎麼抽資料，差在「取後放回」還是「不放回」。
  • 為什麼 500 棵各自只有約 85% 的樹，合起來能到 90%：bagging 主要降低變異。
  • 怎麼用 BaggingClassifier，以及 max_samples、bootstrap、n_jobs 這些參數的意思。
  • Random Patches 和 Random Subspaces：連特徵也隨機抽。

同一種演算法，抽不同的資料

投影片 13–14

要讓模型多樣化，上一篇的做法是用不同的演算法。另一個做法是：每個模型都用同一種演算法，但各自用訓練資料中隨機抽出的一部分來訓練（投影片 13）。抽法有兩種：

  • Bagging：取後放回（with replacement）。抽到一筆之後把它放回去，下一次還可能再抽到它，所以同一個模型的資料裡，同一筆可能出現好幾次。Bagging 是 bootstrap aggregating 的縮寫；統計學把取後放回的抽樣叫做 bootstrap。
  • Pasting：取後不放回（without replacement）。同一個模型的資料裡，每一筆最多出現一次。

投影片 14 的圖就是 bagging：從原始資料取後放回地抽出好幾袋資料（bootstrapping），每袋各訓練一個分類器，最後把它們的預測合起來（aggregating）。注意最右邊那一袋：1 號被抽到 3 次、3 號被抽到 2 次。

下面用 10 筆資料、5 個模型試試看。每一列是一個模型，格子裡的數字是那筆資料被抽到幾次。切到 Pasting 之後，也把筆數拉到 10 筆，看看會發生什麼事：

實驗：每個模型拿到哪幾筆資料

沒抽到1 次2 次3 次以上
每個模型抽
平均抽到不同的
平均沒抽到

不管哪一種抽法，同一筆資料都可能被好幾個模型抽到（同一欄有好幾格）；差別在於只有 bagging 允許同一個模型抽到同一筆好幾次（投影片 17）。

每個模型訓練好之後，用投票把預測合起來：分類問題選最多票的類別，迴歸問題取平均。scikit-learn 的 BaggingClassifier 如果發現成員能輸出機率（例如決策樹），會自動改用軟投票，把機率平均（上一篇）。

每個模型只看到一部分資料，單獨來看，會比用全部資料訓練的模型差一點（偏差比較高）。但合起來之後，偏差和變異都會降低。整體來說，集成的偏差和「用全部資料訓練的單一模型」差不多，變異卻小很多。

還有一個實際的好處：每個模型各自訓練、互不相干，可以同時在不同的 CPU 核心、甚至不同的電腦上訓練，預測時也一樣，所以 bagging 和 pasting 很容易擴展到大量的資料（投影片 13）。

左邊的單一決策樹為了遷就每一筆訓練資料，切出很多小區塊（過度擬合），測試準確率 85.6%。右邊 500 棵樹的邊界平滑得多，測試準確率 90.4%。兩邊的邊界大致在同一個位置，表示偏差差不多；但右邊不會被個別的資料點拉來拉去，表示變異小很多。

哪一個比較好？投影片 16–17 的說法：

  • 取後放回時，每一次抽都和之前抽到什麼無關（互相獨立）；不放回時，前面抽到的會影響後面還能抽到什麼。所以 bagging 抽出來的子集，彼此差異比較大，比較多樣。
  • 多樣的代價：每個模型的資料和原始資料差比較多，所以每個模型的偏差略高。好處：模型之間比較不相關，合起來的變異比較低。
  • 整體來說 bagging 通常比較好，所以一般預設用 bagging。
補充筆記投影片 16 說「不放回時，兩次抽樣的共變異數不是 0」，是什麼意思？
  • 假設資料有 筆，某個特徵的數值平均是 、變異數是 （以 為分母）。抽兩次，第一次抽到的值記為 ，第二次記為 。
  • 取後放回：兩次互不影響，。
  • 不放回：第一次抽走一個很大的值，剩下的平均就變小，第二次比較可能抽到小的值。算出來是 ，是負的。
  • 很大時， 接近 0。所以資料很多、每個模型只抽一小部分時，bagging 和 pasting 幾乎一樣；只抽到全部或接近全部時，差別才明顯（pasting 抽滿就完全沒有多樣性）。

一句話不放回的抽樣，後一次會受前一次影響；放回的抽樣每次都是重新開始，抽出來的子集比較多樣。

最後一點：bagging 降低的是變異，所以最適合變異大的模型，例如不限制深度的決策樹（投影片 17）。對本來就很穩定的模型幫助不大：在同一份 moons 資料上，邏輯迴歸的測試準確率是 86.4%；bagging 500 個邏輯迴歸（每個都取後放回抽 375 筆），結果還是 86.4%。每個邏輯迴歸畫出來的都是差不多的一條直線，平均起來還是那條直線。

連特徵也抽：Random Patches 與 Random Subspaces

投影片 22–24

BaggingClassifier 不只能抽資料，也能抽特徵：每個模型只用隨機挑出的一部分特徵來訓練（投影片 22）。控制特徵抽樣的參數是 max_features 和 bootstrap_features，用法和 max_samples、bootstrap 一樣，只是對象從資料（列）換成特徵（欄）。

下面每個方格表代表一個模型拿到的訓練資料：每一列是一筆資料，每一欄是一個特徵，上色的格子是這個模型用得到的部分（投影片 23）：

實驗：抽資料、抽特徵，或兩個都抽

每個表是 8 筆資料、6 個特徵。抽資料是取後放回抽 6 筆（max_samples=0.75），抽特徵是取後放回抽 3 個（max_features=0.5）；旁邊的「×2」表示那一列或那一欄被抽到兩次。

  • Random Patches：資料和特徵都抽。
  • Random Subspaces：保留所有資料（bootstrap=False、max_samples=1.0），只抽特徵（bootstrap_features=True，或把 max_features 設成小於 1.0）。

抽特徵讓模型更多樣，代價是偏差再高一點，換來更低的變異。特徵很多的資料（例如影像，每個像素都是一個特徵）特別適合這麼做：每個模型只看一部分特徵，訓練也快很多。第 5 篇的隨機森林也用了類似的想法，只是改成在樹的每個節點隨機挑特徵。

max_samples 和 max_features 可以給整數或小數（投影片 24）：整數是直接指定幾筆、幾個；小數是比例，例如 max_features=0.5 表示抽特徵數量的一半。

補充筆記投影片 24 的 base_estimator 參數，現在還能用嗎？
  • 不能。投影片 24 截的是舊版 scikit-learn 的說明文件，第一個參數叫 base_estimator。1.2 版把它改名為 estimator，1.4 版移除了舊名字。
  • 本篇的寫法 BaggingClassifier(DecisionTreeClassifier(), ...) 是直接把模型當成第一個參數傳進去，新舊版本都能用。要寫名字的話，請寫 estimator=DecisionTreeClassifier()。
  • 投影片上其他參數的意思都沒變。max_samples 的預設值是 1.0（抽和訓練資料一樣多筆），max_features 的預設值是 1.0（全部特徵）。

一句話新版要寫 estimator=，不是 base_estimator=。

Python 實作

投影片 15 的圖 7-5：一棵決策樹，和 500 棵樹的 bagging：

from sklearn.datasets import make_moons
from sklearn.ensemble import BaggingClassifier
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = make_moons(n_samples=500, noise=0.30, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

tree_clf = DecisionTreeClassifier(random_state=42)
tree_clf.fit(X_train, y_train)
print(tree_clf.score(X_test, y_test))

bag_clf = BaggingClassifier(DecisionTreeClassifier(), n_estimators=500,
                            max_samples=100, n_jobs=-1, random_state=42)
bag_clf.fit(X_train, y_train)
print(bag_clf.score(X_test, y_test))
# 0.856
# 0.904

每棵樹抽到哪些資料，記錄在 estimators_samples_（資料的編號）。看看第一棵樹，以及 500 棵的平均：

import numpy as np

idx = bag_clf.estimators_samples_[0]       # 第 1 棵樹抽到的資料編號
print(len(idx), len(np.unique(idx)))
print(np.mean([len(np.unique(i)) for i in bag_clf.estimators_samples_]))
# 100 84
# 88.0

第 1 棵樹抽了 100 次，只抽到 84 筆不同的資料，其他 16 次都是重複的。500 棵樹平均抽到 88 筆不同的資料，和理論值 幾乎一樣。

補充筆記平均抽到幾筆不同的資料，理論值怎麼算？
  • 從 筆資料取後放回抽 次。看某一筆特定的資料：每一次沒抽到它的機率是 ， 次都沒抽到的機率是 。
  • 所以它至少被抽到一次的機率是 。 筆資料都一樣，平均抽到的不同資料就有 筆。
  • 這裡 、： 筆。第一個實驗是 ： 筆。
  • 如果每次抽的筆數和資料一樣多（，這是 max_samples 的預設）， 很大時大約只會抽到 63% 的資料，另外約 37% 一次都沒被抽到。下一篇會用這些沒抽到的資料來評估模型。

一句話每筆資料「一次都沒被抽到」的機率是 ，乘上 就是平均沒抽到幾筆。

Bagging 和 pasting 比一比：除了這一次的測試準確率，再用訓練資料做 5 折交叉驗證：

from sklearn.model_selection import cross_val_score

for bootstrap in (True, False):
    clf = BaggingClassifier(DecisionTreeClassifier(), n_estimators=500, max_samples=100,
                            bootstrap=bootstrap, n_jobs=-1, random_state=42)
    clf.fit(X_train, y_train)
    cv = cross_val_score(clf, X_train, y_train, cv=5).mean()
    print(bootstrap, clf.score(X_test, y_test), cv.round(3))
# True 0.904 0.931
# False 0.92 0.92

Random Patches 和 Random Subspaces 要在特徵多的資料上才看得出意義。換成 scikit-learn 內建的乳癌資料集（569 筆、30 個特徵，判斷腫瘤是良性還是惡性），用投影片 23 的設定，各做 5 折交叉驗證：

from sklearn.datasets import load_breast_cancer

X_bc, y_bc = load_breast_cancer(return_X_y=True)
tree = DecisionTreeClassifier()
models = {
    "單一決策樹": DecisionTreeClassifier(random_state=42),
    "Bagging": BaggingClassifier(tree, n_estimators=500, max_samples=0.75,
        bootstrap=True, n_jobs=-1, random_state=42),
    "Random Subspaces": BaggingClassifier(tree, n_estimators=500, max_samples=1.0,
        bootstrap=False, max_features=0.5, bootstrap_features=True,
        n_jobs=-1, random_state=42),
    "Random Patches": BaggingClassifier(tree, n_estimators=500, max_samples=0.75,
        bootstrap=True, max_features=0.5, bootstrap_features=True,
        n_jobs=-1, random_state=42),
}
for name, model in models.items():
    print(name, cross_val_score(model, X_bc, y_bc, cv=5).mean().round(3))
# 單一決策樹 0.917
# Bagging 0.96
# Random Subspaces 0.965
# Random Patches 0.958

三種集成都比單一決策樹好了 4 個百分點左右，彼此則差不多。哪一種最好要看資料，一樣用交叉驗證來選。每棵樹拿到哪些特徵，記錄在 estimators_features_：

patch_clf = models["Random Patches"].fit(X_bc, y_bc)
print(np.sort(patch_clf.estimators_features_[0]))   # 第 1 棵樹的特徵編號
# [ 2  7  7  9  9 10 12 18 19 24 24 26 27 28 29]

第 1 棵樹抽了 15 個特徵（30 的一半）。因為 bootstrap_features=True 是取後放回，7、9、24 號各被抽到兩次，實際上只用到 12 個不同的特徵。

常見陷阱與自我檢查

Pasting 時讓每個模型抽滿全部資料bootstrap=False 再加上 max_samples=1.0（預設），每個模型拿到的資料一模一樣，完全沒有多樣性。Pasting 一定要讓每個模型抽的筆數比全部資料少。
以為 bagging 對任何模型都有幫助Bagging 主要降低變異，最適合變異大的模型（不限制深度的決策樹）。對邏輯迴歸這種穩定的模型，幾乎沒有幫助。
以為 bagging 讓每一棵樹變準每棵樹只用抽出來的資料訓練，單獨來看通常比較差（這裡平均約 84.5%，比單一決策樹的 85.6% 還低）。變好的是合起來之後的結果。
Bagging 和 Pasting 差在哪裡？在 scikit-learn 怎麼切換？

兩者都是用同一種演算法訓練很多個模型，每個模型用隨機抽出的訓練資料。Bagging 是取後放回，同一個模型可能抽到同一筆資料好幾次；Pasting 是取後不放回，同一個模型裡每筆資料最多出現一次。在 BaggingClassifier 裡，bootstrap=True（預設）是 bagging，bootstrap=False 是 pasting。

從 10 筆資料取後放回抽 10 次，某一筆特定的資料一次都沒被抽到的機率是多少？平均會有幾筆沒被抽到？

每一次沒抽到它的機率是 0.9，10 次都沒抽到是 。10 筆資料都一樣，所以平均有 筆沒被抽到，抽到的不同資料平均約 6.5 筆。

為什麼 bagging 的每個成員偏差比較高，合起來卻比單一模型好？

每個成員只看到抽出來的一部分資料，所以單獨來看比較差（偏差略高）。但每個成員的資料不同，犯的錯也不太一樣，平均之後錯誤會互相抵消，變異大幅降低。對決策樹這種變異很大的模型來說，降低的變異遠比增加的偏差多，所以整體變好。

BaggingClassifier(..., max_samples=1.0, bootstrap=False, max_features=0.5, bootstrap_features=True) 是哪一種方法？

Random Subspaces：每個模型都用全部的訓練資料（不放回、抽滿），只隨機抽一半的特徵。如果資料也抽（例如 max_samples=0.75, bootstrap=True），就是 Random Patches。
