房價跟誰最相關？

投影片 18

corr_matrix = housing.corr(numeric_only=True)

收入以 0.69 遙遙領先，跟第 2 篇專家說的一致，這也是當初用收入分層抽樣的原因。

緯度 −0.14：往北走房價略降。但別因此以為位置不重要，看前面的地圖就知道位置跟房價關係很強，只是不是線性的（兩個昂貴都會區，一南一北）。這正是上一節的教訓。

total_rooms 只有 0.14：它是「整個街區的房間總數」，大街區自然多，跟房子本身大不大沒什麼關係。這個問題留到最後一節解決。

收入 vs 房價：放大那一格

投影片 20

housing.plot(kind="scatter", x="median_income", y="median_house_value", alpha=0.1)

最有希望的屬性值得單獨放大來看（模擬資料，形狀依投影片重現）：

—目前這份資料的 r

相關性很強：明顯的上升趨勢，點也不算太分散。

50 萬的水平線：就是第 2 篇提到的房價上限（price cap），所有更貴的街區都被壓在這裡。

還有不明顯的水平線：大約在 45 萬、35 萬，可能還有 28 萬附近。我用原始資料數過：房價剛好是 45 萬的街區有 37 個、35 萬有 79 個，課本說的「28 萬附近」實際落在 27.5 萬（65 個），再往下還有 22.5 萬（92 個）。這些是資料蒐集時的怪癖（quirks）。課本建議：可以考慮移除這些街區，免得模型學到「房價喜歡停在這幾個數字」這種錯誤規律。

勾選「移除」後 r 會跟著改變，這也是為什麼清理資料要在算相關係數之後重新再算一次。

屬性組合：自己做出更好的特徵

投影片 21

total_rooms 相關性低，不是因為房間數不重要，而是因為它混進了「街區大小」這個干擾。看兩個假想的街區：

街區 A（大社區）

total_rooms 5,000
households 1,000
每戶 5.0 間

街區 B（小社區）

total_rooms 1,200
households 150
每戶 8.0 間

看總數，A 好像比較「大」；除以戶數後才發現 B 的房子大得多，而大房子通常比較貴。把總數除以適當的分母，就能拿掉規模的干擾：

housing["rooms_per_household"]      = housing["total_rooms"] / housing["households"]
housing["bedrooms_per_room"]        = housing["total_bedrooms"] / housing["total_rooms"]
housing["population_per_household"] = housing["population"] / housing["households"]

bedrooms_per_room：−0.26，比 total_bedrooms（0.05）和 total_rooms（0.14）都強得多。負號代表臥室佔房間比例越低，房子越貴：多出來的是客廳、書房、餐廳這類「非必要」空間。

rooms_per_household：0.15，比 total_rooms 略好，意思是房子越大越貴。

population_per_household：−0.02，看起來幾乎無關。但先別急著丟掉：第 6 篇會看到它在隨機森林裡是第 3 重要的特徵。原因是少數極端值把 Pearson r 拉向 0：有個街區平均每戶住了 1,243 人，顯然是宿舍或資料錯誤。只去掉最大的 1%，r 就變成 −0.28，用排名算的 Spearman 相關也有 −0.26。這又是 r 只量線性、而且怕極端值的例子，所以 r 只能拿來快速掃描，不能判定特徵沒用。

課本強調這一步不必做得很徹底：目的只是先抓到一些洞見，趕快做出第一個像樣的模型原型。之後分析模型的錯誤，還會再回來探索，這是一個反覆迭代的過程。

Python 實作：本篇完整流程

import matplotlib.pyplot as plt
from pandas.plotting import scatter_matrix

housing = strat_train_set.copy()                   # 只探索訓練集的副本

# 1) 地理散佈圖
housing.plot(kind="scatter", x="longitude", y="latitude", alpha=0.4,
             s=housing["population"]/100, label="population", figsize=(10,7),
             c="median_house_value", cmap=plt.get_cmap("jet"), colorbar=True)
plt.legend()

# 2) 相關係數（手算一次，跟 pandas 對答案）
x = housing["median_income"].to_numpy()
y = housing["median_house_value"].to_numpy()
u, v = x - x.mean(), y - y.mean()
r = (u @ v) / (np.linalg.norm(u) * np.linalg.norm(v))  # 就是 cos θ
print(r, np.corrcoef(x, y)[0, 1])                    # 兩者相同，約 0.69

corr_matrix = housing.corr(numeric_only=True)
print(corr_matrix["median_house_value"].sort_values(ascending=False))

# 3) 散佈矩陣與放大圖
attributes = ["median_house_value", "median_income", "total_rooms", "housing_median_age"]
scatter_matrix(housing[attributes], figsize=(12, 8))
housing.plot(kind="scatter", x="median_income", y="median_house_value", alpha=0.1)

# 4) 屬性組合，再算一次
housing["rooms_per_household"]      = housing["total_rooms"] / housing["households"]
housing["bedrooms_per_room"]        = housing["total_bedrooms"] / housing["total_rooms"]
housing["population_per_household"] = housing["population"] / housing["households"]
corr_matrix = housing.corr(numeric_only=True)
print(corr_matrix["median_house_value"].sort_values(ascending=False))

手算那段就是前面推導的第 2 步：先中心化，再算夾角餘弦。total_bedrooms 有缺值，pandas 算相關係數時，每一對欄位只用兩欄都有值的列來算，所以這裡還不用處理；到了第 4 篇真正要餵進模型時就必須補上。

常見陷阱與自我檢查

r ≈ 0 就判定「沒關係」r 只量線性關係。經度對房價的 r 只有 −0.05，但地圖上位置明明很關鍵。
把 r 當成斜率斜率 0.1 的完美直線 r=1，斜率 5 但很吵的資料 r 可能只有 0.3。r 量的是點有多貼近直線。
相關就是因果收入跟房價相關，不代表提高某區收入就能直接抬高房價，也可能是反過來或有共同原因。
在整份資料上探索要在訓練集的副本上做，測試集維持鎖著。
直接呼叫 housing.corr()新版 pandas 遇到文字欄會報錯，記得 numeric_only=True。
兩個屬性的 r = 0，它們一定獨立嗎？

不一定。獨立 ⇒ r = 0，但 r = 0 只代表沒有線性關係。反例：X 在 {−1, 0, 1} 等機率，Y = X²，r = 0 但 Y 完全由 X 決定。

為什麼 bedrooms_per_room 比 total_bedrooms 有用得多？

總數會隨街區規模變大，混進了「街區有多大」的資訊；比例則描述「房子長什麼樣」，跟房價的關係更直接。

散佈矩陣的對角線為什麼是直方圖？

對角線是屬性對自己畫散佈圖，一定是一條 45 度直線，沒有資訊。pandas 預設改畫該屬性的直方圖（也可以設定成 KDE）。

收入 vs 房價圖上的水平線，為什麼可能要刪？

它們不是真實的市場規律，而是資料蒐集的怪癖（50 萬是上限，45 萬、35 萬原因不明）。留著的話，模型可能學會把預測值往這些數字靠攏。
