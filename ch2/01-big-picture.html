任務：預測加州每個街區的房價中位數

投影片 3

資料來自 1990 年加州人口普查，每一列是一個街區（district），記錄人口、收入中位數、房屋數量等資訊，以及這個街區的房價中位數。模型要學會：給定其他所有欄位，猜出房價中位數。

為什麼要先問這個？因為下游是「投資分析系統」，它要的是一個房價數字，而且錯估會直接影響要不要花錢。這告訴你三件事：

輸出要是數值，不是「貴／便宜」的分類；誤差要用「差了多少錢」來衡量；大錯（差 30 萬）比小錯（差 1 萬）嚴重得多，這會影響後面選 RMSE 還是 MAE。

反過來想：如果下游系統只需要「低、中、高」三個價位等級，那整個問題就變成分類，模型、指標、資料標記方式全都不一樣。框錯問題，後面做得再好都是白工。

RMSE 與 MAE：兩種匯總誤差的方式

投影片 5–6

RMSE 的計算順序是「先平方、再平均、再開根號」。平方讓大誤差被放大，開根號把單位從「元²」拉回「元」，所以 RMSE 可以直接讀成「大約差多少錢」。MAE 則是直接取絕對值平均，每一塊錢的誤差一視同仁。

投影片特別標註：這不是 loss function。

Loss（cost）function 是訓練時演算法在最小化的東西，要好微分、好優化，例如線性迴歸最小化 RSS，決策樹用不純度（impurity）決定怎麼切。Performance measure 是你拿來評分、跟老闆報告的標準，要貼近商業需求。兩者可以相關（，所以壓低 RSS 等於壓低訓練集的 RMSE），但角色不同。分類問題最明顯：訓練用 cross-entropy，報告用 accuracy。

推導：為什麼 RMSE 一定 ≥ MAE？

令 為第 區的誤差大小，用 表示平均。

第 2 步：用「變異數 ≥ 0」

第 3 步：兩邊都非負，開根號

這個推導順便給了一個很實用的解讀：RMSE 和 MAE 的差距，正好反映誤差大小的變異數。所有街區錯得一樣多時兩者相等；錯誤越集中在少數幾區，差距越大。上面的實驗裡，把滑桿拉到底時兩者差距暴增，就是這個原因。

二維時 的形狀

k 越大，最大的那個誤差越「一手遮天」：佔比長條幾乎被第 1 區（誤差約 7.6 萬）佔滿，平均值也一路往最大誤差靠。這正是投影片那句話：範數次方越高，越在意大的值、越忽略小的值。

右邊的形狀你可能眼熟：k=1 是菱形、k=2 是圓形，就是 Lasso（L1）和 Ridge（L2）正則化的限制區域。同一套範數，一邊拿來量誤差，一邊拿來量參數大小。

那到底選哪個？

如果誤差分布像鐘形曲線，離群值「指數級地罕見」，RMSE 表現很好，也是一般預設。因為真的出現大錯時，你本來就希望被重罰（例如投資判斷錯 30 萬）。

如果資料裡本來就有不少離群街區（資料錯誤、特殊豪宅區），用 RMSE 會讓評分被這幾個點綁架，這時 MAE 更能反映「一般情況下」的準確度。

Python 實作：自己算，再跟 sklearn 對答案

用實驗裡那 5 個街區，把公式直接翻成 NumPy，再用 Scikit-Learn 的函式驗證：

import numpy as np
from sklearn.metrics import mean_squared_error, mean_absolute_error

y_pred = np.array([210644.6045, 317768.8069, 210956.4333, 59218.9888, 189747.5584])
y_true = np.array([286600, 340600, 196900, 46300, 254500])
e = y_pred - y_true                     # 每一區的誤差向量 v
m = len(e)

# 1) 照公式手刻
rmse = np.sqrt(np.mean(e ** 2))         # 46578.64
mae  = np.mean(np.abs(e))               # 38102.89

# 2) 用範數寫：MAE = ||v||₁ / m，RMSE = ||v||₂ / √m
mae_n  = np.linalg.norm(e, ord=1) / m
rmse_n = np.linalg.norm(e, ord=2) / np.sqrt(m)

# 3) sklearn 版本
rmse_sk = np.sqrt(mean_squared_error(y_true, y_pred))
mae_sk  = mean_absolute_error(y_true, y_pred)

# 驗證 RMSE² − MAE² = Var(|e|)
print(rmse**2 - mae**2, np.var(np.abs(e)))   # 兩個數字相同

三種寫法會得到同樣的 RMSE ≈ 46,579、MAE ≈ 38,103。注意 mean_squared_error 回傳的是 MSE，要自己開根號；Scikit-Learn 1.4 以後另外提供了 root_mean_squared_error 可以直接用。

常見陷阱與自我檢查

把 RMSE 當成 loss function投影片特別註明它是 performance measure。訓練時最小化的東西由演算法決定，評分標準由商業需求決定。
以為 univariate 是「只有一個特徵」univariate／multivariate 講的是輸出幾個值；multiple 才是講輸入有多個特徵。
忘記 sklearn 的 MSE 還要開根號直接拿 mean_squared_error 的結果報告，單位會變成「元²」，數字大到沒有意義。
以為 MAE 一定比較好，因為它「比較小」RMSE ≥ MAE 是數學必然，不代表模型比較差。比較模型時要用同一個指標。
模型 A：RMSE 5.0 萬、MAE 4.8 萬。模型 B：RMSE 8.0 萬、MAE 4.0 萬。哪個有少數大錯？

模型 B。它平常更準（MAE 較低），但 RMSE 是 MAE 的兩倍，代表有少數街區錯得非常離譜，平方後把 RMSE 拉高。模型 A 的兩個數字很接近，代表誤差大小很平均。要選哪個，得回到商業目標：投資系統能不能承受偶爾的大錯。

「用多個特徵預測一個值」為什麼同時叫 multiple 又叫 univariate？

兩個詞講的是不同方向。Multiple regression 指輸入有多個特徵；univariate regression 指輸出只有一個值。同時預測房價和人口，就變成 multivariate regression。

線性迴歸訓練時最小化 RSS，評估時用 RMSE，為什麼不會衝突？

因為 ，在同一份資料上，RSS 越小 RMSE 就越小，兩者排名一致。挑 RSS 當 loss 是因為它好微分、有公式解；報告用 RMSE 是因為單位是「元」，人看得懂。
