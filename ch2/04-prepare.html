資料清理：缺值怎麼辦？

投影片 23

第 2 篇看到 total_bedrooms 有 207 個街區沒填。大部分演算法遇到 NaN 會直接報錯，所以一定要處理。投影片列了三個選項：

housing.dropna(subset=["total_bedrooms"])     # 選項 1：刪掉有缺值的街區
housing.drop("total_bedrooms", axis=1)        # 選項 2：整欄刪掉
median = housing["total_bedrooms"].median()   # 選項 3：補一個值
housing["total_bedrooms"].fillna(median, inplace=True)

下面 8 個街區裡有 3 個缺了臥室數，試試三個選項的效果：

選項 1 刪列：最簡單，但會丟掉這些街區的其他 8 個欄位資訊。更大的問題在上線後：新進來的街區如果也缺臥室數，模型根本無法預測它。

選項 2 刪欄：整個屬性都不要了。只有在缺值很多、或這個屬性本來就沒用時才划算。第 3 篇做出來的 bedrooms_per_room（r = −0.26）就依賴它，刪掉很可惜。

選項 3 補值：保留所有列和欄，是課本採用的做法。但要記住兩件事：中位數要用訓練集算，而且要存起來，之後處理測試集和新資料時用同一個數字。

推導：為什麼補中位數，而不是平均？

補值其實是在問：「如果只能用一個常數 代表所有街區，選哪個最好？」答案取決於你怎麼量誤差，而這正好接回第 1 篇的 RMSE 與 MAE。

第 1 步：用平方誤差（RMSE 的觀點）

第 2 步：用絕對誤差（MAE 的觀點）

第 3 步：令它等於 0

比 小的個數要等於比 大的個數，這正是中位數的定義。

所以平均數是「平方誤差最小」的代表值，中位數是「絕對誤差最小」的代表值。平方會放大離群值，所以平均數會被少數極端值拖走；中位數只看排序，極端值再怎麼大，影響都跟一個普通的大值一樣。第 2 篇看到 total_bedrooms 是長尾分布，這時中位數是更穩健的選擇。

用 SimpleImputer 補值，順便認識 Scikit-Learn 的設計

from sklearn.impute import SimpleImputer

imputer = SimpleImputer(strategy="median")
housing_num = housing.drop("ocean_proximity", axis=1)   # 中位數只能對數值欄算

注意 fit 會對所有數值欄算中位數，不只是 total_bedrooms。現在只有它有缺值，但上線後別的欄位也可能缺，全算好比較保險。結果存在 imputer.statistics_，課本中約為：

imputer.statistics_
# array([-118.51, 34.26, 29., 2119.5, 433., 1164., 408., 3.5409])

這段程式碼展示了 Scikit-Learn 最核心的設計，後面每個工具都遵守同一套規則：

角色方法做什麼例子
估計器 estimatorfit(X)從資料學參數所有類別
轉換器 transformertransform(X)用學到的參數改資料SimpleImputer、StandardScaler
預測器 predictorpredict(X)用學到的參數預測LinearRegression

超參數 vs 學到的參數：建構時傳入的（strategy="median"）是超參數，由你決定；fit 之後才有的（statistics_）是學到的參數，名稱一律以底線結尾。

fit_transform：等於先 fit 再 transform，通常有優化過比較快。只能用在訓練集上。

黃金規則：只在訓練集上 fit，測試集和新資料只能 transform。如果在測試集上重新 fit，就等於偷看了測試集的中位數，這叫資料洩漏（data leakage），跟第 2 篇的 data snooping 是同一類問題。

Ordinal 的問題：它發明了不存在的順序

模型會把 0、1、2、3、4 當成數字，以為 1 和 2 比 1 和 4「接近」。對於「差、普通、好、很好」這種本來就有順序的類別沒問題，但離海距離的這 5 類沒有這種關係。點兩個類別比較看看：

One-hot 距離—

One-hot 讓每個類別各佔一個維度，任兩類的距離都是 ，內積都是 0（正交），沒有誰比較近。代價就是投影片紅字寫的：維度變多了，1 欄變成 5 欄。類別有幾千種（例如郵遞區號、職業）時會爆炸，這時可以改用數值特徵代替（例如用「到海的距離」代替 ocean_proximity），或用神經網路學 embedding。

為什麼輸出是稀疏矩陣？

投影片顯示 <16512x5 sparse matrix ... with 16512 stored elements>。每一列只有 1 個 1，其餘 4 個是 0，如果全部存起來是 82,560 個數字，大部分是 0。稀疏矩陣（CSR 格式）只記錄非零值和它們的位置，所以剛好存 16,512 個。類別越多，省下的空間越可觀。要看一般陣列就呼叫 .toarray()，或建構時設 sparse_output=False。

為什麼不用 pd.get_dummies？它也能做 one-hot，但不會「記住」訓練時看過哪些類別。如果測試集剛好沒有 ISLAND（全部只有 5 筆，很可能發生），get_dummies 就只會產生 4 欄，欄位對不上。OneHotEncoder 會把類別存在 categories_，之後 transform 永遠輸出同樣的 5 欄；遇到沒看過的類別，可以設 handle_unknown="ignore" 輸出全 0。

自訂轉換器：把屬性組合包起來

投影片 22、26

第 3 篇手動加了三個組合特徵。要把它放進流水線，就得寫成 Scikit-Learn 認得的轉換器。只要實作 fit（回傳 self）和 transform 就行：

from sklearn.base import BaseEstimator, TransformerMixin

rooms_ix, bedrooms_ix, population_ix, households_ix = 3, 4, 5, 6   # 在 housing_num 裡的欄位位置

class CombinedAttributesAdder(BaseEstimator, TransformerMixin):
    def __init__(self, add_bedrooms_per_room=True):    # 不要用 *args、**kwargs
        self.add_bedrooms_per_room = add_bedrooms_per_room
    def fit(self, X, y=None):
        return self                                     # 沒有東西要學
    def transform(self, X):
        rooms_per_household = X[:, rooms_ix] / X[:, households_ix]
        population_per_household = X[:, population_ix] / X[:, households_ix]
        if self.add_bedrooms_per_room:
            bedrooms_per_room = X[:, bedrooms_ix] / X[:, rooms_ix]
            return np.c_[X, rooms_per_household, population_per_household, bedrooms_per_room]
        return np.c_[X, rooms_per_household, population_per_household]

TransformerMixin：自動送你一個 fit_transform。

BaseEstimator：自動送你 get_params() 和 set_params()，前提是 __init__ 只用具名參數。第 6 篇的自動調參就是靠這兩個方法去改超參數。

add_bedrooms_per_room：把「要不要加這個特徵」變成超參數。第 3 篇只看了相關係數，到底有沒有幫助，交給第 6 篇實際訓練後比較。

特徵縮放

投影片 25

收入是個位數，房間總數動輒好幾千。除了少數例外（例如決策樹），大部分演算法在各屬性尺度差很多時表現都不好。投影片介紹兩種統一尺度的方法：

Min-max scaling（normalization）：MinMaxScaler

減掉最小值、除以全距，結果落在 0 到 1。最小值變 0，最大值變 1，中間線性對應。如果需要別的範圍，可以用 feature_range 參數調整。

Standardization（標準化）：StandardScaler

減掉平均再除以標準差。投影片說結果「平均為 0、變異數為 1」，驗證一下，利用期望值的線性：

注意標準化沒有把分布變成常態分布，形狀完全不變，長尾還是長尾，只是平移加縮放。

把滑桿拉到 40，比較兩個「縮成原本的幾 %」。Min-max 的輸出只由最小和最大兩個值決定，一個離群值就能把其他 999 個點擠到左邊一小段。標準化用的平均和標準差是 1,000 個點一起算的，離群值還是會把 撐大一些，所以其他點也會縮，但幅度小得多。這就是課本說的：標準化受離群值的影響小得多（不是完全不受影響）。資料越多，單一離群值對 的影響越小；如果離群值很多，可以改用以中位數和四分位距縮放的 RobustScaler。代價是標準化的輸出沒有固定範圍，有些演算法（例如某些神經網路）偏好 0～1 的輸入，這時 min-max 比較合適。

跟補值一樣：縮放器只能在訓練集上 fit，測試集和新資料用同一組 或 去 transform。所以測試集的 min-max 結果可能超出 0～1，這是正常的。

Pipeline：把所有步驟串起來

投影片 26

現在數值欄要依序做三件事（補值、加組合特徵、標準化），類別欄要做 one-hot。先用 Pipeline 把數值欄的三步串起來：

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

num_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy="median")),     # ①
    ('attribs_adder', CombinedAttributesAdder()),      # ②
    ('std_scaler', StandardScaler()),                   # ③
])
housing_num_tr = num_pipeline.fit_transform(housing_num)

規則：Pipeline 接收 (名稱, 估計器) 的清單。除了最後一個，其他都必須是轉換器（要有 fit_transform）。

執行方式：呼叫 num_pipeline.fit_transform(X) 時，它依序對每一步呼叫 fit_transform，把輸出當成下一步的輸入。Pipeline 對外提供的方法跟最後一步一樣：最後一步是轉換器就能 transform，是預測器就能 predict。

順序很重要：① 一定要在 ② 前面。② 算 bedrooms_per_room 時要用到臥室數，NaN 參與運算，結果還是 NaN。

名稱：可以自己取，但不能重複，也不能含雙底線 __。第 6 篇調參時會用 num__imputer__strategy 這種寫法指定某一步的超參數，雙底線就是分隔符號。

接著用 ColumnTransformer 把數值欄和類別欄分流處理，再合併：

from sklearn.compose import ColumnTransformer

num_attribs = list(housing_num)          # 8 個數值欄的名稱
cat_attribs = ["ocean_proximity"]

full_pipeline = ColumnTransformer([
    ("num", num_pipeline, num_attribs),
    ("cat", OneHotEncoder(), cat_attribs),              # ④
])
housing_prepared = full_pipeline.fit_transform(housing)

ColumnTransformer 的每一組是（名稱, 轉換器, 欄位名稱清單）。它把指定的欄位交給對應的轉換器，再把所有輸出左右拼接。一個小細節：OneHotEncoder 輸出稀疏矩陣，但合併後每列 16 格裡有 12 格非零，密度 0.75 高於預設門檻 0.3，所以最後回傳的是一般的密集陣列。

Python 實作：本篇完整流程

import numpy as np
import pandas as pd
from sklearn.base import BaseEstimator, TransformerMixin
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

# 0) 從第 2 篇接過來：只處理訓練集的特徵
housing = strat_train_set.drop("median_house_value", axis=1)
housing_labels = strat_train_set["median_house_value"].copy()
housing_num = housing.drop("ocean_proximity", axis=1)

# 1) 自訂轉換器
rooms_ix, bedrooms_ix, population_ix, households_ix = 3, 4, 5, 6

class CombinedAttributesAdder(BaseEstimator, TransformerMixin):
    def __init__(self, add_bedrooms_per_room=True):
        self.add_bedrooms_per_room = add_bedrooms_per_room
    def fit(self, X, y=None):
        return self
    def transform(self, X):
        rph = X[:, rooms_ix] / X[:, households_ix]
        pph = X[:, population_ix] / X[:, households_ix]
        if self.add_bedrooms_per_room:
            bpr = X[:, bedrooms_ix] / X[:, rooms_ix]
            return np.c_[X, rph, pph, bpr]
        return np.c_[X, rph, pph]

# 2) 數值流水線 + 整體流水線
num_pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("attribs_adder", CombinedAttributesAdder()),
    ("std_scaler", StandardScaler()),
])
full_pipeline = ColumnTransformer([
    ("num", num_pipeline, list(housing_num)),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["ocean_proximity"]),
])

# 3) 只在訓練集上 fit
housing_prepared = full_pipeline.fit_transform(housing)
print(housing_prepared.shape)                               # (16512, 16)

# 4) 驗證：數值部分平均 ≈ 0、標準差 ≈ 1
print(housing_prepared[:, :11].mean(axis=0).round(3))
print(housing_prepared[:, :11].std(axis=0).round(3))

# 5) 看學到的參數
print(full_pipeline.named_transformers_["num"]["imputer"].statistics_)
print(full_pipeline.named_transformers_["cat"].categories_)

第 4 步是很好的自我檢查：如果某欄平均不是 0，代表那一欄沒進到標準化那一步。Scikit-Learn 1.2 以後還有 set_output(transform="pandas") 可以讓輸出變成帶欄名的 DataFrame，但流水線裡每一步都要能回報欄名；這裡的 CombinedAttributesAdder 沒有實作 get_feature_names_out，直接加會報錯，要先補上那個方法。

常見陷阱與自我檢查

在整份資料或測試集上 fit補值的中位數、縮放的平均與標準差都算是「學到的參數」，只能來自訓練集，否則就是資料洩漏。
對沒有順序的類別用 OrdinalEncoder模型會把 0～4 當成有大小的數字，學到不存在的順序。
用 get_dummies 處理測試集測試集少了某個類別時欄數會對不上。用 OneHotEncoder，並考慮 handle_unknown="ignore"。
以為標準化會變成常態分布它只平移和縮放，分布形狀不變；要處理長尾得另外取 log 之類的轉換。
Pipeline 的步驟順序寫反組合特徵放在補值前面，拿 NaN 去算，新特徵也會變成 NaN。
舊版參數名稱OneHotEncoder 的 sparse 在 1.2 版改名為 sparse_output，1.4 版移除了舊名稱。
為什麼 SimpleImputer 要對所有數值欄都 fit，不是只對 total_bedrooms？

現在只有它有缺值，但上線後的新資料可能在任何一欄缺值。全部先算好中位數，transform 時哪一欄缺就補哪一欄。

測試集經過 MinMaxScaler 後出現 1.08，是不是程式寫錯了？

不是。縮放器用的是訓練集的最小、最大值，測試集只要有值超過訓練集的最大值，就會大於 1。反過來，如果在測試集上重新 fit 讓它剛好落在 0～1，才是錯的。

為什麼決策樹不太需要特徵縮放？

決策樹每次只看單一特徵，問「這個值有沒有大於某個門檻」。對單一特徵做單調的平移縮放，排序不變，能切出的分割也完全一樣。

housing_prepared 為什麼是 16 欄？

8 個原始數值欄，加上 CombinedAttributesAdder 的 3 個組合特徵，共 11 欄；ocean_proximity 做 one-hot 變 5 欄。11 + 5 = 16。

補值前後，total_bedrooms 的變異數會怎麼變？

會變小。補進去的值全部等於中位數，這些點沒有離散程度，拉低了整體變異數，也會在直方圖上形成一根尖峰。如果缺值本身可能帶有資訊，可以設 add_indicator=True，多加一欄標記「這筆原本是缺值」。
