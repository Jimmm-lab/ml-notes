68,628 美元是好是壞？課本提到大多數街區的房價中位數落在 12 萬到 26.5 萬之間（我用原始資料查過，這正是第 25 到第 75 百分位，也就是中間一半的街區），平均差將近 7 萬，實在不怎麼樣。

而且這是在「看過的」訓練集上。連考古題都考不好，代表模型欠擬合（underfitting）：特徵提供的資訊不夠，或是模型不夠強。

三條路：換更強大的模型、餵更好的特徵（例如取 log 後的人口），或減少對模型的限制。這個模型沒有正則化，第三條走不通，所以先試更強的模型。

第二個模型：決策樹，RMSE 竟然是 0

投影片 28

from sklearn.tree import DecisionTreeRegressor

tree_reg = DecisionTreeRegressor()
tree_reg.fit(housing_prepared, housing_labels)
housing_predictions = tree_reg.predict(housing_prepared)
tree_rmse = np.sqrt(mean_squared_error(housing_labels, housing_predictions))
tree_rmse   # 0.0

完全沒有誤差？投影片旁邊放了一個驚嘆號，並寫著：更可能的是模型嚴重過擬合了。決策樹能找出複雜的非線性關係，但不加限制的話，它會一路切到每片葉子只剩一筆資料，等於把 16,512 個答案背下來。

要確認是不是過擬合，得看模型在沒看過的資料上表現如何。可是測試集還不能碰，第 2 篇說過，要等到最後確定模型才能打開。解法是交叉驗證，下面會講。

投影片的補充：決策樹用的 loss function 不是 RSS，而是評估每次切分後子節點的「純度／不純度」（第 6 章）。迴歸樹的不純度就是節點內的 MSE。

推導：迴歸樹為什麼能把訓練誤差壓到 0？

第 1 步：每片葉子預測什麼？

一片葉子 裡的所有樣本都給同一個預測值 。要讓葉子內的平方誤差最小，跟第 4 篇補值的推導一模一樣：

所以葉子預測的是葉內房價的平均，葉子的誤差就是葉內的變異：。

第 2 步：怎麼選切分？

Scikit-Learn 的決策樹用的是 CART 演算法（Classification And Regression Tree），每次都把一個節點切成左右兩半。它在每個節點試遍所有特徵 和門檻 ，挑出讓兩個子節點加權 MSE 最小的那一刀：

第 3 步：一直切下去

只要某片葉子裡的房價還不完全一樣，就還能再切一刀讓 變小。不設停止條件時，會切到每片葉子內所有 都相同（通常就是只剩一筆），此時 ，每一項都是 0：

唯一的例外是兩筆特徵完全相同、房價卻不同的資料，樹無法把它們分開。課本的結果剛好是 0.0，代表沒有這種情形。

把深度拉到最大（13，等同不設限），訓練 RMSE 變成 0，預測線變成穿過每個實心點的鋸齒，驗證 RMSE 反而變大。這就是房價決策樹 0.0 的真相。線性迴歸則是另一個極端：訓練和驗證都一樣差，一條直線根本畫不出這個形狀。下方曲線裡，驗證誤差在深度 4 最低，那才是好的複雜度。

用交叉驗證打分數

投影片 29–30

最直覺的做法是再從訓練集切出一塊驗證集。更好的做法是 K-fold 交叉驗證：把訓練集切一次成 10 份（fold），接著輪流拿其中 1 份驗證、其他 9 份訓練，總共訓練並評估 10 次，得到 10 個分數。每筆資料剛好被拿來驗證一次。

from sklearn.model_selection import cross_val_score

scores = cross_val_score(tree_reg, housing_prepared, housing_labels,
                         scoring="neg_mean_squared_error", cv=10)
tree_rmse_scores = np.sqrt(-scores)

def display_scores(scores):
    print("Scores:", scores)
    print("Mean:", scores.mean())
    print("Standard deviation:", scores.std())
拿來訓練的 9 份拿來驗證的 1 份
目前平均 RMSE—
目前標準差—

右邊的分數是投影片 29 上決策樹的真實結果：平均 71,408、標準差 2,439。跟訓練集的 0.0 相比天差地遠，而且比線性迴歸還差。交叉驗證的另一個好處是能看到分數的波動（± 2,439），知道這個估計有多準。代價是要訓練 10 次。

為什麼要用「負的」MSE？Scikit-Learn 的交叉驗證預期的是效用函數（越大越好），而 MSE 是成本函數（越小越好）。所以它回傳 −MSE，程式裡才要先加負號再開根號：np.sqrt(-scores)。新版也可以直接用 scoring="neg_root_mean_squared_error"，再取負號就是 RMSE。

切法有沒有洗牌？迴歸模型傳 cv=10 時，預設用不洗牌的 KFold，照資料順序切。這裡沒問題，因為第 2 篇的分層抽樣已經把順序打亂了；如果資料是依某個欄位排序過的，就要自己傳 KFold(10, shuffle=True, random_state=42)。

標準差用哪個公式？NumPy 的 .std() 預設除以 （ddof=0），投影片上的 2,439 就是這樣算的。除以 會得到 2,571。

隨機森林：很多棵樹一起投票

from sklearn.ensemble import RandomForestRegressor

# forest_rmse（訓練集）= 18603.5

隨機森林訓練很多棵決策樹，每棵樹用隨機抽樣（可重複）的資料，而且每次切分只從隨機挑選的一部分特徵裡找最好的一刀，最後把所有樹的預測平均。這種「組合多個模型」的做法叫集成學習（Ensemble Learning），是第 7 章的主題。

單棵樹會背答案，為什麼一群會背答案的樹平均起來就變好了？關鍵在變異數：

推導：平均 n 棵樹，變異數降多少？

設每棵樹對某個街區的預測 變異數都是 ，任兩棵的相關係數都是 （第 3 篇的 Pearson 相關），所以 。

第 1 步：展開平均的變異數

第 2 步：代入，對角線有 項，非對角線有 項

第 3 步：整理

第二項隨樹的數量 變多而消失，第一項 則是降不下去的底線。所以隨機森林要刻意讓樹彼此不同（降低 ）：每棵用不同的資料樣本、每次切分只看部分特徵，就是為了這個。單棵樹的偏差不變，變異數大幅下降，驗證誤差就跟著降。

一個容易忽略的細節：Scikit-Learn 的 RandomForestRegressor 預設 max_features=1.0，也就是每次切分其實會看全部特徵，樹與樹的差異只來自 bootstrap 抽樣（分類用的 RandomForestClassifier 預設才只看 √特徵數 個）。所以上面投影片 31 的森林，ρ 還不夠低。第 6 篇的 grid search 把 max_features 調小後，用更少的樹就拿到更好的分數，正是這個推導的應用。

平均後的變異數（單棵 = 1）—
降不下去的底線 ρ—

把 ρ 拉到 1，無論種多少棵樹，變異數都不會降：大家的錯都一樣，平均也沒用。把 ρ 拉低，曲線會很快往下掉。

多試幾種模型，挑出候選名單

投影片 31

投影片最後一點：還可以試支援向量機（不同的核函數）、神經網路等等。這一步的目標是快速試過幾種不同類型的模型，挑出 2 到 5 個有潛力的候選，先不要花太多時間調超參數，那是第 6 篇的事。

每試完一個模型，就把它存下來，包含超參數、訓練好的參數、交叉驗證分數和預測結果，之後比較各模型的分數和錯誤類型會方便很多：

Python 實作：本篇完整流程

import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error
from sklearn.model_selection import cross_val_score
from sklearn.tree import DecisionTreeRegressor

# housing_prepared, housing_labels：第 4 篇的輸出
models = {
    "Linear":  LinearRegression(),
    "Tree":    DecisionTreeRegressor(random_state=42),
    "Forest":  RandomForestRegressor(random_state=42),
}

for name, model in models.items():
    # 1) 訓練集分數：模型「看過」的資料
    model.fit(housing_prepared, housing_labels)
    pred = model.predict(housing_prepared)
    train_rmse = np.sqrt(mean_squared_error(housing_labels, pred))

    # 2) 10-fold 交叉驗證：模型沒看過的資料
    scores = cross_val_score(model, housing_prepared, housing_labels,
                             scoring="neg_mean_squared_error", cv=10)
    cv_rmse = np.sqrt(-scores)

    gap = cv_rmse.mean() - train_rmse
    print(f"{name:7s} train={train_rmse:9.0f}  cv={cv_rmse.mean():9.0f} "
          f"± {cv_rmse.std():6.0f}  gap={gap:8.0f}")

加上 random_state=42 讓樹和森林每次結果一樣，數字會跟投影片接近但不一定完全相同（投影片沒固定種子，版本也可能不同）。我用原始資料在 Scikit-Learn 1.8 上實際跑過：線性迴歸訓練 68,628／驗證 69,104，決策樹 0／71,630，隨機森林 18,651／50,436，跟投影片的結論完全一致。隨機森林訓練 10 次要跑一陣子，是正常的。

常見陷阱與自我檢查

用訓練集分數選模型決策樹的 0.0 會讓它看起來最好，實際上它在沒看過的資料上最差。
用測試集來挑模型測試集要留到最後。挑模型、調參數都用交叉驗證。
忘記 cross_val_score 回傳負數直接 np.sqrt(scores) 會得到 NaN，要先加負號。
在 some_data 上重新 fit pipeline新資料只能 full_pipeline.transform，否則縮放參數會變成用這 5 筆算的。
以為隨機森林不會過擬合訓練 18,604 vs 驗證 50,182，差距還很大。
訓練 RMSE 70,000、驗證 RMSE 71,000，下一步該做什麼？

兩者都高且接近，是欠擬合。該換更強的模型、做更好的特徵，或放寬正則化。收集更多資料在這種情況下幫助不大。

訓練 RMSE 5,000、驗證 RMSE 60,000，下一步該做什麼？

差距很大，是過擬合。可以簡化模型（例如限制樹的深度）、加正則化，或收集更多訓練資料。

cv=10 代表資料被隨機切了 10 次嗎？

不是。資料只切一次成 10 份，然後輪流讓每一份當一次驗證集，所以總共訓練 10 次。

如果隨機森林裡每棵樹都用全部資料、全部特徵，會怎樣？

每棵樹會長得幾乎一樣，相關係數 ρ 接近 1。依推導，平均後的變異數幾乎等於單棵樹，森林就失去意義了。第 6 篇的 grid search 裡，bootstrap=False 的組合就是往這個方向走，分數也確實比較差。
