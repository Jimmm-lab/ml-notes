第一眼：info() 告訴你的三件事

投影片 7

import pandas as pd
housing = pd.read_csv("housing.csv")
housing.info()

info() 會列出每一欄的非空值數量和型別。整份資料有 20,640 列、10 欄，逐欄看下來有三件事值得注意：

欄位非空值型別說明
longitude／latitude20,640float64經緯度
housing_median_age20,640float64屋齡中位數
total_rooms20,640float64整區房間總數
total_bedrooms20,433float64少了 207 筆
population／households20,640float64人口、戶數
median_income20,640float64收入中位數
median_house_value20,640float64標籤（要預測的答案）
ocean_proximity20,640object文字，不是數字

缺值：total_bedrooms 只有 20,433 筆，有 207 個街區沒填。大部分 ML 演算法遇到缺值會直接報錯，第 4 篇會處理。

文字欄：ocean_proximity 是 object 型別，內容是 NEAR BAY、INLAND 這類文字，是類別屬性，之後要編碼成數字（就是你問過的 one-hot）。

「總數」而非「每戶」：total_rooms 是整個街區加總，大街區自然房間多，單看它意義不大。第 3 篇會把它除以戶數變成「每戶房間數」。

類別欄：數一數每類有幾筆

housing["ocean_proximity"].value_counts()

ISLAND 只有 5 筆。記住這個數字，後面講分層抽樣時會回來用到它：一個類別太小，就很難保證它在訓練集和測試集裡都有代表。

直方圖：這份資料被動過手腳

投影片 9–10

housing.hist(bins=50, figsize=(20,15))

對每個數值欄畫直方圖，是找出資料「怪地方」最快的方法。下面依投影片觀察的形狀重現三個代表性的欄位（模擬資料，形狀與原圖一致）：

被縮放（scaled）：median_income 的單位不是美元，而是「萬美元」，3 代表約 $30,000。投影片提到大部分落在 1.5～6 之間。

被截斷（capped）：收入被夾在 0.5～15 之間；屋齡上限 52、房價上限 500,001。直方圖最右邊那根突然冒高的柱子，就是所有超過上限的值被硬塞進同一格。

尺度差很多：收入是個位數，人口是幾千，房價是幾十萬。多數演算法不喜歡這樣，第 4 篇做特徵縮放。

長尾（tail-heavy）：人口、房間數的分布往右拖很長，演算法比較難抓到規律。常見做法是取 log 讓它變回鐘形，勾選上面的 log 選項就看得到差別。

房價被截斷為什麼特別嚴重？全部 20,640 個街區裡，有 965 個（約 4.7%）的房價剛好是 500,001。因為它是標籤。模型會學到「房價最高就是 500,001」，永遠不會預測出 60 萬。如果下游投資系統需要分辨 50 萬以上的差異，有兩條路：幫這些街區找回真實房價，或者把它們從訓練集和測試集都移除（反正模型也預測不準）。

切出測試集：現在就鎖起來，別再看

投影片 11

才看了幾張圖就要切？對，而且越早越好。原因叫做 data snooping bias（資料窺探偏差）：你的大腦本身也是一個很會找規律的模型。如果你先把整份資料看透，很可能不自覺地挑出一個「剛好在測試集上看起來很有效」的模型或特徵，最後在測試集得到過度樂觀的分數，上線後卻表現不如預期。

做法很簡單：隨機挑 20%（資料量很大時可以更少），放到一邊，直到專案最後才打開。

但「隨機」有個陷阱：每次跑都不一樣

如果每次執行程式都重新隨機切，這次在測試集的資料，下次可能跑到訓練集。跑個幾十次，整份資料就都被模型（和你）看過了。固定 random_state 能讓同一份資料每次切得一樣，可是資料一更新（多了新街區），洗牌結果就全變了。

比較穩的做法是：用每筆資料的 ID 決定它去哪。把 ID 算一個雜湊值（hash），雜湊值落在前 20% 的就放測試集。同一個 ID 永遠算出同一個雜湊值，所以不管資料怎麼增加，舊資料都待在原本的位置。

from zlib import crc32

def is_id_in_test_set(identifier, test_ratio):
    return crc32(np.int64(identifier)) & 0xffffffff < test_ratio * 2**32

crc32 會把 ID 打散成 0 到 232−1 之間近乎均勻分布的整數，所以「小於 0.2×232」的機率就是 20%。它只看 ID 本身，不看其他資料，這是穩定的關鍵。房價資料沒有 ID 欄，課本用列號代替：

def split_train_test_by_id(data, test_ratio, id_column):
    ids = data[id_column]
    in_test_set = ids.apply(lambda id_: is_id_in_test_set(id_, test_ratio))
    return data.loc[~in_test_set], data.loc[in_test_set]

housing_with_id = housing.reset_index()   # 多出一欄 "index"，就是列號
train_set, test_set = split_train_test_by_id(housing_with_id, 0.2, "index")

每個方格是一筆資料，黃色是測試集。按按鈕模擬資料更新，被紅框圈起來的是「換了陣營」的舊資料。

方法 A：每次重新隨機切

方法 B：用列號當 ID，做雜湊

試試兩個按鈕：新增資料時，方法 B 的舊資料一格都沒動；但如果刪掉一筆，後面所有資料的列號都往前移一位，ID 變了，雜湊結果跟著亂掉。這正是投影片最後一點：房價資料沒有 ID 欄，拿列號當 ID 的話，新資料只能加在最後面，而且永遠不能刪資料。更穩的做法是用不會變的欄位組出 ID，例如用經緯度 longitude * 1000 + latitude。

分層抽樣：讓測試集「長得像」全體

投影片 9、12

純隨機抽樣在資料量很大時沒問題，但資料量不夠大時，可能運氣不好抽歪，這叫 sampling bias（抽樣偏差）。課本舉民調的例子：美國人口 51.1% 是女性，隨機打電話給 1,000 人，大約有 10.7% 的機率抽到的女性比例低於 48.5% 或高於 53.5%，結果就會失真。好的民調公司會按比例「分層」：確保 1,000 人裡剛好有 511 位女性。

回到房價：專家說 收入中位數 是預測房價最關鍵的屬性，所以我們要確保測試集裡各收入層的比例跟全體一致。但收入是連續值，沒辦法直接「分層」，要先切成類別：

housing["income_cat"] = pd.cut(housing["median_income"],
                               bins=[0., 1.5, 3.0, 4.5, 6., np.inf],
                               labels=[1, 2, 3, 4, 5])

切點的選法有講究。投影片 9 的提醒是：每一層都要有足夠多的樣本，否則那一層的比例估計本身就不可靠。所以層數不能太多、每層不能太小。6 以上的收入散佈在一條很長的尾巴上，如果繼續每 1.5 切一層，後面每一層都會很小，所以全部併成第 5 層（np.inf，約佔 11%）；這也是為什麼前面那個只有 5 筆的 ISLAND 不適合拿來當分層依據。

實驗：隨機抽 vs 分層抽

全體 20,640 個街區的收入層比例固定不變，調整測試集大小，看兩種方法抽出來的比例偏離全體多少：

測試集越小，隨機抽樣的偏差越誇張，尤其是只佔 4% 的第 1 層。分層抽樣則幾乎完全貼著全體比例，因為它不是「碰運氣」，而是在每一層內部各自抽 20% 再合起來。

推導：隨機抽樣會偏多少？

設某一層在全體中佔比例 ，從中隨機抽 筆當測試集。抽中的這層筆數近似二項分布 。

第 1 步：樣本比例的平均與變異數

第 2 步：換成「相對誤差」（就是比較表裡的誤差%）

第 3 步：代入第 1 層，

也就是說，光是運氣，第 1 層的比例就有約 ±7.6%（一個標準差） 的相對誤差；偏到 ±15%（兩個標準差）以上，大約每 20 次就會發生 1 次。公式分母是 ，也就是「這一層被抽到的期望筆數」，所以層越小、測試集越小，偏差越大。這就是上面模擬器裡第 1 層範圍最寬、縮小測試集時更誇張的原因，也解釋了為什麼每一層都要夠大。

分層抽樣則是直接照比例決定每層要抽幾筆，剩下的只有「把 湊成整數」的誤差，每層頂多差 1 筆。以第 1 層為例，期望筆數 ，實際會抽 164 或 165 筆，相對誤差只有 −0.24% 或 +0.36%，跟上面的比較表和模擬結果一致。層越大，湊整數的影響越小。

用 Scikit-Learn 實作

投影片 13

from sklearn.model_selection import StratifiedShuffleSplit

split = StratifiedShuffleSplit(n_splits=1, test_size=0.2, random_state=42)
for train_index, test_index in split.split(housing, housing["income_cat"]):
    strat_train_set = housing.loc[train_index]
    strat_test_set  = housing.loc[test_index]

n_splits=1：只切一組。這個類別也能產生多組不同切法，所以它回傳的是一個可以迭代的東西，就算只要一組也得寫 for 迴圈接。

split.split(X, y)：第二個參數 y 放的是分層依據，這裡是 income_cat，不是房價。它回傳的是索引，不是資料本身，所以要再用 .loc 取出。

random_state=42：固定亂數種子，讓每次執行切出來都一樣。注意「一樣」只限同一個版本：我用目前的 Scikit-Learn 1.8 重跑，分層測試集的五層比例是 0.0400／0.3188／0.3505／0.1764／0.1143，跟投影片 13 只差在小數點後第四位，因為新版切到的街區不完全相同。

其實有更簡潔的寫法，一樣是分層抽樣（兩種寫法擇一即可，切到的街區不會完全相同）：

from sklearn.model_selection import train_test_split
strat_train_set, strat_test_set = train_test_split(
    housing, test_size=0.2, stratify=housing["income_cat"], random_state=42)

這張表可以這樣做出來。注意執行時 housing 還是整份資料，income_cat 也還在：

def income_cat_proportions(data):
    return data["income_cat"].value_counts() / len(data)

train_set, test_set = train_test_split(housing, test_size=0.2, random_state=42)  # 純隨機

compare = pd.DataFrame({
    "Overall":    income_cat_proportions(housing),
    "Stratified": income_cat_proportions(strat_test_set),
    "Random":     income_cat_proportions(test_set),
}).sort_index()
compare["Rand. %error"]  = 100 * compare["Random"]     / compare["Overall"] - 100
compare["Strat. %error"] = 100 * compare["Stratified"] / compare["Overall"] - 100

分層抽樣的比例跟全體「幾乎一模一樣」（投影片寫的 Very close!），誤差都在 0.25% 以內；隨機抽樣則最多偏了 5%。第 4、5 層（高收入）在隨機測試集裡被低估，如果模型剛好在高收入區表現特別好或特別差，測試分數就會失真。

最後一步：清掉輔助欄、拆出特徵與標籤

比較完之後，income_cat 就完成任務了，要把它從兩個集合裡刪掉，避免它被當成特徵：

for set_ in (strat_train_set, strat_test_set):
    set_.drop("income_cat", axis=1, inplace=True)

接著把訓練集拆成「特徵」和「答案」：

housing = strat_train_set.drop("median_house_value", axis=1)   # 特徵 X
housing_labels = strat_train_set["median_house_value"].copy()  # 標籤 y

drop() 會回傳新的 DataFrame，不會改動 strat_train_set；標籤用 .copy() 則是確保之後改動它時不會影響到原資料。注意從這裡開始，變數 housing 指的是訓練集的特徵，不再是整份資料。

常見陷阱與自我檢查

看完全部資料才切測試集探索、挑特徵的過程會不自覺地「偷看」測試集，最後分數偏樂觀。
以為固定 random_state 就萬無一失它只保證同一份資料切得一樣；資料一更新，切法就全變。
用列號當 ID 卻刪了資料後面所有列號都會位移，雜湊結果跟著亂掉。
分層切太細層數太多、某層太小（像 ISLAND 只有 5 筆），那一層的比例本身就估不準。
忘了刪 income_cat它是從 median_income 衍生的輔助欄，留著會變成重複的特徵。
為什麼不能在看完所有資料、選好模型之後才切測試集？

因為你挑模型、挑特徵的過程已經「看過」測試集了，測試分數就不再是對「沒見過的資料」的公平估計，通常會偏樂觀。這就是 data snooping bias。

已經固定 random_state=42 了，為什麼還需要用 ID 雜湊切？

固定種子只保證「同一份資料」每次切得一樣。資料一旦新增，洗牌的對象變了，切法就全變，舊資料可能換到另一邊。ID 雜湊是看每筆資料自己的 ID，跟資料總量無關，所以更新後舊資料不會移動。

如果改用 ocean_proximity 分層，會遇到什麼問題？

ISLAND 只有 5 筆，按 20% 切只能分到 1 筆左右，這一層的比例根本估不準。而且分層依據應該是「對預測最重要」的屬性，專家指出的是收入，不是離海距離。

split.split(housing, housing["income_cat"]) 的第二個參數，為什麼不是房價？

第二個參數是「要保持比例的類別」，不是預測目標。這裡我們要保持的是收入層的比例，所以放 income_cat。房價是連續值，也沒辦法直接拿來分層。
