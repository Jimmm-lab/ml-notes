每一步只看一筆資料

投影片 20

批次梯度下降（BGD）的梯度是把每一筆資料的梯度平均起來。資料越多，每一步就越慢。隨機梯度下降（Stochastic Gradient Descent，SGD）的想法很大膽：每一步只隨機抽一筆資料，用那一筆算出的梯度就直接走。投影片列出三個特點：

  1. 快很多：每一步只處理一筆，計算量和資料筆數無關。
  2. 可以處理放不進記憶體的資料：每一步只需要把一筆資料放進記憶體，叫做 out-of-core（核外）學習，資料可以留在硬碟上一筆一筆讀。
  3. 不規則：每一筆資料「想要的方向」都不太一樣，所以成本函數不會平順地下降，而是上上下下跳動，只有平均起來在下降。走到最低點附近後，它還會一直在附近跳來跳去，永遠不會真正停下。最後得到的參數不錯，但不是最佳。

為什麼只看一筆，方向「平均起來」還是對的？

MSE 是每一筆誤差平方的平均，所以它的梯度也是每一筆梯度的平均：

是只看第 筆時的梯度。如果每一步從 筆裡均勻隨機（每一筆機率相同）抽一筆 ，每一筆被抽到的機率都是 ，那麼抽到的梯度的期望值（平均起來會是多少）剛好是：

也就是說，單一筆的梯度是真正梯度的一個不偏（unbiased）估計：每一次都有誤差，但不會系統性地偏向某一邊。就像問路時只隨便問一個路人，每個人指的方向都有點偏，但平均起來是對的。

  2. （投影片 24 沒有畫這條，這裡加上來對照）固定學習率的 SGD 很快就衝到最佳解附近，接著就在附近亂跳，MSE 曲線一直上下抖動，永遠停不下來。
  3. 用了學習時程的 SGD 和小批次 GD也很快到達最佳解附近，而且越後面跳得越小。兩者用同一個公式 5/(t+50)，但 在 SGD 數的是「第幾筆」、在小批次數的是「第幾批」，所以 50 個 epoch 後 SGD 的學習率約 0.001、小批次約 0.017。多按幾次「重來」比較，這組設定下大約八成的時候，小批次 GD 最後的 MSE 比隨機 GD 更接近最佳解；不過這個比較受學習時程影響很大，換一組時程結論可能不同。投影片說小批次會在比較靠近最低點的地方打轉，指的是在同樣的學習率下：20 筆平均起來的梯度，隨機誤差比單一筆小很多。投影片的結論：批次 GD 每一步都很花時間；如果學習時程設得好，SGD 和小批次 GD 也能走到最低點。

學習時程與 epoch

投影片 22

SGD 的隨機性是一把兩面刃：在凹凸不平的地形上，亂跳有機會跳出局部最低點（上一篇那種假的谷底）；但也因為一直在跳，它永遠停不在最低點。

為什麼固定學習率停不下來？

在最佳解上，全部資料的梯度平均是 0，但每一筆自己的梯度通常不是 0（除非每個點都剛好落在直線上）。SGD 每一步只用一筆，所以就算已經站在最佳解上，下一步還是會被那一筆拉走 這麼遠。只要 不變，這個「被拉走」就不會消失。

解決方法是讓學習率慢慢變小：一開始步伐大，可以快速前進、也比較容易跳出局部最低點；之後步伐越來越小，最後穩穩停在最低點附近。投影片說這很像模擬退火（simulated annealing）：這個名字來自冶金的「退火」，把高溫（課本說是熔化）的金屬慢慢冷卻，原子一開始動得很劇烈、可以重新排列，溫度降低後才慢慢固定在穩定的位置。學習率就像溫度：一開始高、跳得大，之後慢慢降低。決定每一步學習率的函數叫學習時程（learning schedule）。課本的例子是

是目前走到第幾步（從 0 開始）。學習率從 開始，第 100 步是 0.033，第 1,000 步是 0.0048，第 5,000 步大約只剩 0.001。學習率降得太快，還沒走到最低點就幾乎動不了；降得太慢，就會在最低點附近跳很久，或者在訓練太早結束時停在不好的位置。

epoch：把資料「看完一輪」

習慣上，把 筆訓練資料（ 是訓練資料筆數）都處理過一輪的量叫做一個 epoch（回合）；對 SGD 來說，就是走 步。同樣是一個 epoch，三種方法走的步數差很多（下圖用 、每批 5 筆來示意，一格代表一次參數更新）：

投影片的對比：上一篇的批次 GD 跑了 1,000 個 epoch（1,000 次更新）；下面這段使用學習時程的 SGD 只跑 50 個 epoch（每個 epoch 100 次更新，共 5,000 次更新），就得到很接近的答案：

n_epochs = 50
t0, t1 = 5, 50                                # 學習時程的超參數

def learning_schedule(t):
    return t0 / (t + t1)

np.random.seed(42)
theta = np.random.randn(2, 1)                 # 隨機初始化：[[0.497], [-0.138]]

for epoch in range(n_epochs):
    for iteration in range(m):
        random_index = np.random.randint(m)
        xi = X_b[random_index : random_index + 1]
        yi = y[random_index : random_index + 1]
        gradients = 2 * xi.T @ (xi @ theta - yi)   # 只用一筆，所以不除以 m
        eta = learning_schedule(epoch * m + iteration)
        theta = theta - eta * gradients

theta                                         # array([[4.21076011], [2.74856079]])

正規方程式的答案是 ，SGD 的答案差了一點點，在全部資料上的 MSE 是 0.8074，最佳解是 0.8066。這就是投影片說的「不錯，但不是最佳」。

隨機抽，會有資料被漏掉

這段程式每一步都從 100 筆裡可重複地隨機抽一筆，所以一個 epoch 裡有些資料被抽到好幾次，有些一次都沒被抽到。平均來說，一個 epoch 只會用到大約 的資料。如果想確保每一筆都用到，可以改成每個 epoch 先把資料洗牌（打亂順序），再依序一筆一筆走過去；scikit-learn 的 SGDRegressor 預設就是這樣做（shuffle=True）。

scikit-learn 的 SGDRegressor

scikit-learn 用 SGDRegressor 做隨機梯度下降的線性迴歸。課本的設定：

from sklearn.linear_model import SGDRegressor

sgd_reg = SGDRegressor(max_iter=1000, tol=1e-5, penalty=None, eta0=0.01,
                       n_iter_no_change=100, random_state=42)
sgd_reg.fit(X, y.ravel())                     # y.ravel()：目標要是一維陣列
sgd_reg.intercept_, sgd_reg.coef_             # (array([4.21278812]), array([2.77270267]))
sgd_reg.n_iter_                               # 366：實際跑了 366 個 epoch

每個參數的意思：

  • max_iter=1000：最多跑 1,000 個 epoch。
  • tol=1e-5、n_iter_no_change=100：如果連續 100 個 epoch，訓練損失都沒有比目前最好的值再降低超過 ，就提前停止。這裡在第 366 個 epoch 停下。
  • penalty=None：不加正則化。SGDRegressor 預設會加一點 L2 正則化（第 5 篇會講），這裡關掉，才能和前面的結果比較。
  • eta0=0.01：起始學習率。預設的學習時程是 learning_rate='invscaling'，也就是 （ 是第幾次更新，每看一筆加 1，從 1 開始），和課本的 形式不同，但一樣是越來越小。
  • random_state=42：固定洗牌用的亂數，讓結果可以重現。
  • 這裡只有一個特徵、範圍在 0 到 2，所以省略縮放；實務上要先用 StandardScaler，例如 make_pipeline(StandardScaler(), SGDRegressor(...))。

結果 同樣非常接近正規方程式的解。

小批次梯度下降

投影片 23

小批次梯度下降（Mini-batch GD）是折衷：每一步既不用全部資料（BGD），也不只用一筆（SGD），而是隨機抽一小群資料，叫做小批次（mini-batch），用它們的梯度來走一步：

投影片的式子直接加總；實作上常改成平均（再除以批量大小），兩者只差一個常數倍，等於換一個學習率。和 SGD 比：

  • 比較穩：幾筆資料的梯度平均起來，隨機的誤差互相抵銷一部分，所以最後會在離最低點更近的地方打轉。
  • 比較容易利用硬體：一次算一小批是矩陣運算，GPU 很擅長，常常比一筆一筆算快很多（課本提到的主要優點）。
  • 代價：因為比較不亂跳，遇到有局部最低點的地形時，可能比較難跳出來。不過線性迴歸的 MSE 是凸函數，沒有這個問題。
n_epochs = 50
minibatch_size = 20
n_batches_per_epoch = int(np.ceil(m / minibatch_size))
t0, t1 = 5, 50                                # 同一個公式；t 改成數第幾批

np.random.seed(42)
theta = np.random.randn(2, 1)
for epoch in range(n_epochs):
    shuffled = np.random.permutation(m)       # 每個 epoch 先洗牌
    X_b_shuffled, y_shuffled = X_b[shuffled], y[shuffled]
    for i in range(n_batches_per_epoch):
        idx = i * minibatch_size
        xi = X_b_shuffled[idx : idx + minibatch_size]
        yi = y_shuffled[idx : idx + minibatch_size]
        gradients = 2 / minibatch_size * xi.T @ (xi @ theta - yi)   # 一小批的平均梯度
        eta = t0 / (epoch * n_batches_per_epoch + i + t1)
        theta = theta - eta * gradients

theta                                         # array([[4.18308151], [2.79583749]])

100 筆、每批 20 筆，所以每個 epoch 走 5 步，50 個 epoch 共 250 步，學習率從 0.1 降到約 0.017。結果在全部資料上的 MSE 是 0.8069，比上面 SGD 的 0.8074 更接近最佳解 0.8066，雖然只更新了 250 次（SGD 更新了 5,000 次）。學習時程和批量大小都是要調的超參數。

幾點說明：

  • 超參數：批次 GD 有 2 個（步數、學習率）；SGD 再加上學習時程、容忍度等；小批次 GD 再加上批量大小。
  • 批次 GD 和資料放不進記憶體（投影片打了「???」）：嚴格說，批次 GD 也可以每一步都從硬碟把資料一段一段讀進來、把梯度累加起來，所以不是做不到；但每走一步就要把整份資料從硬碟讀一遍，慢到不實用，所以課本的表格寫「No」。
  • scikit-learn 那一欄：投影片在批次 GD 和小批次 GD 也寫了 SGDRegressor，但 SGDRegressor 實際上只做隨機梯度下降（一次更新一筆）。就算用 partial_fit 一次餵它一小批資料，它內部還是一筆一筆更新。課本第三版的表格在這兩格寫的是 N/A（沒有現成的類別），要用的話得像上面那樣自己寫，或使用深度學習框架。
  • 訓練好之後，這五種方法得到的模型幾乎一樣，用法也完全相同：都是 。差別只在訓練的過程。

Python 實作

接著第 1 篇的資料（X、y、X_b、m 已經準備好），一次比較三種做法：正規方程式（lstsq）、固定學習率的 SGD、SGDRegressor：

import numpy as np
from sklearn.linear_model import SGDRegressor

def mse(theta):
    return ((X_b @ theta - y) ** 2).mean()

theta_ne = np.linalg.lstsq(X_b, y, rcond=None)[0]
mse(theta_ne)                                 # 0.80658...（最佳解）

# SGD：固定學習率，對照用
np.random.seed(42)
theta = np.random.randn(2, 1)
for epoch in range(50):
    for iteration in range(m):
        k = np.random.randint(m)
        theta = theta - 0.05 * 2 * X_b[k:k+1].T @ (X_b[k:k+1] @ theta - y[k:k+1])
theta.ravel(), mse(theta)                     # (array([3.97065939, 2.52218468]), 1.0562...)

# SGDRegressor
sgd_reg = SGDRegressor(max_iter=1000, tol=1e-5, penalty=None, eta0=0.01,
                       n_iter_no_change=100, random_state=42)
sgd_reg.fit(X, y.ravel())
sgd_reg.intercept_, sgd_reg.coef_             # (array([4.21278812]), array([2.77270267]))

固定學習率 0.05 的 SGD 跑完 50 個 epoch，停在 ，MSE 1.056，比最佳解的 0.807 高不少：最後幾步剛好被幾筆資料拉離了最佳解（最後一個 epoch 的 MSE 平均約 0.93，在 0.81 到 1.44 之間跳）。換一個停下的時間點，結果又不一樣，這就是「永遠停不下來」。

常見陷阱與自我檢查

資料依某種順序排好，卻沒有打亂如果資料是依房價由低到高排好的，SGD 依序走過去，就會先一直往「便宜房子」的方向調，再一直往「貴房子」調，學到的東西很偏。每個 epoch 先洗牌，或像課本一樣每次隨機抽。
用單一步的損失判斷是否收斂SGD 每一步的損失本來就會跳動，看到某一步變大不代表訓練壞掉。要看一段時間的平均趨勢，或在每個 epoch 結束時用全部（或驗證）資料算一次。
學習時程降得太快學習率很快就變得很小，參數還沒走到最低點就幾乎不動了，看起來像「收斂」，其實停在半路。
忘了縮放特徵三種梯度下降都會被細長的碗拖慢（上一篇的實驗），用之前先標準化。
訓練資料有 1,000,000 筆，小批次大小是 100。一個 epoch 裡，三種梯度下降各更新幾次參數？

批次 GD：1 次。小批次 GD：1,000,000 ÷ 100 = 10,000 次。隨機 GD：1,000,000 次。

已經站在最佳解上了，固定學習率的 SGD 下一步為什麼還會移動？

最佳解只保證「全部資料的梯度平均是 0」。SGD 只用一筆資料的梯度，那一筆的梯度通常不是 0（除非它剛好落在直線上），所以參數會被拉走 。要讓它停下來，就得讓 越來越小。

資料有 500 GB，電腦記憶體只有 16 GB，該選哪一種方法？

隨機 GD 或小批次 GD：每一步只需要把一筆或一小批資料讀進記憶體。正規方程式和 SVD 的一般做法（例如 LinearRegression）要把整個 讀進記憶體，課本的表格也寫「不行」（特徵不多時，其實可以一段一段把 和 累加起來再解，只是現成工具不這樣做）；批次 GD 雖然可以每一步把資料從硬碟讀過一遍，但每走一步都要讀 500 GB，太慢了。

為什麼說隨機抽一筆的梯度是真正梯度的「不偏估計」？

每一筆被抽到的機率都是 ，所以抽到的梯度的期望值是 ，剛好就是全部資料的梯度（MSE 的梯度就是每一筆梯度的平均）。每一次會有誤差，但平均起來不偏向任何方向。
