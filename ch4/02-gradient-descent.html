下山的想法

投影片 9–10

想像你蒙著眼睛站在山坡上，想走到谷底。你看不到整座山，只能用腳感覺腳下哪個方向往下傾斜，然後朝那個方向踩一步；再感覺一次、再踩一步。坡度越平，通常代表離谷底越近（但後面會看到例外：高原上坡度也很平，卻離谷底還很遠）；坡度變成 0，就到了。

梯度下降（Gradient Descent）就是這樣做的：

  1. 隨機初始化（random initialization）：先隨便給參數 一組數字，相當於被丟在山坡上某個地方。
  2. 量坡度：算出成本函數（例如 MSE）在目前位置對 的梯度（gradient），也就是「往哪個方向、多陡地往上」。
  3. 往下坡走一小步：朝梯度的反方向更新 ，步伐大小由學習率（learning rate）決定。
  4. 重複 2、3，直到梯度幾乎是 0，演算法收斂（converge）到最低點。

投影片把它歸類為一種最佳化演算法（optimization algorithm）：目標是找到讓成本函數最小的參數。和正規方程式相比，它適合特徵非常多的情況，因為每一步只需要算梯度，不需要求反矩陣；資料多到放不進記憶體時，則要用下一篇的隨機／小批次版本，每一步只看一部分資料。

成本函數（cost function）、損失函數（loss function）、誤差函數（error function）這幾個名詞，在這一章幾乎可以互換，都是指「要被最小化的那個數字」，下面用 表示。

兩個陷阱與凸函數

投影片 14

切到「凹凸不平」的地形，就會遇到投影片說的兩個陷阱：

  1. 局部最低點（local minimum）：從左邊出發，會先掉進左邊那個比較淺的坑。那裡坡度也是 0，演算法以為到了，但右邊還有一個更深的全域最低點（global minimum）。
  2. 高原（plateau）：從右邊出發，地面幾乎是平的，坡度很小，每一步只挪動一點點。用 η = 0.05 從 θ = 2.8 出發，要走好幾百步才離開高原；如果步數上限太小，就會在還沒走到谷底時被迫停下。

好消息是：線性迴歸的 MSE 是凸函數（convex function），這兩個陷阱都不會發生。投影片的定義是：在曲線上任選兩點，把它們用線段連起來，這條線段永遠不會穿過曲線（線段一定在曲線上方或剛好貼著）。碗形符合；凹凸不平的地形不符合：把兩個坑的谷底連起來，線段會穿過中間那座小山。

凸函數沒有「假的谷底」：任何坡度為 0 的地方都是全域最低點。再加上 MSE 的坡度變化很平順（不會突然變陡），只要學習率不太大、走得夠久，梯度下降一定能走到全域最低點附近。

特徵縮放

投影片 15

投影片舉的例子：特徵 是房間數（1 到 5）， 是面積（1,000 到 2,000 平方英尺）。兩個特徵的數字大小差很多時，成本函數的碗會被壓成又細又長的形狀，梯度下降先快速衝到谷底那條「溝」，接著沿著溝底慢慢爬，要走很久（投影片右圖）。兩個特徵尺度相近時，碗是圓的，直直走向中心（左圖）。

為什麼細長的碗會慢？

MSE 是二次函數，碗在不同方向的彎曲程度不一樣。把一維推導推廣：碗有兩個主要方向，就是等高線橢圓的短軸（最陡）和長軸（最平）。沿著每一個主要方向，離谷底的距離每一步乘上 ， 是那個方向的彎曲程度（數學上是成本函數二次微分矩陣的特徵值）。一維的 就是 ，乘數 和前面的推導一樣。

  • 為了不發散，每個方向都要 ，所以 ，學習率被最陡的方向限制住。這就是上面說的「最大安全值」。
  • 在最平的方向，每一步只縮短 這個比例的距離，非常少。就算把 開到 ，每步也只縮短 。

叫條件數，就是碗「細長」的程度。這份資料標準化後條件數約 1.0，用坪約 16.9，用平方公尺約 184，步數也大致跟著條件數變多。

要走幾步？容忍度

投影片 19

步數設太少，停下來時還離谷底很遠；設太多，後面一大段參數幾乎不再改變，只是浪費時間。投影片的做法：步數上限設得很大，但當梯度向量的長度（norm）小於一個很小的數字 時就提前停止。這個 叫容忍度（tolerance）。梯度很小代表坡很平，已經（幾乎）到谷底了。

Python 實作

把本篇的程式整理在一起，接著第 1 篇的資料：

import numpy as np

np.random.seed(42)
m = 100
X = 2 * np.random.rand(m, 1)
y = 4 + 3 * X + np.random.randn(m, 1)
X_b = np.c_[np.ones((m, 1)), X]

# 批次梯度下降 + 容忍度
def batch_gd(eta=0.1, n_max=100_000, tol=1e-6):
    theta = np.random.randn(2, 1)
    for k in range(n_max):
        gradients = 2 / m * X_b.T @ (X_b @ theta - y)
        if np.linalg.norm(gradients) < tol:        # 坡夠平了就停
            return theta, k
        theta = theta - eta * gradients
    return theta, n_max

theta, k = batch_gd()
theta.ravel(), k                              # (array([4.21509398, 2.77011531]), 393)

# 最大安全學習率：2 / (成本函數二次微分矩陣最大的特徵值)
H = 2 / m * X_b.T @ X_b
2 / np.linalg.eigvalsh(H).max()               # 0.4842...

batch_gd() 裡的 np.random.randn(2, 1) 接在產生資料之後，所以起點和上面一樣是 (0.013, 1.454)，要走 393 步，和容忍度表格中 那一列相同。停下來的答案和正規方程式只差 左右，這就是容忍度的意思：夠接近就停，不追求完全相等。實務上用梯度下降訓練線性迴歸時，scikit-learn 提供的是下一篇會介紹的 SGDRegressor；記得先用 StandardScaler 把特徵標準化。

常見陷阱與自我檢查

沒有先縮放特徵正規方程式不在乎單位，梯度下降非常在乎。實測只是把坪換成平方公尺，步數就從 73 步變成 843 步。
學習率太大，參數變成 inf 或 nan看到成本函數越來越大、或出現 inf、nan，第一個要懷疑的就是學習率太大。先把它縮小 10 倍試試。
把「梯度很小」當成「一定到最低點」在凸函數上這是對的；但在凹凸不平的地形，梯度很小也可能是局部最低點、高原，甚至山頂。線性迴歸的 MSE 是凸的，所以不用擔心。

把面積從「坪」換成「平方公尺」，正規方程式的答案會變嗎？梯度下降呢？

兩者最後找到的模型（預測結果）都一樣，面積的權重只是自動除以 3.3058。差別在過程：正規方程式一步算完，不受影響；梯度下降的碗變得更細長（條件數從約 16.9 變成約 184），要走的步數從 73 步變成 843 步。

用梯度下降訓練線性迴歸，會不會卡在局部最低點？

不會。線性迴歸的 MSE 是凸函數，沒有假的谷底，任何坡度為 0 的地方都是全域最低點。只要學習率在安全範圍內、步數夠多，就會走到全域最低點附近。

一維的碗 學習率上限是 1，為什麼本篇的資料用 0.5 就發散了？

上限取決於碗有多陡。 的二次微分是 2，上限是 2/2 = 1。本篇資料的 MSE 在最陡方向的彎曲程度約 4.13，上限是 2/4.13 ≈ 0.484，所以 0.5 已經超過了。
