ROC 曲線畫的是什麼

投影片 17

ROC 曲線（receiver operating characteristic，接收者操作特徵曲線）這個名字來自二戰時期的雷達：操作員要從訊號裡判斷是不是敵機，靈敏度調高就會多抓到敵機，但也多出很多假警報。這和分類器調門檻是同一件事。

ROC 曲線的縱軸是 TPR（true positive rate），橫軸是 FPR（false positive rate）：

TPR（Recall、sensitivity）

所有真的是 5的圖裡，被判斷成 5 的比例。越高越好。

FPR（1 − specificity）

所有真的不是 5的圖裡，被誤判成 5 的比例。越低越好。TNR 又叫 specificity（特異度），所以 FPR = 1 − specificity。

兩個比例的分母都是「真實的某一類」，也就是混淆矩陣的某一列：TPR 看的是下面那一列（真的 5），FPR 看的是上面那一列（真的非 5）。這一點等一下會很重要。投影片第 17 頁的重點是：Recall（TPR）越高，FPR 也越高。門檻降低時會多抓到 5，同時也會多誤判非 5。

from sklearn.metrics import roc_curve

fpr, tpr, thresholds = roc_curve(y_train_5, y_scores)   # y_scores 來自上一篇的 cross_val_predict

隨機分類器是一條對角線

投影片 18

ROC 圖上一定會畫一條從 (0, 0) 到 (1, 1) 的虛線，代表完全隨機猜的分類器。好的分類器要離這條線越遠越好，往左上角靠。

推導：為什麼隨機猜會落在對角線上

投影片的說法：隨機挑出比例 的圖判斷成正類。因為挑選和真實答案無關，平均而言，真正的正類裡有比例 被挑中，真正的負類裡也有比例 被挑中：

（、 是正類和負類的總數。）所以不管 是多少，這個點都在 的對角線上； 從 0 走到 1，就畫出整條對角線，底下的面積是 0.5。和上一篇比較：隨機分類器在 PR 圖上是一條高度等於正類比例的水平線，會隨資料改變；在 ROC 圖上則永遠是同一條對角線，和正類多少無關。

AUC：曲線下面積

投影片 18、21

要用一個數字比較分類器，就算 ROC 曲線下的面積（ROC AUC）。完美的分類器是 1，隨機猜是 0.5。

from sklearn.metrics import roc_auc_score
roc_auc_score(y_train_5, y_scores)   # 0.9605（sklearn 1.8）  投影片：0.9612

AUC 還有一個很直覺的意思：隨便抽一張 5 和一張非 5，5 的分數比較高的機率。0.96 的意思就是，100 對裡大約有 96 對，模型把 5 排在非 5 前面。

推導：AUC 等於「正類排在負類前面」的機率

第 1 步：把門檻從最高一路往下降

每經過一張負類的分數，FPR 增加 ，曲線往右走一小格；每經過一張正類的分數，TPR 增加 ，曲線往上走一小格。

第 2 步：看每一小格往右時的高度

經過某一張負類 時，曲線的高度 TPR 等於「分數比 高的正類」所佔的比例。這一格的面積是這個高度乘上寬度 。（如果有正類和負類的分數剛好相同，曲線會斜著走一段，面積就是那段梯形，相當於這些配對各算半個。）

第 3 步：把所有小格加起來

（、 分別是正類和負類的集合。）分子是「正類分數大於負類分數」的配對數，分母是所有配對數，所以 AUC 就是隨機抽一對時正類贏的機率（分數相同的配對算半個）。它等於 Mann–Whitney U 統計量除以 。

我在真實資料上驗證了兩次。用排名算出所有 5,421 × 54,579 對，結果是 0.96049，和 roc_auc_score 完全一樣。另外隨機抽 200,000 對，5 贏的比例是 0.9610，也很接近。

0.96 聽起來很厲害。投影片第 21 頁卻在同一條 ROC 曲線旁邊寫著：「看起來很好，是因為 5 比非 5 少很多，但它其實不夠好。」下一節說明原因。

正類很少時，ROC 為什麼太樂觀

投影片 20、23

投影片的經驗法則：正類很稀少（資料不平衡），或你比起 FN 更在意 FP 的時候，用 PR 曲線；否則用 ROC 曲線。關鍵在分母。

指標公式分母是Recall 90% 時
FPRFP ÷ 真的非 554,579（很大）4,575 ÷ 54,579 = 8.4%
TPR（Recall）TP ÷ 真的 55,421（小）4,879 ÷ 5,421 = 90.0%
PrecisionTP ÷ 判斷成 59,454（小）4,879 ÷ 9,454 = 51.6%

投影片第 23 頁的說法：一個還不錯的預測器，不會做出大量的正類預測，所以 FP 和 TP 都是比較小的數字。但 FPR 的分母是全部的負類，數量是正類的 10 倍。4,575 張誤判放在 54,579 張裡只佔 8.4%，FPR 很容易一直停在很小的值，看不出差別，AUC 也就可能反映不出真正的表現。Precision 則把 FP 直接放在 TP 旁邊比：4,575 張誤判不是和 54,579 張非 5 比，而是和 4,879 張抓對的 5 比，問題一下就看出來了。

不同正類比例下的 ROC 與 PR

投影片 24

投影片最後一張參考圖，比較不同正類比例（50%、10%、1%）下的 ROC 和 PR 曲線。下面用一個簡單的模擬重現：假設負類的分數服從標準常態分布，正類的分數也是常態分布、標準差同樣是 1，只是平均值往右移了 。 越大，兩類分得越開。

ROC 曲線

PR 曲線

固定 、只切換正類比例：ROC 曲線一動也不動，因為 TPR 和 FPR 都只看同一類裡的比例；PR 曲線卻會隨正類變少而整條往下掉，基準線也跟著下降。這就是投影片的兩個結論：

  • 在相同的正類比例下，如果一個模型的 ROC 曲線整條都在另一個上方（像這裡不同的 ），它的 PR 曲線也會整條在上方，兩種曲線的排名一致。但兩條 ROC 曲線有交叉時，AUC 和 AP 的排名可能相反。
  • 但在不平衡的資料上，PR 曲線比 ROC 曲線和 AUC 更有資訊量：ROC 看起來還很漂亮的模型，PR 曲線會告訴你它實際的誤報有多嚴重。

常見陷阱與自我檢查

在不平衡資料上只看 ROC AUCAUC 0.96 的 SGD，在 Recall 90% 時將近一半的正類預測是錯的。正類很少時，一定要一起看 PR 曲線或 Precision。
忘了第一個門檻是 infroc_curve 的第一個門檻是 inf，對應 (0, 0) 那一點。拿門檻去做運算或畫「對門檻的曲線」時，要記得處理它。
把 ROC 和 PR 的橫軸搞混ROC 的橫軸是 FPR，PR 的橫軸是 Recall，而 Recall 是 ROC 的縱軸。兩張圖最好的角落也不同：ROC 是左上（FPR = 0、TPR = 1），PR 是右上（Recall = 1、Precision = 1）。投影片第 20 頁說 PR 曲線「應該更靠近左上角」，以 PR 圖的座標來看，應該是右上角才對。
以為 predict_proba 一定是細緻的機率隨機森林的機率是 100 棵樹各自機率的平均。樹長到每片葉子都只剩一類時，每棵樹只會給 0 或 1，平均起來就等於投票比例，只會出現 0、0.01、0.02……1 這 101 種值（樹的數量換了，種類也會變）。我在真實資料上數過正好 101 種。畫出來的曲線會是一段一段的。
某個模型的 AUC 是 0.3，是不是比隨機猜還差、完全沒用？

比隨機差，但不是沒用：它的排名傾向反過來。把分數加上負號，或把預測結果反過來，AUC 就變成 1 − 0.3 = 0.7。AUC 低於 0.5 通常代表正負類的標籤或分數方向搞反了。

一個模型在某點 TPR = 0.8、FPR = 0.05。如果正類佔 1%，Precision 是多少？

用推導的公式：。FPR 只有 5%，看起來很低，但因為負類是正類的 99 倍，判斷成正類的圖裡只有 14% 是真的。

把資料裡的負類複製一倍（正類比例從 9% 變成約 5%），ROC 曲線和 PR 曲線會怎麼變？

ROC 曲線完全不變：每個門檻下，負類裡被誤判的比例一樣，FPR 不變；TPR 也不變。PR 曲線會往下掉：同一條門檻下 FP 的數量變成兩倍，Precision 變低，基準線也從 0.09 降到約 0.05。

什麼時候用 ROC 比較合適？

正類和負類的數量差不多，而且兩種錯誤差不多重要的時候。這時兩種曲線給出的結論通常一致，ROC 曲線和 AUC 的解讀又比較直覺（對角線、0.5、1），而且在各類內部的分數分布不變時，不受正類比例影響。不過不同資料集之間通常不只正類比例不同，AUC 不能直接拿來比。
