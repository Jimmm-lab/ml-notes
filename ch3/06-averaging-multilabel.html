每一類各算一次

投影片 32

多類別問題的第一步，是用一對其餘的方式每一類各算一次，之後再決定怎麼把它們合成一個數字：輪到 A 時，把 A 當正類，其他全部當負類，就回到第 2 篇熟悉的二元情況。

下面是投影片的 4 類例子（A、B、C、D，共 127 筆）。列是真實類別，行是預測類別；點左邊的類別名稱，看它的 TP、FP、FN 在哪裡。格子裡的數字都可以改，下面所有指標會跟著重算：

TPFP（同一行、其他列）FN（同一列、其他行）
類別PrecisionRecallF1筆數（support）

以類別 A 為例（投影片的算式，P 是 Precision、R 是 Recall）：

FP 是「同一行、其他列」：模型猜 A 但其實不是 A（B 裡有 3 筆）；FN 是「同一列、其他行」：真的是 A 卻被猜成別的（26 + 20 + 12 = 58 筆）。其他類別很少被誤認成 A（Precision 高），但真的 A 卻很常被漏掉（Recall 低）。f1_score(y_true, y_pred, average=None) 會一次回傳 4 個 F1：[0.621, 0.333, 0.267, 0.133]。

三種平均：micro、macro、weighted

投影片 33

4 個分數不好比較，所以要合成一個。投影片介紹三種方法：

  1. micro：先把所有類別的 TP、FP、FN 全部加總，再算一次 Precision、Recall、F1。投影片註明：這等於準確率（accuracy）。
  2. macro：每一類的 F1 直接平均。每一類的權重一樣，不管那一類有 108 筆還是 2 筆。
  3. weighted：每一類的 F1 依筆數加權平均，筆數多的類別影響比較大。

（ 是類別數， 是第 類的真實筆數， 是總數。）在投影片的例子裡三個數字差很多：A 有 108 筆、表現最好，weighted 被 A 拉高到 0.573；C 和 D 只有 4 筆和 2 筆、表現很差，macro 把它們和 A 看得一樣重，被拉低到 0.339。

推導：單一標籤的多類別問題裡，micro 平均為什麼等於準確率？

每一筆資料只有一個真實類別、一個預測類別。

猜對的一筆

它是真實類別的 TP；對其他類別來說只是 TN，不會算進任何 TP、FP、FN。所以 就是猜對的總筆數。

猜錯的一筆（真實 、預測 ）

它同時是 的一個 FP，也是 的一個 FN。所以每一筆錯誤都讓 和 各加 1，兩者都等於猜錯的總筆數 。也就是說 ，所以下面 Precision 和 Recall 的分母一樣，F1 也跟著相等。

代進去

投影片的例子：猜對的是對角線 50 + 8 + 4 + 1 = 63 筆，micro 平均 = 63 ÷ 127 = 0.496，和 f1_score(average='micro') 的 0.49606 一樣。

順帶一個小發現：weighted 平均的 Recall 也等於準確率，因為 。weighted 的 F1 和 Precision 則不一定。

該用哪一種？

macro：每一類都一樣重要時用，特別是想知道少數類別表現如何。投影片註明：macro 不管各類別的樣本數。

weighted：想要一個反映「整體資料」的數字時用。它依筆數加權，所以是偏向大類別的，並不會替小類別「補償」；大類別的好表現可能掩蓋小類別的問題。

micro：在單一標籤的多類別問題裡就是準確率；在多標籤問題裡（下面會講）才和準確率不同。

試試看：把上面矩陣「真 D」那一列、「猜 D」那一格的 1 改成 20（多了 19 筆被猜對的 D），看 macro 和 weighted 怎麼變。（答案：macro 從 0.339 跳到約 0.494，weighted 從 0.573 變成約 0.605；D 從最小的類別變成第二大，對 macro 的影響特別明顯。）

真實 MNIST 上的三種平均

把第 5 篇縮放後的 SGD 預測（sklearn 1.8，60,000 張的交叉驗證預測）拿來算。下面是每個數字的 Precision、Recall 和 F1（縱軸從 0.6 開始）：

micro F1（= 準確率）0.8965
macro F10.8976
weighted F10.8991

三個數字幾乎一樣，和投影片的例子完全不同。原因是 MNIST 的 10 類大小差不多（每類 5,421 到 6,742 張），加權和不加權差不了多少。macro 和 weighted 差很多時，代表類別大小不平衡，而且大類別和小類別的表現不一樣（類別一樣大時，這兩個數字會完全相等）。至於 micro 和 macro 的差距，就算類別一樣大也可能出現，例如某些類別的 Precision 特別低，所以要回頭看逐類的分數才知道原因。

逐類看才看得到的東西：數字 8 的 F1 最低（0.769），但它的 Recall 很高（0.927），問題出在 Precision 只有 0.657，每三次猜 8 就錯一次。這和第 5 篇混淆矩陣裡「第 8 行特別亮」是同一件事。5 的 F1 第二低（0.850），Precision（0.882）和 Recall（0.820）都在 10 類裡偏低。

多標籤分類

投影片 34

到目前為止，每筆資料只屬於一類。但有時候一筆資料可以同時屬於好幾類：一張照片裡可能同時有太陽和雲；一篇文章可以同時是「科技」和「商業」。這種問題叫多標籤分類（multilabel classification），輸出不是一個類別，而是一串 0 和 1。

多類別（單一標籤）

每張圖剛好一個 1：只能選太陽、月亮、雲其中之一。

多標籤

每張圖可以有好幾個 1。點下面的按鈕，自己加減標籤。

向量的順序是 [太陽, 月亮, 雲]。左邊每個向量都是 one-hot（剛好一個 1）；右邊可以是 [1 0 1]（太陽和雲）甚至 [1 1 1]。投影片說多標籤「比較複雜」：模型要對每個標籤各自判斷，評估時也要決定怎麼合併好幾個標籤的分數。

課本的例子：大數字、奇數

課本用 MNIST 做了一個多標籤的例子：每張圖有兩個標籤，「是不是大數字（7、8、9）」和「是不是奇數」。

import numpy as np
from sklearn.neighbors import KNeighborsClassifier

y_train_large = (y_train >= '7')
y_train_odd = (y_train.astype('int8') % 2 == 1)
y_multilabel = np.c_[y_train_large, y_train_odd]   # 每一列有兩個標籤

knn_clf = KNeighborsClassifier()
knn_clf.fit(X_train, y_multilabel)
knn_clf.predict([some_digit])                      # array([[False,  True]])

第一張圖是 5：不是大數字、是奇數，答案 [False, True] 完全正確。KNeighborsClassifier 天生支援多標籤；SVC 不支援，直接丟多標籤進去會出錯（實測錯誤訊息是 y should be a 1d array）。課本第三版建議用 ClassifierChain 把它串起來：每個標籤一個模型，後面的模型會把前面那些標籤當成額外的特徵（訓練時用真實標籤，或設定 cv 時改用交叉驗證的預測；預測時用前面模型的預測），所以能利用「標籤之間的關係」。照課本用前 2,000 張實測，ClassifierChain(SVC(), cv=3, random_state=42) 對第一張圖的預測是 [[0., 1.]]，同樣正確。

評估時，同樣可以每個標籤算一個 F1 再平均（cross_val_predict 和 f1_score 在前幾篇已經匯入）：

y_train_knn_pred = cross_val_predict(knn_clf, X_train, y_multilabel, cv=3)
f1_score(y_multilabel, y_train_knn_pred, average="macro")   # 0.9764...（和課本相同）
指標（sklearn 1.8 實測）大數字奇數合併

多標籤時，micro 平均就不再等於準確率了。這時「準確率」通常有兩種說法：每個標籤各自對不對，或是整列完全對（exact match，兩個標籤都要對）。表中最後兩列就是這兩種：每個標籤各自的準確率是 0.982 左右，整列完全對只有 0.975，後者一定不會比前者高。要注意：accuracy_score 遇到多標籤時，算的就是整列完全對。多標籤還多了一種 average="samples"：先對每張圖算一個 F1，再對所有圖平均。

表中的 samples F1 只有 0.593，為什麼？0、2、4、6 這些圖既不是大數字、也不是奇數，兩個標籤都是 False，佔了訓練集的 39.4%（23,641 張）。模型對它們也大多預測「沒有標籤」。對一張「真實和預測都沒有任何標籤」的圖，F1 是 0 ÷ 0，scikit-learn 預設把它當成 0，並跳出 UndefinedMetricWarning。這些圖明明全對，卻被算成 0 分，平均就被拉到 0.593。實測：38.6% 的圖真實和預測都沒有任何標籤；改成 f1_score(..., average="samples", zero_division=1)，把這些「全對」的圖算成 1 分，samples F1 就變成 0.979。這個例子說明：選平均方式之前，要先想清楚它在你的資料上會遇到什麼邊界情況。

Python 實作

接續前幾篇的程式。前半段是投影片的 4 類例子，可以直接執行；後半段用第 5 篇縮放後的預測 y_train_pred：

import numpy as np
from sklearn.metrics import f1_score, recall_score, classification_report

# 投影片的 4 類例子：把混淆矩陣展開成 y_true、y_pred
M = np.array([[50, 26, 20, 12],
              [ 3,  8,  2,  0],
              [ 0,  0,  4,  0],
              [ 0,  1,  0,  1]])
labels = np.array(list("ABCD"))
y_true = np.repeat(np.repeat(labels, 4), M.ravel())
y_pred = np.repeat(np.tile(labels, 4), M.ravel())

f1_score(y_true, y_pred, average=None)        # array([0.621, 0.333, 0.267, 0.133])
f1_score(y_true, y_pred, average="micro")     # 0.49606...
f1_score(y_true, y_pred, average="macro")     # 0.33861...
f1_score(y_true, y_pred, average="weighted")  # 0.57281...
(y_true == y_pred).mean()                     # 0.49606...：和 micro 一樣
recall_score(y_true, y_pred, average="weighted")   # 0.49606...：weighted recall 也一樣

# 真實 MNIST（第 5 篇縮放後的 SGD 預測）
print(classification_report(y_train, y_train_pred, digits=3))
#               precision    recall  f1-score   support
#            8      0.657     0.927     0.769      5851
#     accuracy                          0.896     60000
#    macro avg      0.906     0.895     0.898     60000
# weighted avg      0.907     0.896     0.899     60000   （節錄）

classification_report 一次印出每一類的 Precision、Recall、F1、筆數（support），以及 macro 和 weighted 平均，是做多類別評估時最方便的工具。

常見陷阱與自我檢查

多類別時忘了指定 averagef1_score 預設 average='binary'，只適用於二元問題。遇到多類別的標籤會直接報錯，要自己指定 'micro'、'macro'、'weighted' 或 None。
在單一標籤的多類別問題裡同時報告 micro F1 和準確率兩者一定相等，同時報告只是重複。
只看 weighted，忽略小類別weighted 由大類別主導。如果少數類別很重要（例如罕見疾病），一定要看 macro 或逐類的分數。
把多標籤當成多類別多類別的輸出是一個類別；多標籤的輸出是一串 0／1。多類別常用 softmax（把各類分數轉成機率、總和為 1 的函數，之後的章節會介紹）；多標籤則是每個標籤各給一個「有／沒有」的答案（可以用 ClassifierChain 讓後面的標籤參考前面的），機率加起來不必是 1。
為什麼投影片例子的 macro F1（0.339）比 micro（0.496）低那麼多？

micro 等於準確率，被佔 85% 的 A 主導；macro 讓每一類同樣重要，而 C（F1 0.267）和 D（F1 0.133）表現很差，把平均拉低。macro 明顯低於 micro，通常代表小類別的表現比大類別差。

一個 3 類問題，某模型永遠猜最大的那一類（佔 80%）。micro 和 macro F1 大約是多少？

micro 等於準確率 0.8。macro：最大類的 Precision 0.8、Recall 1，F1 = 2 × 0.8 × 1 ÷ 1.8 ≈ 0.889；另外兩類從來沒被猜過，F1 是 0。macro = (0.889 + 0 + 0) ÷ 3 ≈ 0.30。macro 一眼就看穿了這個笨模型，就像第 2 篇 F1 看穿 Never5 一樣。

多標籤問題裡，micro 平均為什麼不再等於準確率？

推導 micro = accuracy 時，關鍵是分母 剛好等於資料筆數 ，因為每筆資料剛好有一個預測類別。多標籤時，一張圖可以預測 0 個、1 個或好幾個標籤，這個分母就變成「預測出來的標籤總數」，不再是 。而多標籤的「準確率」本身也換了基準：每個標籤各自的準確率連 TN 都算進去，整列完全對則是以整張圖為單位。分子分母都不同，自然不會相等。
