MNIST：七萬張手寫數字

投影片 2–3

MNIST（Modified National Institute of Standards and Technology）是一組手寫數字圖片，一共 70,000 張，由美國的高中生和人口普查局員工寫成。每張圖都附上正確答案，也就是它寫的是 0 到 9 的哪一個數字。它小、乾淨、又有標準答案，所以幾乎每一本機器學習的書都拿它當第一個分類練習，被稱為機器學習界的「Hello World」。

下面是資料集裡真正的前 24 張圖，和投影片第 2 頁那張圖的前兩列、再加第三列的前 4 張一模一樣。最後 4 張（標籤有虛線底線）不是第 25–28 張，而是從訓練集挑出來、5 偵測器判斷錯誤的例子，後面講 SGD 時會用到。每張圖下面是它的標籤：

點任何一張圖，下面的像素檢查器和 5 偵測器都會換成那一張。

一張圖＝784 個數字

投影片 3

電腦看不到「圖」，只看得到數字。每張 MNIST 圖是 28 × 28 = 784 個像素，每個像素是一個 0 到 255 的整數，代表墨水有多濃：0 是完全沒有筆跡的背景，255 是最濃的筆畫。把這 784 個數字一列一列接起來，就變成資料表裡的一列，也就是 784 個特徵。

特徵 0攤平後的一列（784 個特徵）特徵 783

在圖上移動游標（手機可以點），看每個像素在那一長條裡的位置。第 r 列、第 c 行的像素，攤平後是第 28r + c 個特徵，所以長條上每 28 格就是原圖的一整列。這也說明了攤平會丟掉什麼：原本上下相鄰的兩個像素，在長條上相隔 28 格，模型不會自動知道它們是鄰居。

0 是黑還是白？投影片寫「0 是黑、255 是白」，這是用灰階直接顯示時的樣子：黑底白字。課本畫圖時用的是反過來的色表，所以書上看到的是白底黑字。兩種畫法數字完全一樣：0 永遠是背景，255 永遠是最濃的筆畫。這一頁的圖在淺色模式下是白底深色字，深色模式下會變成黑底白字，就是這兩種畫法。

大部分特徵是 0。我把 70,000 張圖全部數過：平均每張只有約 150 個像素不是 0，其他約 81% 的像素都是空白背景。

已經切好、洗好的訓練集

投影片 3

MNIST 出廠就已經切好了：前 60,000 張是訓練集，後 10,000 張是測試集。上一章我們要自己用分層抽樣切測試集，這裡不用，直接用切片取出來就好。

訓練集也已經洗牌（shuffle）過了，這有兩個好處。第一，做交叉驗證時每一份（fold）都會混到各種數字，不會有一份剛好全是 0。第二，有些演算法對資料順序很敏感，SGD 就是一個：它一次看一筆資料就更新一次參數，如果資料照數字排好，它會先連看約 6,000 張 0，參數被帶往「0 的方向」，接著又被一路帶去 1、2、3……最後學到的東西會偏向最後看到的數字。不過 scikit-learn 的 SGDClassifier 預設 shuffle=True，每一輪都會自己重新洗牌，所以對這個模型來說，資料集事先洗好主要是為了交叉驗證；自己寫 SGD、或資料是一筆一筆串流進來時，順序才真的要自己處理。

訓練集裡每個數字有幾張（真實數量）

10 個數字大致平均，每個都在 1 成左右。5 剛好是最少的：5,421 張，只佔 9.04%。記住這個數字，最後一節會用到。

二元分類器：5 偵測器

投影片 4

直接分 10 類有點難，所以課本先把問題簡化：只問「這張是不是 5？」。答案只有兩種，是 5（正類，positive）和不是 5（負類，negative），這種只分兩類的模型叫二元分類器（binary classifier），這一個就叫「5 偵測器」。

y_train_5 = (y_train == '5')   # 是 5 → True，其他數字 → False
y_test_5  = (y_test == '5')

（這一篇的程式片段都假設資料已經載入，完整、可以從頭執行的程式在最後的〈Python 實作〉一節。）這一步只是把答案換掉，圖片本身不變。回到上面那排數字，按「顯示 5 偵測器要學的答案」：原本 0 到 9 的十種標籤，變成只有 True 和 False 兩種。

投影片寫 == 5，這裡為什麼寫 == '5'？用 fetch_openml 下載的 MNIST，標籤是字串 '5'，不是整數 5。舊版課本先把標籤轉成整數，所以可以寫 == 5。如果標籤還是字串卻寫 == 5，比較結果會全部是 False，不會出現任何錯誤訊息；要到 fit 時才會因為「只有一個類別」而報錯。我在真實資料上試過：(y_train == 5).sum() 的結果是 0。

SGDClassifier 在算什麼

投影片 4–5

from sklearn.linear_model import SGDClassifier

sgd_clf = SGDClassifier(random_state=42)
sgd_clf.fit(X_train, y_train_5)

投影片在這裡問了兩個問題：它的 hypothesis function 是什麼？loss function 又是什麼？名字裡的 SGD 是訓練方法（隨機梯度下降，第 4 章），不是模型本身。投影片第 5 頁說得很清楚：SGDClassifier 是一種線性分類器，用 SGD 來訓練；它預設的 loss='hinge' 就是線性 SVM（第 5 章）。

第 1 張圖（真的是 5）的分數是 2,164，大於 0，所以判斷是 5，和 sgd_clf.predict([some_digit]) 回傳 True 一致。這個分數就是 decision_function 的輸出，第 3 篇會一直用到它。

老實說，這張權重圖看起來很雜亂，一點都不像 5。顏色最深的格子反而在邊緣：我算過，那些位置在不到 5% 的圖裡有墨水，平均權重大小約 3.6；而在 3 成以上的圖裡都有墨水的位置，平均只有約 1.1。所以單看一個權重很難解讀，真正決定答案的是 784 票的加總。以第 1 張為例，加分的像素合計 +16,717，扣分的合計 −14,632，兩邊相減是 +2,085，再加上偏差 +79，得到 +2,164，才讓它被判斷成 5。整個訓練集平均來看，真正的 5 分數約 +3,945，其他數字約 −6,207。

對照組：把 5,421 張 5 的平均圖，減掉其他 54,579 張的平均圖。橘色是 5 比較常有墨水的地方：上面那一橫的右端、左邊那一豎、底下的弧；藍色集中在正中央偏右和下半部中間，那是其他數字常經過、5 卻通常留白的地方。SGD 學到的權重和這張圖有關（在 1 成以上的圖有墨水的像素上，相關係數約 0.34），但不一樣：它不是在記「平均的 5 長什麼樣子」，而是在調整 784 個權重，讓容易搞混的那些圖被分對。

最後 4 張（虛線底線）是故意挑出來的錯誤案例：兩個被當成「不是 5」的 5，和兩個被誤認成 5 的其他數字（一個 9、一個 0）。點它們看兩條長條：加分和扣分互相拉鋸，兩邊都有好幾千到兩萬多分，淨值卻只有幾百到兩千多，只佔兩邊總量的一小部分，就被推到錯的那一邊。這兩種錯誤正是第 2 篇混淆矩陣要數的東西。

Loss function：hinge loss 與推導

投影片 5

權重是怎麼學出來的？這要看第二個問題：loss function。SGDClassifier 預設 loss='hinge'。先把答案改寫成 （是 5）或 （不是 5），再看 這個乘積，它叫間隔（margin）：猜對時 ，猜錯時 ，而且數值越大代表猜得越有把握。

把所有訓練資料的 hinge loss 平均，再加上投影片標的 penalty='l2' 正則化（係數 alpha=0.0001），就是訓練時要最小化的 cost function：

0/1 loss（錯一次扣 1）
hinge（線性 SVM）
log loss ÷ ln 2（邏輯迴歸）

拖動滑桿，注意 0 到 1 之間的那一段：模型已經猜對了（），hinge loss 卻還不是 0。這就是投影片標的 margin violation：光是猜對不夠，還要猜得「夠有把握」，分數要離 0 至少一段距離，才不會被扣分。這段安全距離就是 SVM 的核心想法，第 5 章會細講。

為什麼不直接最小化「猜錯幾次」（0/1 loss）？因為 0/1 loss 是階梯狀的，除了跳的那一點以外斜率都是 0，梯度下降完全不知道該往哪裡走。hinge 和 log loss 都是凸函數，而且錯得越離譜 loss 越大、斜率不為 0，梯度下降有方向可走。hinge 整條都壓在 0/1 loss 上方；log loss 要除以 ln 2 才會（t·s = 0 時自然對數的值是 0.693，比 1 小），所以圖上畫的是除以 ln 2 的版本。log loss 處處平滑；hinge 在 t·s = 1 有一個折角，那一點改用次梯度（subgradient），下面的推導就是這樣處理的（剛好等於 1 時，0 或 都是合法的次梯度；scikit-learn 選擇在 時就更新）。把 loss 改成 'log_loss'，同一個 SGDClassifier 就變成邏輯迴歸，還能輸出機率。

用交叉驗證量準確率

投影片 4

模型訓練好了，接著評估。分類問題最直覺的指標是準確率（accuracy）：猜對的張數除以全部張數。和上一章一樣，用 K-fold 交叉驗證，這次切成 3 份：

from sklearn.model_selection import cross_val_score
cross_val_score(sgd_clf, X_train, y_train_5, cv=3, scoring="accuracy")
# 投影片：        array([0.96355, 0.93795, 0.95615])
# sklearn 1.8 實測：array([0.95035, 0.96035, 0.9604 ])

三份都在 95% 左右。投影片的數字是舊版 scikit-learn 跑出來的；我用 1.8 版在真實資料上重跑，得到的是第二行。SGD 的細節會隨版本調整，所以幾個百分點內的差異是正常的，結論不變。

cv=3 的三輪（分類器會自動用「分層」切法）

當估計器是分類器時，cv=3 會自動改用 StratifiedKFold：每一份都保持和整體一樣的 5 的比例。我數過，三份剛好各有 1,807 張 5（5,421 ÷ 3）。

超過 95% 的圖都猜對，看起來很厲害。在下結論之前，先做一個實驗。

笨分類器也有 91%

投影片 6

投影片寫了一個什麼都不學的分類器：不管看到什麼圖，永遠回答「不是 5」。

from sklearn.base import BaseEstimator

class Never5Classifier(BaseEstimator):
    def fit(self, X, y=None):
        return self                                   # 什麼都不學（投影片寫 pass；sklearn 慣例是 fit 回傳 self）
    def predict(self, X):
        return np.zeros((len(X), 1), dtype=bool)      # 全部回答 False

never_5_clf = Never5Classifier()
cross_val_score(never_5_clf, X_train, y_train_5, cv=3, scoring="accuracy")
# array([0.91125, 0.90855, 0.90915])   ← 投影片和我重跑的結果完全一樣

它的準確率超過 90%。投影片問：為什麼這麼高？答案就在前面那張長條圖：只有 9.035%（約 9%）的圖是 5，所以永遠猜「不是 5」，自然會猜對剩下的 90.965%（約 91%）。這種一類遠多於另一類的資料叫偏斜資料（skewed dataset），也常叫不平衡資料。在這種資料上，準確率幾乎沒有參考價值，投影片的結論就是：Not a good metric for the case.

設正類比例為 。永遠猜負類，猜對的就是所有負類，準確率是 ；永遠猜正類則是 。聰明的笨模型會挑多的那一類：

所以在 MNIST 的 5 偵測器上，準確率的及格線是 90.965%（約 91%），不是 50%。SGD 的 95.7%（三份平均）要跟約 91% 比，而不是跟 50% 比。換成錯誤率看更清楚：笨模型錯 9.0%，SGD 錯 4.3%，只少了大約一半。第 2 篇會看到，它其實漏掉了不少 5：投影片的版本只抓到約 76%，我用新版重跑只有約 65%。

那三個數字為什麼不一樣？如果答案是固定的 ，三份的準確率應該完全相同才對。原因是 Never5Classifier 只繼承了 BaseEstimator，scikit-learn 認不出它是分類器，cv=3 就改用不分層的普通 KFold，三份裡的 5 張數不一樣：

三份加起來 1,775 + 1,829 + 1,817 = 5,421，剛好是全部的 5。改用 scikit-learn 內建的 DummyClassifier（它是真正的分類器），切法變成分層，三份都是 1,807 張 5，結果三個都是 0.90965，我實際跑過確認。

Python 實作

把這一篇的步驟串起來。每一行後面的輸出，都是我用 scikit-learn 1.8 在真實 MNIST 上跑出來的：

import numpy as np
from sklearn.datasets import fetch_openml

mnist = fetch_openml('mnist_784', as_frame=False)
X, y = mnist.data, mnist.target
X.shape                                   # (70000, 784)
y[0]                                      # '5'（字串）

X_train, X_test, y_train, y_test = X[:60000], X[60000:], y[:60000], y[60000:]
y_train_5 = (y_train == '5')
y_test_5  = (y_test == '5')
y_train_5.mean()                          # 0.09035：只有 9% 是 5

from sklearn.linear_model import SGDClassifier
sgd_clf = SGDClassifier(random_state=42)
sgd_clf.fit(X_train, y_train_5)

some_digit = X[0]
sgd_clf.predict([some_digit])             # array([ True])
sgd_clf.decision_function([some_digit])   # array([2164.22...])

# hypothesis 自己算：w·x + b，和 decision_function 一樣
w, b = sgd_clf.coef_[0], sgd_clf.intercept_[0]
w @ some_digit + b                        # 2164.22...

from sklearn.model_selection import cross_val_score
cross_val_score(sgd_clf, X_train, y_train_5, cv=3, scoring="accuracy")
# array([0.95035, 0.96035, 0.9604 ])

# 基準線：永遠猜多數類
from sklearn.dummy import DummyClassifier
dummy_clf = DummyClassifier()
dummy_clf.fit(X_train, y_train_5)
any(dummy_clf.predict(X_train))           # False：一張 5 都不猜
cross_val_score(dummy_clf, X_train, y_train_5, cv=3, scoring="accuracy")
# array([0.90965, 0.90965, 0.90965])

fetch_openml 第一次執行要花一點時間下載，之後會用快取。sgd_clf.fit 在一般筆電上大約要十幾秒，cross_val_score 會訓練 3 次，所以要等久一點。

常見陷阱與自我檢查

標籤是字串，卻寫 y_train == 5fetch_openml 的標籤是 '5'。和整數比較會全部得到 False，而且當下不會報錯。先印出 y[0] 確認型別。
在偏斜資料上只看準確率正類只佔 9%，什麼都不學也有 91%。報告準確率時，一定要附上「永遠猜多數類」的基準線。
把 decision_function 的分數當機率2,164 不是機率（機率最大只到 1），它只是 。正負號決定答案，大小只能拿來比較誰比較有把握。要機率得改用 loss='log_loss'。
自訂估計器沒有被認成分類器交叉驗證會用不分層的切法，每一份的類別比例不同。自己寫分類器時要繼承 ClassifierMixin，而且要寫在 BaseEstimator 左邊：class Never5Classifier(ClassifierMixin, BaseEstimator)。我在 scikit-learn 1.8 試過，順序寫反的話仍然不會被認成分類器。最簡單的做法是直接用 DummyClassifier。
在測試集上調來調去到目前為止，所有評估都只用訓練集的交叉驗證。X_test 要留到最後才用，道理和上一章一樣。
如果 5 和非 5 剛好一樣多，Never5Classifier 的準確率會是多少？

50%。基準線是 ，兩類一樣多時是 0.5。這也是為什麼在平衡資料上，準確率 90% 很有意義；在 9:1 的資料上，90% 等於什麼都沒學。

一張 5 的分數是 0.3，另一張是 2,164。兩張都判斷成 5，對 hinge loss 來說有差嗎？

有差。hinge loss 是 ：分數 2,164 的那張 loss 是 0；分數 0.3 的那張雖然猜對，loss 還有 0.7，這就是 margin violation。訓練時模型會繼續調整權重，把那張的分數往 1 以上推。

權重圖裡顏色最深的格子為什麼都在邊緣？

看推導的更新式：像素 的權重只有在那張圖的 時才會被 改動。常有墨水的像素，會同時收到 5 的「往上加」和非 5 的「往下減」，兩邊大多互相抵銷，所以權重不大。邊緣像素很少有墨水，只會被少數幾張難分的圖改動；把它的權重調很大，幾乎不影響其他圖的分數，卻能把那幾張圖分對，而拉回 0 的 L2 力量（）又很弱。結果就是這些權重很大，卻只服務極少數的圖，有點像在「背」那幾張圖。這也提醒我們：線性模型的單一權重不一定能直接解讀。

為什麼訓練集要先洗牌，SGD 才學得好？

SGD 一次只看一筆資料就更新。如果資料照數字排好，連續幾千步都只看到同一個數字，權重會被一路帶往那個數字，下一段又被帶去另一個方向，最後結果會偏向最後看到的類別。洗牌後，每一小段都混到各種數字，每一步的方向平均起來才接近整體的梯度。補充：scikit-learn 的 SGDClassifier 預設 shuffle=True，每一輪會自己重新洗牌，所以用它時不必擔心這點；自己實作 SGD，或資料是依序串流進來時，才需要自己洗牌。
