先拿到乾淨的預測

投影片 7

要數「哪種猜對、哪種猜錯」，先要有一份預測。直接拿訓練好的模型去 predict 訓練集不行，因為那些圖模型都看過了，就像拿考古題考學生，分數不準。

from sklearn.model_selection import cross_val_predict

y_train_pred = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3)

cross_val_predict 和上一篇的 cross_val_score 一樣做 3-fold 交叉驗證，差別在於它不回傳分數，而是回傳每一張圖的預測。每一張圖都是由「訓練時沒看過它」的那個模型來猜的，投影片的備註稱這種預測是乾淨的（clean）。

混淆矩陣的四個格子

投影片 7–8

混淆矩陣（confusion matrix）的想法很簡單：數一數「A 類被猜成 B 類」發生了幾次。scikit-learn 的慣例是每一列（row）是真正的類別，每一行（column）是模型猜的類別。二元分類只有兩類，所以是 2 × 2 共四個格子。

點任一格，會跳到下一節，看 sklearn 1.8 模型分到那一格的圖（不管上面選哪個模型，圖都來自 sklearn 1.8 的預測；格子是 0 的就不會跳）。

名字怎麼記？投影片第 8 頁在「TN、FN、TP、FP」上畫了兩種箭頭：第二個字母是模型猜的答案（P = 猜是 5，N = 猜不是 5），第一個字母是猜得對不對（T = 對，F = 錯）。所以 FP 就是「猜是 5，但猜錯了」，也就是把不是 5 的圖誤認成 5；FN 是「猜不是 5，但猜錯了」，也就是漏掉了一張真的 5。

讀投影片的矩陣時也用這個規則：第一列 [53057, 1522] 是所有不是 5 的圖（負類），其中 53,057 張被正確判斷為非 5（TN），1,522 張被誤認成 5（FP）。第二列 [1325, 4096] 是所有真的 5：1,325 張被漏掉（FN），4,096 張被抓到（TP）。

切換成「完美預測」，所有數字都集中在左上到右下的對角線上，其他格子都是 0。模型越好，數字就越集中在對角線上。切換成「Never5 笨分類器」，右邊整行都是 0：它從來不猜 5，所以 5,421 張 5 全部落在 FN。準確率沒有說出來的事，混淆矩陣一眼就看得到。

Precision 與 Recall

投影片 8–9

投影片第 8 頁從四個格子數出五個總數：

要數的東西公式投影片的值

2. 猜對的預測TN + TP57,153

第 2 除以第 1 就是準確率（57,153 ÷ 60,000 = 0.95255，和上面對帳的數字一樣）。接下來把焦點放在正類，用第 4 個數分別除以第 3 和第 5 個數：

兩個公式的分子一樣都是 TP，差別在分母。Precision（精確率）的分母是「模型說是 5 的」，問的是：你喊了「這是 5」，有幾成是真的？Recall（召回率）的分母是「真的是 5 的」，問的是：所有的 5 裡面，你找到了幾成？

套回投影片的數字：

也就是說，這個 5 偵測器說「是 5」的時候，只有 72.9% 是對的；而所有的 5 裡面，它只找到 75.6%。準確率 95% 的光環下，它每喊四次「是 5」就有一次喊錯，每四個 5 就漏掉一個。用 sklearn 1.8 重跑的模型則是 Precision 0.837、Recall 0.651：比較少誤認，但漏掉更多。兩者是不同版本 scikit-learn 訓練出來的模型，兩種錯誤的比例不一樣；第 3 篇會說明，同一個模型還能透過門檻在 Precision 和 Recall 之間取捨。

兩種作弊法

投影片 9

投影片提到一個讓 Precision 變成 100% 的「簡單方法」：只猜一張，而且確保它是對的，Precision 就是 1 ÷ 1 = 100%。反過來，把每一張都猜成 5，Recall 就是 100%。我用 sklearn 1.8 的決策分數實際試了一下，從分數最高的圖開始，只把前 n 張猜成 5：

猜成 5 的張數PrecisionRecallF1

分數最高的那一張真的是 5，所以 Precision 是 100%，但 Recall 只有 0.02%，5,421 張 5 只找到 1 張。全部猜 5 則是反過來。單看其中一個指標，都可以被輕易騙過去，所以兩個一定要一起看，或是合成一個數字，這就是 F1。

笨分類器的 Precision 是多少？Never5 從不猜 5，Precision 的分母 FP + TP = 0，變成 0 ÷ 0，數學上沒有定義。scikit-learn 會跳出 UndefinedMetricWarning，然後把它當成 0；Recall 是 0 ÷ 5,421 = 0，F1 也是 0。準確率給它 91 分，這三個指標都給它 0 分。

F1：調和平均與推導

投影片 8–9

F1-score 是 Precision 和 Recall 的調和平均（harmonic mean）：先取倒數、再平均、再取倒數。

投影片第 9 頁的四個例子：

四組的一般平均都是 0.7，F1 卻越來越低。兩個數字差越多，F1 被扯得越低，這就是投影片說的「F1 偏好 Precision 和 Recall 差不多的分類器」。

圖上的曲線是 F1 的等高線，同一條線上的點 F1 都一樣。越往右上角 F1 越高，而且每條曲線都是凸向左下角（原點）的弓形：要讓 F1 變高，兩個指標都得高，只把一邊拉到 1 沒有用。按「全部猜 5」看看，一般平均還有 0.55，看起來像及格邊緣；F1 只有 0.17，一眼就被看穿。上面三條長條中，中間那一條是幾何平均 ，大小一定介在一般平均和調和平均之間。另外，圖上的虛線是 P = R 的位置，每條 F1 等高線都在這條虛線上離原點最近。

Python 實作

接續第 1 篇的程式（已經有 sgd_clf、X_train、y_train_5）。註解裡的輸出是我用 scikit-learn 1.8 在真實 MNIST 上跑出來的；投影片的舊版數字寫在旁邊對照：

from sklearn.model_selection import cross_val_predict
from sklearn.metrics import confusion_matrix

y_train_pred = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3)
cm = confusion_matrix(y_train_5, y_train_pred)
cm
# array([[53892,   687],     投影片：[[53057, 1522],
#        [ 1891,  3530]])            [ 1325, 4096]]

tn, fp, fn, tp = cm.ravel()              # 攤平的順序：先第一列，再第二列
(tn + tp) / cm.sum()                     # 0.95703...（= 三個 cross_val_score 的平均）

# 完美預測：所有數字都在對角線上
y_train_perfect_predictions = y_train_5
confusion_matrix(y_train_5, y_train_perfect_predictions)
# array([[54579,     0],
#        [    0,  5421]])

from sklearn.metrics import precision_score, recall_score, f1_score
precision_score(y_train_5, y_train_pred)  # 0.8370...  投影片 0.7291
tp / (tp + fp)                            # 0.8370...  自己算，一樣
recall_score(y_train_5, y_train_pred)     # 0.6511...  投影片 0.7556
tp / (tp + fn)                            # 0.6511...
f1_score(y_train_5, y_train_pred)         # 0.7325...  投影片 0.7421
tp / (tp + (fn + fp) / 2)                 # 0.7325...  推導 1 的公式

# 笨分類器：分母是 0 的時候，用 zero_division 指定要回傳什麼
import numpy as np
never5_pred = np.zeros(len(y_train_5), dtype=bool)
precision_score(y_train_5, never5_pred, zero_division=0)   # 0.0，不會跳警告
recall_score(y_train_5, never5_pred)                       # 0.0

常見陷阱與自我檢查

把列和行看反scikit-learn 是「列＝真實、行＝預測」，但有些課本和工具的畫法剛好相反。讀別人的混淆矩陣前，先確認哪一邊是真實答案。
用 predict 訓練集來算混淆矩陣模型看過那些圖，數字不能代表它遇到新圖的表現。要用 cross_val_predict，或是留到最後才用測試集。
只報告 Precision 或只報告 Recall只猜 1 張就能讓 Precision 100%，全部猜 5 就能讓 Recall 100%。兩個要一起看，或看 F1。
搞錯哪一類是「正類」Precision 和 Recall 都是針對正類算的。如果把「不是 5」當成正類，投影片的模型 Precision 會變成 53,057 ÷ 54,382 = 0.976，Recall 是 53,057 ÷ 54,579 = 0.972，看起來好很多，但回答的是另一個問題。scikit-learn 用 pos_label 指定正類，預設是 pos_label=1；布林標籤可以直接用，因為 True == 1。如果標籤是字串（例如 '5'），就要自己寫 pos_label='5'。
以為 F1 永遠是最好的指標F1 把兩種錯誤看得一樣重。有些情境寧可多誤報也不能漏掉，有些情境剛好相反，第 3 篇會看投影片舉的兩個例子。
一個模型 TP = 90、FP = 10、FN = 60。Precision、Recall、F1 各是多少？

Precision = 90 ÷ (90 + 10) = 0.90，Recall = 90 ÷ (90 + 60) = 0.60。F1 用推導 1 的公式：90 ÷ (90 + (60 + 10) ÷ 2) = 90 ÷ 125 = 0.72。也可以用調和平均驗算：2 × 0.9 × 0.6 ÷ 1.5 = 0.72。

在同一個模型上，再加 10,000 張正確判斷的「非 5」圖（TN 多了 10,000），哪些指標會變？

只有準確率會變高。Precision、Recall、F1 的公式裡都沒有 TN，所以完全不受影響。這也說明了為什麼負類很多時，這三個指標比準確率可靠。

為什麼 Never5 的 Precision 是「沒有定義」而不是 0？

Precision 的分母是「猜成正類的張數」，Never5 一張都沒猜，分母是 0，0 ÷ 0 沒有定義。scikit-learn 預設跳出警告後回傳 0，也可以用 zero_division 參數改成回傳 1 或 NaN。實務上看到這個警告，通常代表模型根本沒在預測正類。

兩個模型的 F1 都是 0.72，一個是 (P, R) = (0.9, 0.6)，另一個是 (0.72, 0.72)。它們一樣好嗎？

F1 一樣，但犯的錯不同：第一個很少誤報、但漏掉四成；第二個兩種錯誤差不多。哪個比較好要看應用：漏掉的代價高，就選 Recall 高的；誤報的代價高，就選 Precision 高的。第 3 篇會談怎麼依需求調整。
