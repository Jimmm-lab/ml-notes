分數、門檻與取捨

投影片 10

第 1 篇看過，SGDClassifier 對每張圖都會算一個決策分數（decision score），也就是 。它不會直接輸出「是 5」或「不是 5」，而是拿分數和一條門檻（threshold）比：分數比門檻高就判斷成正類，否則判斷成負類。預設的門檻是 0。

三條門檻的結果和投影片完全一樣：門檻 A 時 Precision 6/8 = 75%、Recall 6/6 = 100%；門檻 B 時 4/5 = 80%、4/6 = 67%；門檻 C 時 3/3 = 100%、3/6 = 50%。門檻往右移，判斷成 5 的圖變少，模型只挑最有把握的，Precision 通常會上升，Recall 則一定不會上升。這就是投影片說的：對同一個模型，提高 Precision 會降低 Recall，反之亦然。

注意「通常」兩個字。把門檻從 −1,500 慢慢拉到 0 試試：分數 −1,061 的那張 5 會被移出去，Precision 從 5/6 = 83% 降到 4/5 = 80%。門檻變高，Precision 卻變低了，最後一節會推導為什麼會這樣。

該重視 Precision 還是 Recall

投影片 12

既然兩者要取捨，就要看錯誤的代價。投影片舉了兩個方向相反的例子，我另外補了兩個常見情境：

重視 Precision

兒童安全影片過濾器（投影片）：寧可把很多好影片擋掉（低 Recall），也要確保放行的每一支都安全（高 Precision）。

重視 Recall

監視器偵測扒手（投影片）：Precision 只有 30% 也沒關係，只要 Recall 有 99%。警衛會多跑幾趟誤報，但幾乎所有扒手都會被抓到。

重視 Precision

垃圾郵件過濾：把正常信誤判成垃圾信（FP）的代價很高，重要的信可能就被錯過了。
補充的例子

重視 Recall

疾病的初步篩檢：漏掉一個病人（FN）的代價遠高於多做一次複檢，所以先求不漏，再用後續檢查排除誤報。
補充的例子

判斷的方法很簡單：問自己「FP 和 FN，哪一種錯比較不能接受？」不能接受 FP，就提高門檻、追求 Precision；不能接受 FN，就降低門檻、追求 Recall。

拿到決策分數

投影片 13

投影片寫：scikit-learn 不讓你直接設定門檻，但可以拿到它用來做判斷的決策分數，自己拿分數去比。

y_scores = sgd_clf.decision_function([some_digit])
y_scores                                 # array([2164.22...])

threshold = 0
y_scores > threshold                     # array([ True])，和 predict() 一樣

threshold = 3000
y_scores > threshold                     # array([False])：門檻提高，這張 5 就被漏掉了

分數的意思。投影片把分數標成「到 SVM 超平面的有號距離」。更精確地說： 是一個超平面，一張圖到它的有號距離是

decision_function 回傳的是分子，所以它和距離成正比，正負號代表在哪一邊，絕對值越大代表離邊界越遠。這個模型的 ，所以第一張圖分數 2,164 對應的距離約 14.3。只要拿來比大小和比正負，兩者完全等價；第 5 章講 SVM 時會再細講。

這一點在新版已經不一樣了。scikit-learn 1.5 起新增了 FixedThresholdClassifier，可以把門檻直接包進模型裡；另一個 TunedThresholdClassifierCV 還會用交叉驗證自動找門檻。我在 1.8 上試過，門檻設成 3,000 時，第一張圖就被判斷成不是 5，和上面手動比較的結果一樣：

from sklearn.model_selection import FixedThresholdClassifier
clf_3000 = FixedThresholdClassifier(sgd_clf, threshold=3000,
                                    response_method="decision_function")
clf_3000.fit(X_train, y_train_5)
clf_3000.predict([some_digit])           # array([False])

要挑門檻，需要每張訓練圖的分數。和上一篇一樣用 cross_val_predict，只是改成要分數而不是預測：

y_scores = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3,
                             method="decision_function")

Precision 和 Recall 對門檻的曲線（投影片第 14 頁那張圖）

幾個觀察：

  • 兩個分布有一大片重疊，重疊區裡的圖不管門檻放在哪裡，總有一些會被分錯。門檻只能決定「錯在哪一邊」，要減少重疊得靠更好的模型。
  • Recall 曲線（實線）一路平滑地往下走；Precision 曲線（虛線）在右端門檻很高時變得鋸齒狀，因為那裡只剩幾十張圖，多一張少一張就差很多。這就是投影片的註解：提高門檻時 Precision 有時會下降，雖然整體趨勢是上升。
  • 預設門檻 0 時，sklearn 1.8 是 P = 0.837、R = 0.651；投影片的舊版是 P = 0.729、R = 0.756，所以投影片那張圖上兩條線幾乎在 0 附近交叉；這裡畫的 1.8 版，兩條線交叉在負的門檻。

推導：為什麼 Recall 只降不升，Precision 卻可能忽高忽低？

Recall 的分母不會動

，分母 是真正的 5 的總數，和門檻無關。門檻提高只會讓 TP 不變或減少，所以 Recall 是門檻的非遞增函數。

Precision 的分子和分母一起動

設目前判斷成正類的有 張，其中 張是 TP，Precision 是 。門檻提高到剛好把分數最低的那一張正類預測移出去：

如果移出的是 FP（ 不變；這裡 、）：

如果移出的是 TP（ 也少 1）：

第二式等號只在 （全部都對）時成立，因為 。所以移出一張 FP，Precision 上升；移出一張 TP，Precision 不會上升（只有全部都對時不變，其他時候下降）。整體會上升，是因為分數越低的地方 FP 越多，門檻往上移時被移出的多半是 FP。但在分數很高、張數很少的地方，只要剛好移出一張 TP，曲線就會往下跳。

我在 sklearn 1.8 的 60,000 個分數上逐一檢查相鄰的兩個門檻：Precision 上升了 54,579 次，每一次都是移出一張 FP；下降了 5,416 次，每一次都是移出一張 TP，和推導完全吻合。（另外 5 張 5 沒有造成下降：其中 4 張被移出時 Precision 已經是 100%；分數最高的那張 5 在最高的門檻下仍被判斷成 5，從來沒有被移出。）

找出 90% Precision 的門檻

投影片 14–15

假設需求是「Precision 至少 90%」。precision_recall_curve 會算出每一個可能門檻的 Precision 和 Recall：

from sklearn.metrics import precision_recall_curve
precisions, recalls, thresholds = precision_recall_curve(y_train_5, y_scores)

idx_90 = np.argmax(precisions >= 0.90)    # 第一個（最低的）達到 90% 的門檻
threshold_90_precision = thresholds[idx_90]
threshold_90_precision                     # 3370.0...   投影片約 7816

y_train_pred_90 = (y_scores >= threshold_90_precision)
precision_score(y_train_5, y_train_pred_90)   # 0.9000...   投影片 0.9000
recall_score(y_train_5, y_train_pred_90)      # 0.4799...   投影片 0.4368

np.argmax 用在布林陣列上，會回傳第一個 True 的位置。thresholds 是由低到高排好的，所以這一行找的是「剛好達到 90% 的最低門檻」。為什麼要最低？因為 Recall 是門檻的非遞增函數，在 Precision 達標的門檻裡，最低的那個 Recall 不會比其他的低，犧牲最少。

結果是一個 Precision 90% 的分類器，但 Recall 只有 48%（投影片是 43.7%），一半以上的 5 都漏掉了。課本的提醒很實在：如果有人說「我們要 99% 的 Precision」，你要問：在多少 Recall 下？幾乎任何分類器都能達到很高的 Precision，只要把門檻調得夠高。

投影片標了一句：「Precision 在 Recall 約 80% 附近開始急速下降。」在 sklearn 1.8 的曲線上也一樣：Recall 70% 時 Precision 還有 81%，到 80% 剩 71%，到 90% 只剩 52%。如果要選門檻，最好選在急降之前。

怎麼比較兩個模型：曲線下面積

投影片最後問：要怎麼在「所有門檻」上比較兩個分類器？答案是看曲線下的面積。PR 曲線下的面積叫 AUC-PR，scikit-learn 常用 average_precision_score（AP）來估計它：AP 把每一段 Recall 的增量乘上該點的 Precision 再加總，，是一種階梯式的估計，不做內插，所以和用梯形法算的 auc(recalls, precisions) 會有一點差異（這裡 AP 是 0.81004，梯形法是 0.80998，幾乎一樣）。完美的分類器是 1；這個 5 偵測器是 0.810（sklearn 1.8）。另一個常用的是 ROC 曲線下面積，下一篇的主題。

推導：隨機猜的分類器，PR 曲線在哪裡？

投影片在圖上畫了一條虛線，標著「隨機分類器（值等於正類的比例）」。設有 張正類、 張負類（投影片寫成 P、N），隨機挑出比例 的圖判斷成正類。因為是隨機挑的，平均而言正類和負類被挑中的比例都是 ：

Precision 和 無關，永遠等於正類的比例；Recall 則等於 ，可以從 0 走到 1。所以隨機分類器的 PR 曲線是一條高度 的水平線，面積也是這個值。MNIST 的 5 只佔 9.04%，所以基準線在 0.09；如果兩類一樣多，基準線就在 0.5。注意：投影片把那條虛線畫在 0.5 的高度，那是「兩類一樣多」時的位置，只是示意；對 MNIST 的 5 偵測器，基準線其實在 0.09，也就是曲線最右端的高度（投影片右下角的 P/(P+N) 就是在提醒這件事）。

這也解釋了投影片圖上的兩個註記：曲線最右端（門檻最低，全部猜正類）Recall = 1，Precision = 5421 ÷ 60000 = 0.09，不是 0；最高的真實門檻至少還猜了一張，而分數最高的那張剛好是 5，所以 Recall 是 1/5421，大於 0。程式畫出來的曲線會再往左碰到 Recall = 0、Precision = 1 的點，那是 precision_recall_curve 額外補上的端點，沒有對應任何門檻。

Python 實作

接續前兩篇的程式。註解裡的輸出是 scikit-learn 1.8 在真實 MNIST 上的結果；畫圖的部分省略了格式設定：

import matplotlib.pyplot as plt
from sklearn.model_selection import cross_val_predict
from sklearn.metrics import precision_recall_curve, precision_score, recall_score, average_precision_score

y_scores = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3,
                             method="decision_function")
precisions, recalls, thresholds = precision_recall_curve(y_train_5, y_scores)
len(precisions), len(thresholds)         # (60001, 60000)：precisions 多一個
precisions[-1], recalls[-1]              # (1.0, 0.0)：最後補上的端點，沒有對應門檻

# 投影片第 14 頁的圖：去掉最後一個點，長度才和 thresholds 一樣
plt.plot(thresholds, precisions[:-1], "b--", label="Precision")
plt.plot(thresholds, recalls[:-1], "g-", label="Recall")
plt.xlabel("Threshold"); plt.legend(); plt.grid(True)
plt.show()

# 投影片第 16 頁的圖
plt.plot(recalls, precisions)
plt.xlabel("Recall"); plt.ylabel("Precision"); plt.grid(True)
plt.show()

idx_90 = np.argmax(precisions >= 0.90)
threshold_90_precision = thresholds[idx_90]   # 3370.0...
y_train_pred_90 = (y_scores >= threshold_90_precision)
precision_score(y_train_5, y_train_pred_90)   # 0.9000...
recall_score(y_train_5, y_train_pred_90)      # 0.4799...

average_precision_score(y_train_5, y_scores)  # 0.8100...（PR 曲線下面積的階梯式估計）

常見陷阱與自我檢查

陣列長度對不上precisions 和 recalls 比 thresholds 多一個元素（最後補上的 Precision = 1、Recall = 0）。畫「對門檻的曲線」時要用 precisions[:-1]。
把完整模型的分數和交叉驗證的分數混用第一張圖用完整模型算的分數是 2,164；在 cross_val_predict 裡，它是由沒看過它的那個模型算分數，分數是 1,201。挑門檻要用交叉驗證的分數，因為那才像模型遇到新圖時的樣子。
用測試集挑門檻門檻也是一個要調的參數，和上一章的超參數一樣，要在訓練資料的交叉驗證上決定，最後才用測試集確認一次。
把 >= 和 > 混用precision_recall_curve 的定義是「分數 ≥ 門檻就算正類」，所以依它找出的門檻做預測時也要用 >=。predict() 本身則是分數 > 0 才算正類。要特別小心的是：precision_recall_curve 回傳的門檻就是某一張圖的分數，所以改用 > 一定會少算那一張。那張如果是 5（Precision 90% 的門檻 3,370 就是），Recall 會少一點，Precision 也會跟著變：這裡從 0.90003 降到剛好 0.9（2,601 ÷ 2,890），差一點就跌破 90%。
只報告一個數字「Precision 90%」沒有說 Recall 多少，就沒有意義。報告時兩個一起給，或直接給 PR 曲線。
把門檻從 0 調到 3,370，TP、FP、Recall 各會怎麼變？

TP 從 3,530 降到 2,602，FP 從 687 降到 289。Recall 從 0.651 降到 0.480；Precision 則從 0.837 升到 0.900。門檻提高後，判斷成 5 的張數從 4,217 減少到 2,891，兩種數都變少，但 FP 減少的比例大得多。

同一個模型，有沒有可能 Precision 和 Recall 都比預設門檻時高？

在局部是可能的：如果門檻正下方剛好是幾張 5，把門檻降低一點會多抓到它們，TP 和判斷成 5 的張數同時加 1，（只要還沒全對），Precision 和 Recall 一起上升。上面那排 12 張圖就有這個例子：門檻從 0 降到 −1,500，Precision 從 80% 升到 83%，Recall 從 67% 升到 83%。但這只是在局部撿到便宜；要讓兩者在整條曲線上都變好，得讓兩個分數分布重疊得更少，也就是換一個更好的模型、或做更好的特徵。第 4 篇會看到隨機森林在同一個問題上的表現。

某個資料集的正類只佔 1%，一個模型的 AP 是 0.3。這算好還是壞？

要和基準線比。隨機分類器的 AP 等於正類比例 0.01，所以 0.3 是基準的 30 倍，已經學到不少東西；但離 1 還很遠。同樣的 0.3 放在兩類各半的資料上（基準 0.5），就比亂猜還差。

為什麼找 90% 門檻時要取「最低的」那個？

在所有 Precision ≥ 90% 的門檻裡，Recall 是門檻的非遞增函數，門檻越低 Recall 只會不變或變高。所以最低的那個門檻，是在滿足 Precision 要求的前提下，漏掉最少 5 的選擇。
